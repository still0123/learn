## 1. 当前 idea 是否够创新？

### 1.1 硕士论文层面

**够，但需要收敛主线。**

当前开题里的三个核心方向是：

1. 视觉特征压缩/视听协同锚定；
2. 广告营销知识 RAG；
3. 链式反思/链式校验。

这三个方向单独看都不是全新技术，但放在广告视频问答这个垂直场景里，通过声画异步、OCR/Logo 细节、广告营销知识、证据回溯校验形成闭环，是可以支撑硕士论文的。

不过，要注意：**硕士论文 defend 的重点不应该是“我用了哪些先进模块”，而应该是“我针对广告视频的什么具体难点做了什么改造，并用实验说明有效”。**

### 1.2 专利创造性层面

专利层面风险比较明显。审查员已经在第二次审查意见中指出：

- 权利要求 1-6 不具备创造性；
- 通用视频问答 + 自我验证 + 多尺度 RAG + 跨模态对齐 + 热力图定位，组合后可以得到当前方案；
- 广告视频问答被认为只是通用视频问答的具体应用场景；
- 过采样、Top-K 筛帧、全局/局部双流、RAG、CoT、关键词触发校验、确认/修正令牌都容易被认为是常规手段。

这说明专利文本目前最大问题是：**审查员可以把方案拆成几个已知模块，然后认为组合显而易见。**

所以后续不管是专利抗辩还是论文写作，都应该减少“模块列表式表达”，强化“统一证据流”的技术机制。

## 2. 当前最强和最弱的创新点

### 2.1 最强创新点：视听-文字协同视觉锚定压缩

这是最值得主打的创新点。

当前方案里真正有差异化潜力的是：

- 用户问题引导视觉区域；
- ASR 语音引导视觉区域；
- OCR/text/logo/brand 文字显著性引导视觉区域；
- 时序滑动窗口解决声画异步；
- 响应图生成局部锚框；
- 全局视图 + 局部视图保留上下文和细节。

这个点比“RAG”或“链式反思”更有学术价值。

但现在写法里有两个风险：

1. **容易被认为是 AVAM 的广告视频版本。** 你引用了 AVAM，而你的响应图、锚框、局部裁剪、全局-局部输入都和 AVAM 方向很近。
2. **“Token 压缩”定义不够严格。** 如果你既输入全局图，又输入局部图，而且分辨率都很高，实际视觉 token 可能没有减少，甚至变多。

因此这个创新点应该改写为：

> **面向广告视频声画异步的视听-文字协同视觉证据锚定方法。** 该方法不是简单 Token pruning，而是在过采样关键帧上，利用问题语义、邻域 ASR 语义和 OCR/Logo 显著性共同生成时空响应图，自适应选择局部高分辨率证据区域，并与全局视图共同构成证据保留型双流输入。

### 2.2 中等偏弱创新点：广告营销知识 RAG

RAG 本身不新。把知识库换成广告营销知识库，在论文里可以作为应用创新/系统增强，但不宜作为主要原创贡献。

目前风险是：

- 只是 JSON 知识条目 + Top-K 检索；
- 可能被认为是 prompt engineering；
- 容易引入无关知识，导致“看起来专业但事实不准”；
- 如果知识库来自测试集答案或标签体系，会有数据泄漏风险。

应该改成：

> **证据驱动的广告知识检索。** 检索查询不只来自用户问题，还来自局部视觉证据、ASR 关键词、OCR 文本和视觉标签；知识只有在与视频证据匹配时才注入；答案必须区分“视频事实证据”和“营销理论解释”。

### 2.3 偏弱创新点：CoT + Self-Reflection/链式校验

这个点现在最容易被质疑。

原因：

- CoT 已经非常常见；
- Self-Refine/Reflection 已经很多；
- “观察—分析—推理—答案”更像 Prompt 模板；
- “关键词触发”容易被认为是工程规则；
- “确认令牌/修正令牌”是常规结构化输出；
- 专利审查员已经认为链式校验可以由对比文件 2 的自我验证启示得到。

要增强这个点，建议不要主打“自我反思”，而改成：

> **证据回溯式声明校验。** 先把初始答案拆成视觉声明、OCR 声明、语音声明、营销推理声明，再分别回查关键帧、局部 crop、ASR 时间片段和知识库条目。校验输出应包含声明 ID、证据 ID、错误类型、修正文本，而不是简单让模型“再想一遍”。

## 4. 当前开题里需要调整的地方

### 4.1 不要把“RAG + CoT + Reflection”作为主要创新

建议弱化这些表述：

- “引入 RAG 增强广告知识”；
- “采用链式思维推理”；
- “利用自我反思减少幻觉”；
- “使用确认/修正令牌”。

这些可以保留，但要定位为辅助模块。

### 4.2 主线改为“证据定位—证据解释—证据校验”

推荐主线：

```text
证据定位：视听-文字协同响应图找到关键视觉证据
证据压缩：全局/局部双流保留场景和细节
证据解释：广告知识库解释这些证据对应的营销含义
证据推理：结构化生成把证据组织成答案
证据校验：声明级回溯检查答案是否被证据支持
```

这样 RAG、CoT、Reflection 都被纳入“证据流”，而不是孤立模块。

### 4.3 题目可以更聚焦

当前题目：

> 基于视觉特征压缩与链式反思的广告视频问答方法

这个题目可以用，但“链式反思”太像 Prompt 技巧，“视觉特征压缩”也可能被质疑 token 是否真的压缩。

建议考虑：

1. **基于视听文字证据定位与链式校验的广告视频问答方法**
2. **面向广告视频问答的视听协同证据压缩与知识增强推理方法**
3. **基于视听文字时空响应图的广告视频问答证据推理方法**
4. **面向广告视频理解的证据约束问答推理与校验方法**

如果还想保留原始方向，我建议用：

> **基于视听协同证据压缩与链式校验的广告视频问答方法**

比“视觉特征压缩与链式反思”更稳。
