# 一种基于增量视频证据与声明依赖闭包的视频问答答案更新控制方法、装置、设备及存储介质

## 摘要

本发明公开一种视频问答的答案更新控制方法。基于初始视频证据集合生成初始答案；当初始答案中的问题必填语义槽存在声明支持缺口时，从同一视频的初始覆盖位置之外获取增量视频证据，形成扩展证据集合。在不将初始答案作为待改写文本输入的条件下，基于用户问题和扩展证据集合生成候选答案。将初始答案和候选答案拆解为原子声明并建立声明映射，确定实质变化声明；在同一扩展证据集合及同一核验定义下核验新旧原子声明，为每一实质变化声明绑定来自增量视频证据的时空模态见证；基于有向声明依赖关系构造受影响声明闭包和只读证明上下文。仅当闭包内的迁移条件、见证条件和一致性条件均满足时，原子提交候选状态；否则依据扩展证据集合下的支持状态继续取证、保留、输出证据不足、撤回或拒答。最终答案仅由已提交或保留的声明受限重组，并经无新增声明终检。本发明避免新旧答案使用不同证据口径产生不可比更新，并避免失去支持的旧声明在失败回退时被重新输出。

## 说明书

### 一、技术领域

本发明涉及视频处理、计算机视觉、语音处理和自然语言处理技术领域，尤其涉及一种通过同一视频内的增量证据、声明—视频证据核验和依赖闭包状态控制更新视频问答答案的方法、装置、电子设备和存储介质。

### 二、背景技术

高信息密度视频中的文字、数量、人物、动作、时间或因果关系，可能只出现在少数帧或短时语音片段中。受输入预算限制，首次回答所使用的帧、画面文字或语音文本不能覆盖全部决定性证据。

已有方案可以在答案置信信息较低时更新候选区域、重选视频帧并迭代生成答案；也可以将初始答案输入验证或修正流程，通过验证问题得到更新答案；还可以使用多候选答案的模型内部评分、全局与局部区域表征、跨模态对齐或约束解码。上述手段分别解决补证、修正、候选选择或生成约束中的一部分问题，但并未当然解决：新旧答案是否在同一扩展证据集合下可比较、单项事实变化是否有本轮新增视频证据见证、相关事实是否应一致提交，以及失败后如何防止已失效的旧事实被再次输出。

因此，需要把补证、候选生成、同证据核验、声明变化控制和输出约束组织为同一声明—证据状态的连续控制过程。

### 四、发明要解决的技术问题

本发明至少解决以下相互关联的问题：

1. 初始视频证据未覆盖决定性事实时，如何从同一视频获得可回溯且区别于初始覆盖位置的增量证据；
2. 如何在不以初始答案作为改写输入的条件下生成候选答案，并使新旧答案使用同一扩展证据口径；
3. 如何避免整体评分掩盖单项新增、替换或撤回声明缺少证据支持；
4. 如何对依赖声明进行局部一致更新，同时不将只读证明前提误作回滚对象；
5. 如何在更新失败时避免恢复已在当前证据快照下失效的旧声明；
6. 如何防止最终自然语言重组阶段引入未核验的新事实。

### 五、术语和数据结构

1. **初始视频证据集合 E0**：首次生成 A0 前，在预设输入预算内从原始视频取得的视频帧、区域、画面文字或带时间段语音文本。
2. **增量视频证据 ΔE**：识别出证据缺口后从同一原始视频取得，且其源片段或覆盖位置不属于 E0 已覆盖范围的证据。
3. **扩展证据集合 E+**：E0 与 ΔE 合并形成的不可变证据快照；A0 与 A2 的比较使用相同的 E+ 标识、内容和核验配置。
4. **原子声明**：可由视频证据分别判断为支持、证据不足或冲突的最小事实语义单元。
5. **支持度**：核验器针对原子声明在一个证据快照下输出的数值或等级依据；支持度经预设状态判定规则映射为支持、证据不足或冲突状态，核验异常单独记为异常而不参与状态比较。
6. **实质变化声明**：A0 与 A2 映射后，规范化事实槽的值、状态或存在性发生非等价变化的声明。
7. **见证证据**：位于 ΔE 中、与实质变化声明必要证据槽相匹配的可回溯视频证据单元。
8. **受影响声明闭包**：从实质变化声明沿预定义出边方向取得、需要共同写入或不写入的下游声明集合。
9. **证明上下文**：核验闭包时需要读取的上游声明及证据；其为只读集合，不因被引用而自动回滚。
10. **候选目标状态**：就一个闭包拟写入的新增、替换、撤回或等价压缩后的结构化状态；证据不足状态不构成可提交的事实目标状态。
11. **提交条件**：候选目标状态符合迁移条件、必要槽均有 ΔE 见证、无同一事实槽非等价候选值且证明上下文无冲突状态的合取条件。
12. **问题必填语义槽**：由问题类型确定、最终答案需要由受支持声明填充的实体、属性、数量及单位、时间、地点或因果槽。

### 六、发明内容

#### 6.1 单一发明构思

本发明的单一发明构思为：**增量视频证据条件下的声明事务状态控制**。

证据缺口限定 ΔE 的获取；E0 与 ΔE 形成唯一 E+ 快照；A0 和 A2 在相同 E+ 与核验定义下比较；实质变化绑定 ΔE 见证；见证和有向依赖关系共同决定闭包是否提交；最终文本只能由已提交或保留的状态重组。各环节连续传递同一证据快照、声明和状态，不是并列拼接模块。

#### 6.2 总体流程

```text
视频 V + 问题 Q → E0 → A0 → 声明支持缺口
                              ↓
                   未覆盖位置获取 ΔE
                              ↓
                        E+ = E0 ∪ ΔE
                       ↙                 ↘
             A0 在 E+ 下核验     非改写生成 A2 并在 E+ 下核验
                       ↘                 ↙
                声明映射 → 变化见证 → 闭包/证明上下文
                                      ↓
                          满足提交条件？
                           ↙             ↘
                      原子提交       安全状态转移
                                      ↓
                     受限重组 + 无新增声明终检 → 输出
```

#### 6.3 技术效果

上述状态约束直接带来以下可解释技术效果：

1. 同一 E+ 快照和核验配置使 A0/A2 的状态可比较；
2. ΔE 见证防止整体答案状态掩盖单条变化缺少新增证据；
3. 下游闭包与上游证明上下文分离，使受影响声明一致更新且限制回滚范围；
4. 安全状态转移不复活当前证据快照下已失效的旧声明；
5. 受限重组与终检阻止语言生成阶段重新引入未核验事实。

上述效果不表示已经取得特定准确率、时延或其他实验数值，也不保证任意模型或数据集上的固定增益。

### 八、具体实施方式

#### 实施方式一：初始证据、缺口和同视频增量取证

系统建立带原始位置的多模态视频索引：视频帧记录帧号和时间戳，OCR 记录文本、帧号、时间戳和区域，ASR 记录文本和起止时间。E0 在预设视图或视觉令牌预算内形成。一个可选的初始帧选择分数为：

```text
MMR(f) = λ·Rel(q,f) - (1-λ)·max Sim(f,s), s∈S
```

其中 `Rel` 为问题相关度，`Sim` 为视觉相似度，S 为已选帧集合。该方式只是一种 E0 形成方式。

生成 A0 后，系统拆解原子声明并对每项声明判定支持状态。当问题必填语义槽对应声明为证据不足或冲突时，构造未覆盖证据需求，需求可包括所需模态、候选时间范围、对象区域和槽类型。系统从同一原始视频选择 ΔE，并按 `source_span_id` 或原始时间范围排除 E0 已覆盖片段；ΔE 记录帧、OCR 区域、ASR 时间段等原始位置。

#### 实施方式二：非改写候选和同 E+ 核验

将 E0 与 ΔE 合并为 E+ 并生成 `snapshot_id`。生成 A2 的提示仅接收问题和 E+，不包含 A0 的文本、验证问题、修改指令或待润色内容。A0 与 A2 均在相同的 E+ 内容、证据顺序、输入预算和验证器配置下核验；若 `snapshot_id` 或 `verifier_config_id` 不一致，禁止基于二者的相对支持度或状态执行替换。

在一实施方式中，支持度按预设规则映射为三种支持状态：支持、证据不足和冲突。数值支持度用于得到状态或作为从属门槛，不将 A0 在 E0 下的数值与 A2 在 E+ 下的数值直接比较。

#### 实施方式三：声明映射与双域闭包

每一原子声明包括事件、主体角色、谓词和值。系统先在同一视频内进行事件和主体消歧，再按 `(event_id, subject_role, predicate)` 映射 A0/A2 声明。值不作为主映射键，而用于确定迁移类型。例如，针对同一促销事件 E7、商品 P1 和 `price_of` 谓词，A0 的“199元”与 A2 的“99元”映射为替换，而非两个无关声明。

边 X→Y 表示 Y 的成立依赖 X。从实质变化声明沿出边形成下游状态写入集合；沿入边形成只读证明上下文。只接受属性、数量、时间和因果等预设关系类型，且仅在边两端事件相同、满足时间关系并达到关系抽取置信条件时建立边。共享品牌、实体名称、视频帧或证据标识但事实槽不同，不建立依赖边。一种保守实现限制为一跳且最多三个节点；超限或不能消歧时禁止提交而不截断部分提交。

#### 实施方式四：见证、迁移和提交判定

系统按问题和谓词确定每项变化的必要证据槽。例如价格问题至少包括数量、单位和价格语境；时间问题包括时间槽；原因问题包括原因槽。每个必要槽均应由 ΔE 中至少一个支持见证覆盖。OCR 或标识见证记录区域，ASR 见证记录起止时间，动作或实体见证记录帧号或时间范围。

新增或替换需要候选值的正向支持；撤回需要旧值的直接冲突见证，单纯证据不足只使旧声明进入证据不足状态而不触发静默删除。对闭包中全部目标状态逐一判定迁移、见证与一致性条件；只有全部成立才一次性提交。任一必要目标状态失败时，闭包不写入任何候选目标状态。

#### 实施方式五：安全状态机

| 当前条件 | 闭包动作 | 输出动作 |
|---|---|---|
| 全部迁移成立、必要槽均有 ΔE 见证且无事实槽冲突 | 原子提交候选目标状态 | 使用已提交声明 |
| 任一必要迁移失败 | 闭包不写入 | 进入安全状态分支 |
| 候选失败且旧声明在 E+ 下支持 | 不提交候选 | 保留旧声明 |
| 旧声明证据不足且仍有预算 | 不提交 | 继续取证 |
| 旧声明证据不足且预算耗尽 | 不提交 | 输出证据不足；必填槽不能填充时拒答 |
| 旧声明冲突且无受支持替代 | 撤回旧声明 | 非必填槽局部撤回；必填槽不能填充时拒答 |
| 快照不一致、见证不可追溯或闭包超限 | 禁止提交 | 仅保留仍受支持状态，否则证据不足或拒答 |

回退目标不是固定 A0 全文，而是 E+ 下最后一个仍受支持且与已提交闭包无事实槽冲突的结构化状态。

#### 实施方式六：跨闭包传播与冲突撤回

每个闭包记录状态写入集合 W 和证明引用集合 R。当闭包 B 的 W 与闭包 A 的 R 含同一规范化事实槽，即 `W_B ∩ R_A ≠ ∅`，且 B 对该槽作出非等价状态改变时，A 的核验前提失效。系统在处理 B 后以改变后的事实槽状态重新核验 A；若仍有非等价候选值或证明上下文冲突，则将 A、B 合并为联合闭包，只有整体满足提交条件时才提交。

例如，A 的“该商品价格为99元”依赖 B 的“促销有效时间为12秒至15秒”。若 B 因新增 ΔE 表明促销时间实际为20秒至23秒，B 的时间槽写入改变与 A 的证明引用槽相交，系统必须重新核验 A；若 A 的价格见证不在新时间段内，则不允许 A 保持原提交状态。仅共享品牌名称或视频帧而不共享规范化事实槽时，不触发该重核验。

对冲突撤回，若新增 ΔE 显示“199元”为满减门槛而非最终价格，且没有受支持的最终价格替代值，则旧的“最终价格为199元”进入冲突状态并被撤回；若最终价格为问题必填槽，系统拒答而不以证据不足为由恢复该旧值。

#### 实施方式七：受限重组和终检

系统把已提交候选声明和保留的受支持旧声明纳入允许输出集合 `C_allow`。重组器仅可读取 `C_allow` 的声明文本、槽值和证据标识，不读取已撤回或未决声明。重组输出再次拆解为 `C_out`；若任一输出声明不能以相同规范化事实槽和值映射至 `C_allow`，且不属于单位换算、同义实体名或不改变事实槽的语言压缩，则终检失败。系统删除相应语句后重组；仍失败时输出最近受支持的结构化状态，或在必填槽无法填充时拒答。

#### 实施方式八：处理伪代码

```text
E0 = SelectInitialEvidence(video, question)
A0 = GenerateAnswer(question, E0)
C0 = ParseClaims(A0)
state0 = Verify(C0, E0)

if HasRequiredSlotGap(state0):
    deltaE = AcquireIncrementalEvidence(video, need, exclude=Coverage(E0))
    Eplus = FreezeSnapshot(E0, deltaE)
    A2 = GenerateAnswer(question, Eplus, initial_answer_text=None)
    C0plus, C2 = ParseClaims(A0), ParseClaims(A2)
    old, new = Verify(C0plus, Eplus), Verify(C2, Eplus)
    for closure in BuildAffectedClosures(AlignClaims(C0plus, C2)):
        if CommitConditionsMet(closure, old, new, deltaE):
            AtomicCommit(closure)
        else:
            ApplySafeState(closure, old)

RevalidateClosuresWhoseProofContextChanged()
answer = ConstrainedRender(CommittedOrSupportedClaims())
return FinalNoNewClaimCheck(answer)
```

### 九、完整示例

#### 示例一：由 ΔE 见证的价格替换

问题为“视频中商品显示的优惠价格是多少”。E0 只有远景商品画面，A0 为“199元”，对应价格声明为证据不足。系统从未覆盖的第12.4秒取得 ΔE，其中 OCR 区域为“限时99元”，同时段 ASR 为“现在只要九十九元”。A2 在不接收 A0 文本的条件下生成“99元”。在同一 E+ 下，旧价格声明为冲突，新价格声明为支持；二者映射为同一价格槽的替换，数量、单位和价格语境均有 ΔE 见证，闭包无冲突，故原子提交“99元”。

#### 示例二：附加声明不闭合时局部不写入

问题为“视频介绍了产品的什么特点”。A0 为“该产品防水”，A2 为“该产品防水，售价99元”。E+ 支持“防水”，但“99元”只来自缺少货币单位和价格语境的孤立数字。防水闭包保持支持；价格新增闭包不满足必要槽见证，不写入。价格不是必填槽，最终仅输出“该产品具有防水特点”。

#### 示例三：必填槽失效时撤回并拒答

问题为“视频中商品的最终价格是多少”。A0 为“199元”，A2 为“99元”。ΔE 表明“199元”是满减门槛，“100元”是优惠金额，二者均不能填充最终价格。A0 和 A2 的最终价格声明均为证据不足，价格闭包不提交；取证预算耗尽后输出证据不足或拒答。若进一步证据直接表明 A0 的“最终价格199元”错误但仍无替代最终价格，则撤回旧声明并拒答，不恢复 A0。

### 十、装置实施方式

所述装置可以包括视频证据索引、初始答案生成、证据缺口确定、增量证据获取、独立候选生成、同证据声明核验、声明映射与闭包构造、闭包状态控制和受限重组单元。单元可由同一处理器或通过网络连接的多个处理器执行；存储器保存视频索引、证据快照、原子声明、依赖边和决策记录。

### 十一、其他实施方式

1. 本发明不限定具体答案生成模型、视觉编码模型、OCR 模型、ASR 模型或声明核验模型；
2. E0 与 ΔE 可以包含一种或多种视频证据模态，但实质变化的见证能够回溯到同一原始视频；
3. 闭包可以是一跳或多跳，实施时可通过关系类型、置信条件、时间范围和节点上限保持稀疏；
4. 支持状态可以通过离散分类、概率、能量值或其组合确定，但 A0 和 A2 在相同 E+ 与相同核验定义下比较；
5. 当产品要求必须回答时，可以输出结构化证据不足标识而非自然语言拒答；
6. 最终答案可以是文本、结构化槽值、语音或其他由已提交或保留声明确定的输出形式。
