# 基于预冻结视频证据观测记录的视频问答答案状态更新控制专利 V4.4 设计增强稿

> 状态：创新增强初稿，不覆盖 V4.3，不是可直接递交的正式申请文件  
> 更新时间：2026-08-23  
> 用途：作为代理人讨论、权利要求收缩、实施例补写和最小验证的技术蓝本。

## 一、建议名称

**一种基于预冻结视频证据观测记录的视频问答答案状态更新控制方法、装置、设备及存储介质**

其中，“观测记录”不是一般的证据引用或答案解释，而是从本轮增量视频证据中取得、在候选答案生成前冻结、带有规范化事实值和时空上下文、并用于控制后续答案状态是否允许写入的机器记录。

## 二、一句话核心

系统针对问题所需事实槽，从本轮新增视频证据中抽取带实体、谓词、值、限定条件、时间位置、区域和模态来源的规范化观测；在不使用初始答案或候选答案槽值的情况下，于候选答案生成前冻结观测记录；候选答案中的新增、替换或撤回只有与一条无冲突的已冻结观测记录在事实槽、上下文和值约束上匹配，并在同一扩展证据快照下通过核验时，才获得状态写入许可，否则保持、降级为不确定、继续取证或拒答。

## 三、为什么从 V4.3 继续改

V4.3 的 `CoverageDeltaRecord` 证明“价格槽等证据已经看清”，但仍有一个漏洞：

> 看清了价格区域，不等于候选答案写出的价格值就是该区域实际观测到的值。

例如，新增帧中的价格文字非常清晰，因此价格槽覆盖分数上升；但视频中实际写的是“79 元”，A2 却生成“59 元”。如果覆盖增量只控制“这个槽是否已覆盖”，仍需要后置验证器独自阻止错误写入，覆盖记录与具体状态变化之间的联系还不够强。

V4.4 不再只冻结“覆盖变好了”，而是冻结：

```text
商品 X / 促销价格 / 79 / CNY / 11.2 秒 / OCR 框 O7 / 当前上下文无竞争值
```

后续 A2 若写“59 元”，即使价格区域清楚、支持度模型偶然给出较高分，也因候选事实值与预冻结观测值不匹配而不能写入。

因此，V4.4 的升级不是再加一个模块，而是把 V4.3 的抽象覆盖记录替换成可直接约束状态写入的**类型化观测许可对象**。

## 四、单一控制链

```text
问题 Q
  → 事实槽模式与允许观测类型
  → 从 E0 识别未解决槽
  → 从同一视频取得 ΔE
  → 从 ΔE 抽取并消歧事实观测
  → 在 A2 前冻结观测记录 P
  → A2 不接收 A0 语义内容而独立生成
  → A0/A2 在同一 E+ 下拆分、映射和核验
  → 候选迁移与 P 做槽—上下文—值匹配
  → 获许可的候选状态进入暂存/提交
  → 未获许可时输出 E+ 下的安全状态
```

贯穿该链条的唯一新增控制对象是预冻结观测记录 `P`。它由视频取证阶段产生，直接作为状态更新阶段的机器输入，而不是候选答案生成后的解释标签。

## 五、核心数据结构

### 5.1 事实槽模式 `SlotSchema`

至少包括：

- `slot_schema_id`：模式标识；
- `subject_type`：对象类型，例如商品、人物或动作主体；
- `predicate_type`：价格、数量、品牌、动作、时间、空间位置或因果结果；
- `value_type`：数值、枚举、文本、实体、时间或布尔关系；
- `qualifier_schema`：价格类型、单位、时间阶段、说话人、动作对象等限定字段；
- `cardinality_rule`：同一上下文是否只允许一个值；
- `allowed_modalities`：完整帧、局部区域、OCR、ASR 或其组合；
- `normalization_rule_id`：金额、单位、时间、实体指代和关系归一化规则；
- `exclusivity_rule_id`：用于判断两个事实值能否在同一上下文同时成立的规则。

事实槽模式由问题、任务模式和预定义规则确定，不由 A0 或 A2 的候选值反向生成。

### 5.2 视频证据观测记录 `VideoObservationPermit`

建议至少包含：

```text
observation_id
slot_schema_id
context_key
normalized_fact_tuple
qualifiers
evidence_snapshot_id
incremental_evidence_ids
video_time_range / frame_ids
region_bbox / modality
quality_state
competition_group_id
resolution_state
created_before_candidate
answer_value_blind
record_digest（可选）
```

其中：

- `context_key` 至少由视频标识、已消歧实体或事件、谓词槽、时间上下文和适用限定条件构成；
- `normalized_fact_tuple` 可表示为 `(subject, predicate, value, unit, qualifiers)`；
- `incremental_evidence_ids` 仅列出本轮 ΔE 中直接形成该观测的证据；
- `competition_group_id` 将“同一上下文中按槽基数规则不能同时成立”的观测分入同一竞争组；
- `resolution_state` 至少包括 `RESOLVED`、`AMBIGUOUS`、`INSUFFICIENT` 和 `QUALITY_ONLY`；
- `created_before_candidate=true` 表示记录在生成 A2 前冻结；
- `answer_value_blind=true` 表示记录生成时未以 A0 或 A2 的候选槽值作为抽取、检索或选证目标。

`VideoObservationPermit` 这个名称强调其控制作用，但只有 `RESOLVED` 状态的记录能够发放正向写入许可。其余状态保留作审计和失败分支输入。

### 5.3 声明迁移记录 `MigrationRecord`

至少包括：

- `old_fact_tuple` 与 `new_fact_tuple`；
- `migration_type`：保留、新增、替换、撤回/不确定化或等价压缩；
- `target_slot_schema_id`；
- `target_context_key`；
- `required_observation_id`；
- `witness_evidence_ids`；
- `verified_snapshot_id`；
- `authorization_state` 与失败代码。

等价压缩不得改变规范化事实元组，不需要消耗实质写入许可；其他改变事实状态的迁移必须引用具体 `observation_id`。

## 六、观测记录如何生成

### 6.1 值盲化时序

在生成 A2 前执行以下步骤：

1. 由 Q 和任务规则确定事实槽模式；
2. 根据 E0 的观测状态确定未解决槽；
3. 从同一视频取得 ΔE，并固定 E+ = E0 ∪ ΔE 的快照标识；
4. 对 ΔE 做 OCR、ASR、视觉属性、对象关系或时间关系抽取；
5. 按 `normalization_rule_id` 形成规范化事实元组；
6. 按 `context_key`、槽基数和排他规则建立竞争组；
7. 判断竞争组是唯一可解析、存在竞争值、证据不足还是仅质量提升；
8. 冻结记录后，才允许启动 A2 生成。

上述 1—8 不把 A0/A2 的候选事实值作为检索关键词、相似度目标或证据筛选条件。A0 可以用于后续新旧状态比较，但不能用于预冻结记录的观测值选择。

### 6.2 竞争值消歧

对于同一 `context_key` 和单值槽，先将等价观测合并为值簇：

```text
Cluster_k(v) = {o | same_context(o,k) ∧ normalized_value(o)=v}
```

若仅有一个值簇满足模态质量、时空适用和最低证据条件，且不存在达到竞争条件的非等价值簇，则状态为 `RESOLVED`。若两个以上非等价值簇均达到竞争条件，则状态为 `AMBIGUOUS`，不得发放实质写入许可。

“原价 99 元”和“促销价 79 元”在限定字段不同的情况下不应被视为冲突；只有主体、谓词、价格类型、适用时段等上下文相同且槽基数为一时，两个不同值才进入同一竞争组。

### 6.3 质量提升不等于值许可

若 ΔE 仅使图像更清晰，但仍未可靠解析出规范化事实值，记录状态为 `QUALITY_ONLY`。该状态可以触发再次取证或更强 OCR，但不能授权 A2 写入任何新值。

这条规则使 V4.4 与“证据覆盖更完整即可更新答案”的普通方案区分开来。

## 七、机器授权谓词

对实质迁移 `m` 和预冻结观测记录 `p`，可定义：

```text
Permit(m,p) =
    FrozenBeforeA2(p)
    ∧ AnswerValueBlind(p)
    ∧ SnapshotEqual(p, m, E+)
    ∧ OriginatesFromDeltaE(p)
    ∧ Resolution(p) = RESOLVED
    ∧ SlotEqual(m, p)
    ∧ ContextCompatible(m, p)
    ∧ ValueCompatible(new(m), observation(p))
    ∧ WitnessSubset(m, p)
    ∧ SameEPlusVerification(A0, A2, m)
    ∧ TransitionCondition(m,p)
```

不同迁移的状态条件为：

| 迁移 | 必要条件 |
|---|---|
| 新增 | 新事实元组与 `p` 一致，且新声明在 E+ 下受支持 |
| 替换 | 新事实元组与 `p` 一致；旧事实元组在同一上下文下与 `p` 不相容或受 ΔE 明确冲突；新声明在 E+ 下受支持 |
| 撤回 | `p` 表示与旧事实不相容的确定观测或显式否定关系；只有“未找到支持”时不得静默撤回 |
| 不确定化 | 同一竞争组为 `AMBIGUOUS`，或新旧事实均未达到支持/冲突条件；不写入任何竞争值 |
| 等价压缩 | 规范化事实元组不变，且重组终检未产生新事实 |

若 A2 写出的值不等于观测值，或者使用了另一上下文中的相同槽值，则在 `ValueCompatible` 或 `ContextCompatible` 处直接失败，无须等待答案级总分决定。

## 八、状态提交与回退

### 8.1 基础独权中的最小状态控制

每项实质迁移先进入暂存状态。只有对应 `Permit(m,p)=true` 且 E+ 快照仍有效时，才把目标事实状态写入可输出状态集合；否则丢弃该目标状态，并根据 E+ 下最后一个仍受支持的状态输出保留、不确定、继续取证、撤回或拒答。

### 8.2 强从属中的依赖闭包

对存在实体、属性、数量、时间或已确认因果依赖的声明构造有向图。由实质变化节点沿“变化会影响其成立”的方向取得下游写入闭包；上游前提只进入只读证明上下文。

闭包提交条件为：

```text
Commit(K) = SnapshotValid(K)
            ∧ ∀m∈MaterialMigrations(K), ∃p Permit(m,p)
```

一项迁移未获许可时，整个候选闭包不提交。若闭包 B 的写入集合与闭包 A 的证明引用集合相交，B 提交或回退后必须使 A 失效并重核验。

### 8.3 撤回与拒答边界

- 非核心附加声明的观测许可失败：撤回该声明或标记不确定，其余已提交声明可输出；
- 问题所要求的核心槽没有任何可解析观测：继续取证或输出证据不足；
- 核心问句所依赖的闭包被明确冲突且无受支持替代状态：拒答；
- 不得简单回到已在 E+ 下被冲突的 A0。

## 九、建议的权利要求架构

### 9.1 第一层：较集中的方法独权

权利要求 1 只抓以下关系：

1. 从问题确定事实槽模式；
2. 从同一视频的 ΔE 中抽取规范化事实观测；
3. 在 A2 前、以 A0/A2 候选值盲化方式冻结带事实值、上下文和证据来源的观测记录；
4. A2 不接收 A0 语义内容作为改写输入；
5. A0/A2 在同一 E+ 下复评并形成事实迁移；
6. 只有迁移的新事实元组与已解析观测记录在槽、上下文和值上匹配，并满足对应状态条件时，才写入候选状态；否则输出安全状态。

这样比把闭包、反事实、预算、版本和审计全部塞入独权更不容易被说成模块堆叠。

### 9.2 权利要求 1 骨架候选

一种视频问答答案状态更新控制方法，包括：

1. 获取视频、问题、初始视频证据集合 E0 以及基于 E0 生成的初始答案 A0；
2. 根据所述问题确定至少一个事实槽模式，所述事实槽模式至少包括事实槽标识、值类型、允许证据模态、上下文限定字段以及槽基数规则；
3. 针对未解决的事实槽，从所述视频取得区别于 E0 中已用证据单元的增量视频证据 ΔE，并将 E0 与 ΔE 固定为扩展证据快照 E+；
4. 从 ΔE 中抽取带有视频时间位置、图像区域或语音时间段的事实观测，根据事实槽模式对事实观测的实体、谓词、值、单位及限定字段进行规范化，并根据上下文限定字段和槽基数规则确定事实观测的解析状态，生成关联规范化事实观测、解析状态、增量视频证据标识和 E+ 快照标识的观测记录；
5. 在候选答案 A2 生成前冻结所述观测记录，其中生成所述观测记录时不以 A0 或 A2 的候选事实值作为事实观测的检索、抽取或选择目标；
6. 在所述观测记录冻结后，以所述问题和 E+ 生成不接收 A0 语义内容作为改写输入的 A2，并在相同 E+ 和相同核验配置下分别核验 A0 与 A2；
7. 将 A0 和 A2 映射为规范化事实元组并确定实质事实迁移，将所述实质事实迁移与观测记录进行事实槽、上下文和值约束匹配；
8. 仅在被匹配观测记录的解析状态表示同一上下文中不存在达到竞争条件的非等价事实值、所述实质事实迁移的新事实元组与被匹配观测记录的规范化事实观测相容、迁移见证属于被匹配观测记录关联的 ΔE、且新旧事实元组在 E+ 下满足对应迁移状态条件时，将所述实质事实迁移的目标状态写入可输出状态集合；否则禁止写入所述目标状态，并根据 E+ 下仍受支持的事实状态输出安全状态；
9. 基于所述可输出状态集合生成最终答案。

### 9.3 第二层：闭包原子提交从属

从属权利要求限定：按预定义有向语义依赖确定受影响声明闭包；获许可迁移先暂存；仅在闭包中全部实质迁移均取得观测记录许可且快照有效时原子提交，否则丢弃候选闭包。

如果后续全文检索认为“单条许可”仍容易由证据映射和结构化更新组合得到，可把该闭包特征合并回权利要求 1，形成更窄但更强的独权。

### 9.4 其他从属层

1. `competition_group_id`、单值槽竞争和 `AMBIGUOUS` 禁写；
2. 原价/促销价、说话人、动作对象、时间阶段等限定字段消歧；
3. 仅质量提升不发放值写入许可；
4. 快照版本比较与陈旧暂存失效；
5. 写入集合与证明引用集合相交时的跨闭包重核验；
6. 匹配反事实：用同模态、近时间、同分辨率和同预算的非见证证据替换原见证；
7. 确定性派生事实的上游观测 ID、运算符和快照血缘；
8. 最终重组仅允许使用已提交事实元组，终检出现新元组时重新生成或拒答；
9. 设备、系统和存储介质权利要求。

## 十、参考伪代码

```text
schemas = derive_slot_schemas(Q)                     # 不使用 A0/A2 候选值
unresolved = find_unresolved_slots(E0, schemas)
delta_evidence = acquire_from_same_video(V, unresolved, budget)
E_plus = freeze_evidence_snapshot(E0, delta_evidence)

raw_observations = extract_observations(delta_evidence, schemas)
normalized = normalize_fact_tuples(raw_observations, schemas)
groups = build_competition_groups(normalized, schemas)
permits = resolve_and_freeze_before_A2(
    groups,
    snapshot=E_plus,
    answer_value_blind=True,
)

A2 = generate(Q, E_plus)                             # 输入不含 A0 语义内容
old_facts = verify_and_normalize(A0, E_plus, config)
new_facts = verify_and_normalize(A2, E_plus, config)
migrations = map_fact_migrations(old_facts, new_facts)

for m in migrations:
    p = match_by_slot_context_value(m, permits)
    m.authorized = (
        p is not None
        and p.resolution_state == "RESOLVED"
        and p.created_before_candidate
        and p.answer_value_blind
        and p.snapshot_id == E_plus.id
        and set(m.witness_ids) <= set(p.incremental_evidence_ids)
        and transition_condition(m, p, E_plus)
    )

for closure in optional_dependency_closures(migrations):
    stage(closure)
    if snapshot_valid(E_plus) and all_authorized(closure):
        atomic_commit(closure)
    else:
        discard(closure)
        apply_safe_state(closure, E_plus)

return render_without_new_facts(committed_and_supported_facts())
```

## 十一、五个实施例

### 11.1 观测值一致，允许替换

问题询问商品促销价。E0 未包含价格画面，A0 为“99 元”。系统在 11.2 秒取得 OCR 框 O7：“限时 79 元”。在 A2 生成前形成：

```text
(商品X, 促销价格, 79, CNY, 当前促销阶段)
resolution_state = RESOLVED
evidence = O7
```

A2 独立生成“79 元”。A0/A2 在 E+ 下复评后，A2 的规范化元组与记录一致，A0 的 99 元与同一促销价单值槽不相容，替换获许可。

### 11.2 证据清楚但候选值错误，禁止替换

视频观测记录仍是“促销价 79 元”，但 A2 输出“59 元”。由于 `ValueCompatible=false`，即使价格区域清晰、答案总分较高，也禁止把 59 元写入。

这是 V4.4 相对 V4.3 最直接的技术效果。

### 11.3 原价与促销价同时出现，不误判冲突

同一画面显示“原价 99 元，限时 79 元”。两个事实观测的限定字段不同，分别进入“原价”和“促销价”上下文。问题询问促销价时，只允许 79 元记录匹配；99 元不会因同画面出现而形成竞争值。

### 11.4 同上下文出现两个竞争值，进入不确定状态

连续画面都对应同一商品和同一促销阶段，但高质量 OCR 分别得到 79 元和 59 元，且无法根据时间、对象或价格类型消歧。两者进入同一竞争组，`resolution_state=AMBIGUOUS`。无论 A2 选择哪一个值，本轮都不写入；系统继续取证或输出“当前证据无法确定”。

### 11.5 闭包中派生值未获许可，整体暂存失败

A2 把促销价改为 79 元，同时新增“优惠 20 元”。价格元组由已解析观测记录许可，但优惠值缺少受支持的原价观测或确定性计算血缘。若二者属于同一依赖闭包，则候选闭包不提交，避免只写入一半造成内部状态不一致。

## 十二、为什么不属于模块堆叠

V4.4 没有把 OCR、事实抽取、证据映射、验证器和事务分别作为创新。它只主张一个跨阶段的强制关系：

> **在候选答案存在之前，由新增视频证据产生并冻结的具体事实观测，成为该具体事实状态以后能否写入的必要许可。**

- 抽取阶段输出的是同一观测记录；
- 生成阶段受其冻结时序约束；
- 映射阶段使用其槽、上下文和值；
- 核验阶段使用其证据 ID 和快照；
- 写入阶段直接消费其许可状态。

删除该观测记录，补证与事实写入的因果连接即断裂；删除生成前冻结，记录可能退化为事后挑证据；删除值和上下文匹配，清晰但不相干或不一致的证据仍可能错误授权。因此这些限制共同解决的是同一个计算机状态更新错误，而不是各自解决互不相关的问题。

## 十三、近邻风险和取舍

### 13.1 不作为主创新的已知零件

- 候选答案与支持/反对证据的关联和评分已有较早问答专利；
- 大模型输出的事实—证据映射、证据 ID、来源和版本已有公开；
- 第一文本、逐声明证据、第二文本及输出门控已有公开；
- 结构化增量更新、JSONPath 更新提案和模式约束已有公开；
- 视频 OCR 跨帧跟踪、合并识别结果已有公开；
- 原申请已经公开声画滑窗、三流响应图和局部锚定，因此不能把这些重新包装为本案新核心。

上述机制只可作为观测记录的抽取、质量或审计实现。

### 13.2 本轮定向检索未见的完整关系

本轮未检到单篇直接公开以下完整控制关系：

1. 从本轮新增视频证据抽取带具体值和上下文的观测；
2. 在替代候选答案生成前、以新旧候选值盲化方式冻结；
3. 之后要求候选事实迁移在槽、上下文和值上匹配该记录；
4. 把匹配结果作为答案状态写入许可，并对竞争值执行禁写。

该结论仅是定向检索结果，不等于 CNIPA 或商业数据库的正式查新，也不能保证创造性成立。

### 13.3 最强组合攻击

审查员仍可能组合：

```text
视频问答补证/重选帧
+ 候选答案证据评分
+ 事实—证据映射
+ 模式化结构更新
+ 通用事务提交
```

抗辩不能说“每个模块都没有”，而应说明上述组合通常在候选答案产生后寻找证据、排序或修订候选；V4.4 改变了时序和写入控制：答案值盲化的观测先形成且冻结，后产生的候选只有与该先在事实状态匹配才可改变系统答案状态，竞争观测还会显式阻断写入。

## 十四、现有实现支撑与缺口

### 14.1 已有基础

- `EvidencePackage` 已有证据 ID、帧号、时间戳、时间窗、全局/局部视图、OCR、ASR 和评分字段；
- `ClaimCheckPlan` 已能按价格、文字、数量、语音和视觉声明确定所需证据模态；
- 检索记录能够保留 `supporting_evidence_ids`；
- 现有实验脚本保留 OCR 文本、置信度、帧号、时间戳、归一化框，以及 ASR 起止时间和质量字段。

### 14.2 未实现

- `SlotSchema` 的规范化值、限定字段、槽基数和排他规则；
- `VideoObservationPermit` 及 A2 前冻结；
- 同上下文竞争分组与 `RESOLVED/AMBIGUOUS` 状态机；
- 候选事实元组对许可的槽—上下文—值匹配；
- 闭包暂存、快照校验和跨闭包失效传播；
- V4.4 对应实验。

因此，不能把 V4.4 写成“现有代码已经实现”或用 Full‑7844 旧结果证明效果。

## 十五、建议的最小验证

递交前不必先完成全量数据集，但最好至少冻结 30—100 个包含数值、OCR、说话人、动作对象和时间关系的样例，比较：

```text
A0 基线
强制采用 A2
V4.3：覆盖增量许可
V4.4：预冻结具体观测许可
V4.4 + 闭包提交
```

至少记录：

1. 清晰证据但候选值不匹配的错误写入拦截率；
2. 同上下文竞争值的禁写正确率；
3. 不同限定字段的合法多值误拦截率；
4. 正确替换保留率；
5. 无明确冲突时的错误撤回次数；
6. 闭包部分写入次数；
7. 平均新增帧、OCR 区域、ASR 段和 Token 预算。

最小单元测试至少覆盖 11.1—11.5 五种分支。

## 十六、当前建议

- 将 V4.4 作为目前最窄、最具体的创新增强方案；V4.3 保留为较宽的上位备选。
- 正式权利要求先采用“核心许可独权 + 闭包强从属”的两层写法，避免独权一次堆满所有细节；若正式全文查新认为核心许可过宽，再把竞争禁写或闭包提交并入独权。
- 不再增加声画异步、知识库、JSON 更新、证据链等并列模块；这些要么在旧申请中已有，要么近邻密集。
- 下一步不是继续堆概念，而是对本方案做权利要求级全文检索，并补一套可复现的观测记录字段、状态表和五分支实施例。

**结论：V4.4 的优化重点是把“证据覆盖了某个槽”收紧为“候选答案出现前已经冻结了该槽在具体视频上下文中的观测值，后续状态只能写成与该观测一致的值”。这比单纯加模块更能增强技术因果关系，但仍需正式查新和充分公开支撑。**
