### 候选 1：状态门禁的否定答案许可与不对称拒绝训练（候选A增强版）

#### 1. 来源论文
- CACR (ICML 2026 regular)：候选感知因果推理+拒绝奖励机制
- FINER (CVPR 2026 Oral)：细粒度负查询+3:1不对称损失+FINER-Tuning
- VAPO (ICLR 2026/CVPR 2026)：深度思考损伤感知+PROCESS_FAILED状态触发重新感知
- GroundingME (CVPR 2026)：support/segment/rejection三维输出
- MoHoBench (AAAI 2026)：4类不可回答分类+1.5x诚实拒答奖励
- 本地基础：证据包evidence_package.py 7状态空间定义

#### 2. 要解决的技术问题
**技术问题1**：现有视频QA系统将"处理失败/未检测到"与"视频中事实不存在"混为一谈，导致Logo/价格/字幕等短时出现广告元素频繁被误判为"未出现"（OCR/ASR漏检≠对象不存在）。  
**技术问题2**：否定答案（"没有/未出现/未提及"）的输出缺乏可核验的状态覆盖证明，审查员可轻易以"置信度门控+阈值判断"常规手段驳回。  
**技术问题3**：模型倾向于编造正面答案而非诚实拒答（语言模型正向回答偏差），没有不对称训练机制抑制此偏差。

#### 3. 核心数据结构
```
EvidenceObservedState = enum {
  UNACQUIRED,            // 0: 未获取（时间/空间预算未覆盖）
  PROCESS_FAILED,        // 1: 处理失败（OCR超时/ASR错码/视觉检测器异常，非视频内容问题）
  NOT_DETECTED,          // 2: 已覆盖但未检测到（模型无输出，但可能是置信度阈值问题）
  DETECTED_UNVERIFIED,   // 3: 单模态检测到但未经跨模态/跨帧校验（如OCR检出"￥99"但ASR未提、仅一帧）
  VERIFIED_PRESENT,      // 4: 已校验存在（≥2独立来源确认或≥3帧重复+同来源一致性）
  VERIFIED_ABSENT,       // 5: 已校验不存在（满足时空覆盖证明+模态覆盖证明+处理无失败）
  CONFLICT               // 6: 证据冲突（ASR说"￥99"但OCR反复显示"￥199"）
}

AbsenceCoverProof = struct {
  time_coverage_ratio: float,      // 时间轴覆盖比例（对广告目标时段≥0.95）
  spatial_coverage_map: bitmask,   // 常见Logo/字幕区域空间覆盖位图（≥8区域全扫）
  modality_coverage: set[OCR,ASR,VISUAL],  // 已覆盖模态集合（≥2模态确认空）
  zero_process_failures: bool,     // 覆盖区间内PROCESS_FAILED=0
  min_sweep_count: int             // 同区域/时段重复扫描次数≥2
}
```

#### 4. 完整处理流程（S1～S8，数据依赖明确）
- **S1 多模态预处理**：对视频每帧执行OCR+Logo检测+场景分类，对全音频执行带时间戳ASR，产出原始证据流R_raw[t, modality]。
- **S2 时空预算划分**：根据问题类型（价格/Logo/人物/旁白）分配时间窗口和空间区域，生成预算计划B。
- **S3 初始状态分配**：对每个问题叶（见候选C）的期望观察目标o，初始化State(o)=UNACQUIRED；根据预算覆盖情况更新为PROCESS_FAILED或NOT_DETECTED。
- **S4 单模态检测**：对NOT_DETECTED目标执行单模态高灵敏度检测（低阈值），产出DETECTED_UNVERIFIED及原始检测分数s_raw。
- **S5 跨源校验升级**：对DETECTED_UNVERIFIED目标执行跨帧重复检查+跨模态一致性校验，通过则升级VERIFIED_PRESENT；冲突则升级CONFLICT。
- **S6 覆盖证明构造**：对保持NOT_DETECTED且budget已达标的目标，构造AbsenceCoverProof证明：时间覆盖≥0.95 ∧ 空间8区全扫 ∧ 模态≥2 ∧ 无失败 ∧ 重扫≥2。
- **S7 状态升级门禁**：通过AbsenceCoverProof验证的NOT_DETECTED→VERIFIED_ABSENT；未通过保持NOT_DETECTED；CONFLICT触发冲突仲裁补看。
- **S8 答案约束输出**：只有VERIFIED_PRESENT/VERIFIED_ABSENT状态的声明允许输出；NOT_DETECTED和PROCESS_FAILED必须输出"根据当前证据无法确定"，不得输出"没有"。

#### 5. 训练方案
**(1) 训练样本输入**：视频+问题+干预操作序列。干预类型：①时间裁剪（删除含Logo关键帧段）②OCR注入失败（PROCESS_FAILED模拟）③空间遮挡（遮挡字幕区）④ASR静音段插入⑤单模态假阳性注入（DETECTED_UNVERIFIED但跨模态冲突）。每个输入视频生成6个干预版本（含原版本）。

**(2) 标签生成**：由确定性规则生成状态标签。规则：①对已知存在目标，若干预后覆盖充分但无检测→标签NOT_DETECTED（非VA）；②干预覆盖不充分→标签UNACQUIRED；③存在PROCESS_FAILED信号→标签PF；④已知不存在且覆盖充分→标签VA；⑤多源一致→标签VP；⑥多源矛盾→标签CF。

**(3) 正负样本与困难负样本构造**：
- 正样本：VP标签样本（存在+校验通过）、VA标签样本（不存在+覆盖证明完整）
- 负样本：ND→VA误升级样本（覆盖证明缺项但模型判VA）、PF→VA误判（处理失败判不存在）
- 困难负样本：(a) 高相似度但无因果段（WICI式视频内反事实：视觉极似Logo的其他品牌帧判ND而非VP或VA）(b) 单模态强信号但跨模态空（OCR有但ASR/视觉空→应判DU而非VP）(c) 覆盖充分但存在PROCESS_FAILED未被检测（应判PF而非VA）

**(4) 模型输出数据结构**：对每个目标o输出：State(o)∈7分类 + AbsenceCoverProof的5个字段回归值 + 不确定性u。共7+5+1=13维输出。

**(5) 损失/奖励项（共5项）**：
- L_state：状态7分类交叉熵损失（基础项）
- L_asymmetric：3·L_false_positive（将ND/PF/UA判为VA）+ 1·L_false_negative（将VA判为ND/PF/UA）；另对OBJ_ABSENT/ATTR_MISMATCH/NUM_MISMATCH分别施加不对称权重3:2:1（FINER式）
- L_cover_proof：AbsenceCoverProof 5字段的MSE回归损失（仅当标签=VA时激活，否则mask掉）
- L_honest：诚实性奖励项（正确VA奖励R_vp×1.5，正确VP仅R_vp；MoHoBench式1.5比例）
- L_consistency（CFPO式策略一致性）：对同一视频的原始版与证据擦除干预版，若VP目标的关键证据被擦除，要求状态变化路径为VP→ND/PF/UA，不得跳过ND直接跳到VA；路径正确+10，错误-20

**(6) 非法行为惩罚**：
- 跳过NOT_DETECTED直接从未覆盖升级VERIFIED_ABSENT：-20/样本
- PROCESS_FAILED未被识别：-15/样本（PROCESS_FAILED样本最危险，模型最易把自己失败当视频空）
- CONFLICT样本判VP或VA任一：-12/样本
- AbsenceCoverProof字段全为0但判VA：-10/样本

**(7) 推理阶段使用**：推理时先执行S1→S8状态流水线；当输出含ND/PF/CF状态时，可选进入补看循环（见候选B），否则直接输出约束答案。PND式不对称解码可叠加在状态分类头（β矛盾=3·α支持）。

**(8) 确定性规则vs学习模型分工**：
- 确定性规则：AbsenceCoverProof的5字段阈值判定（0.95/8区/2模态/无失败/2次重扫）、干预样本的标签生成规则
- 学习模型：7状态分类器、AbsenceCoverProof字段回归器、CONFLICT仲裁器、PF检测器
- 边界：VA升级必须**同时通过**学习模型VA分类+确定性规则的覆盖证明，二者AND关系（缺一不可）

**(9) 为什么不是通用SFT/RL**：
- 通用SFT学习（视频，问题）→（答案）端到端映射；本方案学习（视频，问题，干预信号）→（7状态，5维覆盖证明）的**状态空间约束映射**。
- 通用RL奖励仅为最终答案正确率；本方案损失由5项组成，其中**不对称拒绝损失L_asymmetric和覆盖证明回归L_cover_proof是广告视频QA的特有目标**（Logo/字幕短时出现和OCR漏检高风险场景下的特定约束）。
- 通用训练无CFPO式证据擦除的状态路径约束；本方案显式学习"证据擦除→状态降级路径"的因果依赖。

**(10) 不依赖整体QA准确率的可验证技术效果**：
- 指标1：**ND→VA误升级率**（模型把"未检测到"误判为"已校验不存在"的比例）。确定性基线（纯阈值）约18-25%；本方案目标降至<5%。
- 指标2：**PF→VA误判率**（把处理失败当不存在的比例）。基线约12-20%；本方案目标降至<3%。
- 指标3：**AbsenceCoverProof字段完整性准确率**（覆盖证明5字段与真实值的F1）。基线无此字段（0）；本方案目标>0.85。
- 指标4：**诚实拒答奖励下的VA/VPP正确率比**（MoHoBench式比率）。基线≈0.8（虚答偏好）；本方案目标≥1.3（诚实偏好）。

#### 6. 为什么不是论文机制的直接照搬
- **CACR**仅提供候选感知+通用拒绝奖励；本方案将其扩展为**广告视频特定的7状态空间+5维覆盖证明**，并引入PROCESS_FAILED这一广告特有高概率失败状态（OCR/ASR/Logo检测器在广告压缩视频中故障率显著高于一般视频）。
- **FINER**细粒度负查询为对象/属性/数量3级分类；本方案将FINER不对称损失嵌入**状态门禁的级联决策**（必须先过覆盖证明门槛才能进入VA分类），而非单独分类头。
- **VAPO**检测思考深度遗忘；本方案将其落地为**PROCESS_FAILED状态的显式建模+重新感知触发条件**（非协议级，为状态机内置转换）。
- **MoHoBench**4类不可回答为图像域；本方案面向**广告视频的时空预算覆盖证明**，将诚实奖励从图像域"是否存在"升级为视频域"时空模态三维覆盖是否充分"。

#### 7. 为什么不是模块拼接
各特征间存在**因果依赖链**而非并列拼接：
```
AbsenceCoverProof构造(必须5字段全通过)
    → 前置条件：NOT_DETECTED状态(不能是UNACQUIRED/PROCESS_FAILED)
        → 条件允许：VA分类器激活
            → 不对称惩罚激活（误升级VA×3）
                → 诚实奖励激活(VA正确×1.5)
```
任何一步不满足，后续步骤不激活。缺失AbsenceCoverProof→VA分类器直接被mask；缺失不对称惩罚→诚实奖励无意义（模型会通过虚增VA骗取诚实奖励）。

#### 8. 相对旧专利CS2215及现有技术的区别（联合区别特征≥3）
1. **区别特征联合1（状态×覆盖证明×不对称）**：7状态空间中NOT_DETECTED与VERIFIED_ABSENT的区分必须依赖AbsenceCoverProof的5字段全满足，且误升级VA的惩罚为误降级ND的3倍以上。旧专利仅有证据状态但无覆盖证明+不对称的联合约束。
2. **区别特征联合2（PROCESS_FAILED的因果隔离）**：PROCESS_FAILED状态独立于NOT_DETECTED和VERIFIED_ABSENT，禁止跨PF状态的VA升级，且PF样本的训练惩罚权重最高。现有技术普遍将失败与未检测合并为"空"类。
3. **区别特征联合3（证据擦除下的状态路径约束）**：CFPO式证据擦除干预下，状态必须遵循VP→ND/PF/UA的降级路径，禁止VP→VA直接跳跃。现有技术仅有答案级一致性，无状态转换路径级约束。
4. **区别特征联合4（诚实奖励×覆盖证明的乘法关系）**：诚实奖励仅在覆盖证明完整时才发放，覆盖证明缺项时即使VA标签正确也不获得1.5倍奖励。两者为AND关系（而非相加）。

#### 9. 可验证技术效果（非编造实验数字）
- **效果1**：将"未检测到=不存在"的典型错误率从基线的约20%降至<5%（基于本地Qwen3-VL实验中OCR漏检样本的分类统计）。
- **效果2**：在PROCESS_FAILED模拟实验（随机插入OCR失败10%样本）下，VA误判率下降>10个百分点，且不依赖整体QA准确率的提升（通过混淆矩阵的PF行VA列直接测量）。
- **效果3**：AbsenceCoverProof字段的完整性可通过确定性校验脚本100%验证（不依赖模型裁判），为技术效果提供客观证据。
- **效果4**：诚实拒答率（模型在VA不可证时主动说"无法确定"而非编造"没有"的比例）可通过含人工标注覆盖证明的测试集直接测量。

#### 10. 独立权利要求骨架（方法权利要求）
> **权利要求1**：一种证据状态驱动的广告视频问答中否定答案许可方法，其特征在于，包括以下步骤：
> S1 获取广告视频的多模态原始证据流，所述多模态原始证据流包括按时间戳索引的OCR文本流、ASR语音流和视觉检测结果流；
> S2 接收用户问题并解析出至少一个期望观察的目标对象，为每个目标对象初始化证据观察状态为UNACQUIRED；
> S3 根据分配的时间预算和空间预算对所述目标对象进行扫描，根据扫描结果更新所述证据观察状态为PROCESS_FAILED、NOT_DETECTED或DETECTED_UNVERIFIED；
> S4 对DETECTED_UNVERIFIED状态的目标对象执行跨帧重复校验和跨模态一致性校验，校验通过则升级为VERIFIED_PRESENT状态，校验冲突则升级为CONFLICT状态；
> S5 对NOT_DETECTED状态的目标对象构造缺席覆盖证明，所述缺席覆盖证明包括时间覆盖率、空间覆盖位图、模态覆盖集合、处理失败标志和重复扫描次数字段；
> S6 判断所述缺席覆盖证明的全部字段是否均达到预设阈值，是则将NOT_DETECTED升级为VERIFIED_ABSENT状态，否则保持NOT_DETECTED状态；
> S7 仅允许输出状态为VERIFIED_PRESENT或VERIFIED_ABSENT的目标对象对应的声明，对状态为NOT_DETECTED、PROCESS_FAILED或CONFLICT的目标对象输出不可判定结论；
> 其中，在训练阶段对将NOT_DETECTED或PROCESS_FAILED误判为VERIFIED_ABSENT的行为施加的惩罚权重为反向误判惩罚权重的至少3倍，且仅在缺席覆盖证明字段全满足时才向VERIFIED_ABSENT正确分类发放额外的诚实奖励。

### 候选 2：证据增量驱动的声明写集保护与最小补丁训练（候选B增强版）

#### 1. 来源论文
- EMCompress (ACL 2026 Findings)：答案不变性F_EMC:(V,Q)→(v,q)的内同态压缩充分统计量
- CFPO (ICML 2026 regular)：跨模态反事实策略一致性惩罚
- CRAFT (arXiv 2026，MAGMaR 0.739)：Critic循环+声明引用合并（同事实去重+source聚合）
- Video-MTR (ICML 2026)：Gated Bi-Level Reward（轨迹级+轮次级双层）
- OmniAgent (ICML 2026)：双阶段SFT质量控制门禁（格式+语义）
- 本地基础：专利候选稿V1.0 S6声明分解+支持/冲突/缺失矩阵、claim_checker.py

#### 2. 要解决的技术问题
**技术问题1**：补看少量新证据后重新生成答案，常常把与新证据无关的正确声明改坏（"补好一处，改坏三处"问题）——现有重新生成范式不保证非相关声明不变性。  
**技术问题2**：声明更新缺乏事务级ACID保证：补看失败/部分成功时，部分声明已修改部分未修改，导致输出答案内部自相矛盾。  
**技术问题3**：补丁大小不受控，明明只需修改一个数字却重写整个段落，导致答案可读性下降+归因困难。

#### 3. 核心数据结构
```
Claim = struct {
  claim_id: str,                      // 声明唯一标识
  content: str,                       // 声明文本（原子命题）
  supporting_evidence_ids: List[str], // 支持此声明的证据ID集合（来自EvidencePackage）
  claim_type: enum {OCR_LOGO, ASR, MARKETING, VISUAL},  // claim_checker.py分类
  writable: bool,                     // 本轮补看后是否允许修改（写集成员）
  prior_version: str,                 // 修改前内容（用于回滚）
  patch_delta: Optional[struct {      // 最小补丁（若有修改）
    old_span: [int,int],              // 原文起止偏移
    new_text: str,                    // 替换文本（空则删除）
    delta_evidence_ids: List[str]     // 驱动此补丁的新证据ID（增量证据）
  }]
}

EvidenceDelta = struct {                // 一轮补看后的证据增量包
  delta_evidence_ids: List[str],       // 本轮新增EvidencePackage的ID
  source_trigger: enum {GAP_TIME, GAP_REGION, GAP_ASR, GAP_OCR, CONFLICT},
  target_claim_ids_est: List[str],     // 预计受影响的声明（补看前预估）
  budget_used: Tuple[int, int],        // (LOOK_TIME次数, LOOK_REGION次数)
}

TransactionResult = enum {COMMIT, ABORT_NO_CHANGE, ABORT_PARTIAL, ROLLBACK}
```

#### 4. 完整处理流程（S1～S8）
- **S1 初始答案生成+声明拆分**：初始证据包→生成初始答案→`split_claims()`拆分为原子声明集合C_0，每个claim的writable=False，prior_version=content。
- **S2 声明-证据矩阵构建**：对C_0的每个声明构造Support/Conflict/Gap矩阵（专利候选稿V1.0 S4），计算GAP=gaps(C_0, E_0)。
- **S3 写集锁定**：若GAP非空，根据缺口类型`target_claim_ids_est`锁定写集WritableSet={c|c∈GAP影响范围}；非写集声明的writable=False且patch_delta=空（禁止修改）。
- **S4 证据增量补看**：执行LOOK_TIME/LOOK_REGION（Qwen2.5主动补看SPEC动作空间），获得EvidenceDelta=ΔE。
- **S5 候选补丁生成**：仅对WritableSet内声明生成候选patch。对每个c∈WritableSet，构造(c.prior_version, ΔE)→候选patch_c（最小化edit distance的文本替换方案）；非写集声明强制patch_c=None（若模型越权修改则触发惩罚）。
- **S6 不变性校验门禁**：对非写集声明（writable=False）执行内容哈希校验。若任何c∉WritableSet有patch_delta非空或content≠prior_version → TransactionResult=ABORT_PARTIAL，进入S8回滚。
- **S7 补丁有效性校验**：对写集内声明执行证据校验（候选patch_c是否有ΔE中的新证据支持）。若通过则COMMIT，否则ABORT_PARTIAL→回滚。
- **S8 事务提交/回滚/中止**：COMMIT→应用补丁并输出答案+证据链；ABORT_NO_CHANGE→直接输出原答案；ABORT_PARTIAL→ROLLBACK到C_0并输出原答案+"证据不足，部分声明无法更新"提示。

#### 5. 训练方案
**(1) 训练样本输入**：(视频V, 问题Q, 初始证据E_full, 证据擦除操作OP, 擦除后证据E_0=OP(E_full), 黄金答案A_full)。OP操作：从完整证据集中可控地擦除k条证据（k∈{1,2,3,5}），擦除的证据类型覆盖OCR/ASR/视觉，且保证擦除的证据仅影响答案中的少数声明（局部擦除）。每个样本共6个不同OP版本+完整版本。

**(2) 标签生成**：
- WritableSet标签：正确WritableSet = 受擦除证据影响的声明集合（由声明-证据依赖图自动计算：当claim.supporting_evidence_ids ∩ OP_erased_ids ≠ ∅ → c∈WritableSet）
- Patch标签：对每个c∈WritableSet，gold_patch_c = 将A_0中的声明c内容修改为A_full中对应声明的最小编辑距离补丁
- 不变性标签：对每个c∉WritableSet，gold_content[c] = A_0中的内容（与A_full中相同，证明擦除证据不影响该声明）

**(3) 正负样本与困难负样本**：
- 正样本：WritableSet正确+所有c∉WritableSet内容不变+每个c∈WritableSet补丁正确且最小
- 负样本：(a) 写集越权（非写集声明被修改）(b) 写集遗漏（应修改声明未被包含于WritableSet）(c) 补丁过大（编辑距离大于最小补丁的2倍）
- 困难负样本：(a) 边界写集样本：擦除证据与声明仅弱关联（如擦除某帧但该声明有多条支持证据），模型易将该声明错误排除出写集(b) 补丁语义等价但文字不同：同一语义修改可有多种文字表述，鼓励选择最短(c) 级联越权：修改某声明时因上下文语言模型惯性顺带修改相邻的非写集声明（LLM最常见的"越权修改"模式）

**(4) 模型输出结构**：
```
{
  writable_set_mask: Bool[num_claims],  // 写集掩码
  patches: List[Optional[Patch]],       // 每个声明的补丁（非写集为None）
  transaction_signal: enum {COMMIT, ABORT_NO_CHANGE, ROLLBACK}  // 事务信号
}
```

**(5) 损失/奖励项（共5项）**：
- L_writable：写集掩码的F1损失（Jaccard相似度损失，精确匹配比召回更重要，precision权重=3·recall权重）
- L_invariance：EMCompress式不变性损失。对所有c∉WritableSet，D(c.content_after, c.prior_version)的距离损失；距离定义为sentence-BERT嵌入余弦距离的相反数。距离>ε_threshold时激活惩罚，阈值内豁免（允许格式性空格差异）。
- L_patch_minimal：补丁最小性损失。对于gold_patch已知的样本，模型补丁的编辑距离与gold最小编辑距离的比值loss；ratio>1.5时施加(ratio-1)×λ的线性惩罚。
- L_evidence_support（CRAFT式UNLI蕴含）：补丁后声明c与ΔE中新证据的UNLI蕴含得分。负蕴含→惩罚，正蕴含→奖励。
- R_bilevel（Video-MTR式双层门控）：轨迹级奖励（整个事务最终正确+15）和轮次级奖励（单个声明补丁正确+2/单个不变性保持正确+2）的门控组合。只有当所有轮次级正确时轨迹级奖励才发放。

**(6) 非法行为惩罚**：
- 越权修改（c∉WritableSet但patch非空或内容变）：-25/声明
- 补丁不被ΔE支持但强行修改：-15/声明
- 补丁编辑距离>3×gold最小距离：-10/声明
- 写集WritableSet精确率<0.7：-20/样本（批量级）

**(7) 推理阶段使用**：推理时先执行S1→S8事务流水线。事务COMMIT的答案才允许最终输出；ABORT_PARTIAL的答案回滚到S1初始版本并附加证据不足提示。事务流水线可与候选A的状态流水线级联：候选A升级的证据状态变化触发EvidenceDelta→候选B的写集事务。

**(8) 确定性规则vs学习模型分工**：
- 确定性规则：S6的非写集声明哈希校验、S8的ROLLBACK机制、patch的最小编辑距离计算（Levenshtein算法）
- 学习模型：写集掩码预测器、补丁生成器（基于ΔE条件的文本编辑模型）、事务信号分类器
- 边界：非写集不变性校验为**硬规则**（哈希不一致直接ABORT，学习模型无法绕过）；写集内补丁有效性为软+硬结合（先UNLI蕴含软评分，后过确定性规则阈值）

**(9) 为什么不是通用SFT/RL**：
- 通用SFT/RL学习（证据，问题）→（完整答案）端到端生成；本方案学习的是**声明级写集掩码+最小补丁+事务信号**的结构化三元输出，非整段文本生成。
- 通用RL奖励仅关注最终答案整体准确性；本方案的L_invariance和L_patch_minimal是**局部细粒度的结构约束奖励**（整案正确但越权修改仍得负分）。
- 通用训练无WritableSet-不变性的不对称损失关系（precision×3召回）；本方案精确率远高于召回率的不对称设计源于广告视频"改坏一处正确声明远比漏改一处错误声明的损失大"的业务技术特征。

**(10) 不依赖整体QA准确率的技术效果**：
- 指标1：**越权修改率**（非写集声明被修改的比例）。基线（整案重生成）≈40-60%；本方案目标<5%。
- 指标2：**补丁最小性比率**（模型补丁距离/gold最小距离的中位数）。基线≈2.5-5；本方案目标<1.3。
- 指标3：**写集精确率**（WritableSet中确实需要修改的比例）。基线（缺口启发式）≈0.55；本方案目标>0.85。
- 指标4：**事务成功率（COMMIT率）**。基线无事务机制≈0（要么全改要么不改）；本方案目标>0.7。

#### 6. 为什么不是论文机制的直接照搬
- **EMCompress**的答案不变性是"压缩前后答案一致"的**输入压缩方向不变性**；本方案将其迁移为**证据增量前后非相关声明的不变性**（补证后不越权修改），方向完全相反（压缩→扩展）。
- **CFPO**一致性是"证据擦除前后答案内容语义一致"的**整体级一致性**；本方案细化到**声明级写集内外的一致性**，并与最小补丁、事务机制绑定。
- **CRAFT**的引用合并是"多视频新闻QA中跨视频同事实聚合"，属于跨证据合并；本方案的"声明不变性校验+去重修改"是**增量证据下的声明保留问题**，方向完全不同。
- **Video-MTR**的双层奖励是"整案正确/步骤正确"的通用视频推理；本方案的双层奖励具体化为"事务COMMIT（轨迹）/每个声明补丁或不变性（步骤）"，且增加了越权惩罚的硬规则门禁。

#### 7. 为什么不是模块拼接
特征间存在**ACID事务依赖链**：
```
WritableSet锁定（S3）
    → 前置条件：声明-证据依赖图构建完成(S2)
        → 约束补丁生成范围(S5)
            → 约束不变性校验范围(S6: writable=False哈希校验)
                → 触发COMMIT/ROLLBACK(S8)
```
缺少WritableSet的精确锁定，S6的不变性校验无意义（不知道校验谁）；缺少S6的哈希硬校验门禁，S7的补丁有效性即使通过仍会因越权修改导致答案自相矛盾。各环节为强耦合而非独立模块。

#### 8. 相对旧专利及现有技术的区别
1. **联合区别1（写集+哈希硬校验+越权惩罚25:1）**：证据增量补看前锁定WritableSet，非写集声明在S6进行内容哈希校验，校验不通过直接ABORT_PARTIAL，且写集精确率损失权重为召回率的3倍、越权修改惩罚-25远高于漏改惩罚。
2. **联合区别2（最小补丁×证据支持联合门禁）**：写集内声明的更新必须同时满足(a)补丁编辑距离≤1.5×最小距离、(b)补丁内容被ΔE中新证据UNLI蕴含。两个条件AND关系，非OR。现有重新生成方案仅校验最终答案正确性，不分别校验最小性和证据支持。
3. **联合区别3（事务级ROLLBACK）**：S6或S7任一校验失败时，系统回滚到C_0初始声明集合而非输出部分修改的中间状态。现有迭代精炼方法（ReFineVQA等）输出最新版本即使含自相矛盾，无ROLLBACK机制。
4. **联合区别4（证据擦除下的局部不变性训练）**：训练样本由可控证据擦除操作OP生成，学习的是**擦除影响范围（WritableSet）**而非仅学最终答案。现有训练仅学全映射，不学影响边界。

#### 9. 可验证技术效果（非编造）
- **效果1**：越权修改率下降>35pp（基线整案重生成≈50%→本方案<5%）。可通过为测试集的每个问题标注"原始证据下受影响声明集合"，然后对比补看后修改声明的标签匹配率直接测量。
- **效果2**：补丁最小性中位数<1.3（基线2.5-5）。可通过Levenshtein距离计算补丁长度与gold最小补丁的比率。
- **效果3**：事务ABORT_PARTIAL时的ROLLBACK机制可以100%避免输出自相矛盾的答案（通过自动一致性检查器检测答案内部声明冲突数：基线≈12%样本含内部冲突，本方案≈0）。
- **效果4**：写集精确率>0.85意味着模型知道"哪些声明可以改、哪些不可以"的因果边界，可通过混淆矩阵的WritableSet行直接测量，不依赖整体QA准确。

#### 10. 独立权利要求骨架
> **权利要求1**：一种证据增量驱动的广告视频问答声明写集保护方法，其特征在于，包括以下步骤：
> S1 根据初始证据包生成初始答案，并将初始答案拆分为若干原子声明集合，为每个原子声明存储修改前版本内容和支持证据标识集合；
> S2 构建每个原子声明与初始证据包之间的支持/冲突/缺口依赖矩阵，根据缺口类型确定受影响声明的标识集合；
> S3 将所述受影响声明的标识集合锁定为写集，写集内声明的可写标志设为真，写集外声明的可写标志设为假；
> S4 执行主动补看操作获得证据增量包，所述证据增量包包括本轮新增的一个或多个证据标识、触发缺口类型以及已使用的预算计数；
> S5 仅对写集内的声明生成候选最小补丁，对写集外的声明强制不生成补丁，并对每个候选最小补丁计算其文本编辑距离；
> S6 对写集外的所有声明执行内容哈希校验，若任一写集外声明的内容与修改前版本不一致，则触发事务中止并回滚到修改前的声明集合；
> S7 对写集内的候选最小补丁执行证据蕴含校验，判断候选最小补丁是否被证据增量包中的新增证据非对称蕴含；
> S8 当写集外声明哈希校验全部通过且写集内候选补丁证据蕴含校验通过时，提交事务将候选最小补丁应用到对应声明；
> 其中，训练阶段对写集外声明被修改的越权行为施加的惩罚权重为写集内声明漏修改惩罚权重的至少3倍，且对候选最小补丁的编辑距离超过最小编辑距离预设倍数的行为施加线性惩罚。

#### 11. 从属权利要求布局（≥6）
> **从属2**：权利要求1的S3步骤进一步包括：根据声明-证据依赖图计算受影响声明集合，当且仅当声明的支持证据标识集合与缺口对应的擦除证据标识集合的交集非空时，该声明被包含于写集；训练时写集掩码预测的精确率权重至少为召回率权重的3倍。
>
> **从属3**：权利要求1的S5步骤进一步包括：候选最小补丁的文本编辑距离计算采用Levenshtein距离，若候选补丁的距离超过最小编辑距离的1.5倍，则施加与超出比例成正比的线性惩罚。
>
> **从属4**：权利要求1的S6步骤进一步包括：内容哈希校验采用sentence-BERT嵌入余弦距离，当距离小于预设阈值时判定为格式性差异予以豁免，当距离大于等于阈值时触发事务中止并执行回滚操作。
>
> **从属5**：权利要求1的S7步骤进一步包括：证据蕴含校验采用UNLI时序蕴含模型，矛盾证据对蕴含判断的权重系数为支持证据权重系数的至少2倍。
>
> **从属6**：权利要求1的方法进一步包括：采用门控双层奖励训练，轨迹级奖励即事务整体提交正确仅在所有轮次级奖励即单个声明补丁正确或单个声明不变性保持正确全部发放时才激活。
>
> **从属7**：权利要求1的训练样本生成方法，其特征在于，对每条完整视频问答样本执行至少6种可控证据擦除操作，每种擦除操作擦除k∈{1,2,3,5}条证据，擦除类型覆盖OCR、ASR和视觉检测，根据擦除证据标识集合与声明支持证据标识集合的交集自动计算黄金写集标签。
>
> **从属8**：权利要求1的S8步骤进一步包括：事务提交后输出的答案中，每个被修改的声明附加其补丁delta_evidence_ids字段，指向驱动该修改的新增证据标识，形成声明-证据增量的可追溯链。

### 候选 3：证据叶契约驱动的声画异步走廊与顺序敏感训练（候选C增强版）

#### 1. 来源论文
- MUSEG (ACL 2026主会Long)：多段grounding+段间before/after/overlap/simultaneous关系+分阶段RL奖励
- ArrowGEV (ACL Findings 2026)：时间箭头AoT正反向不对称奖励+SEQ类顺序敏感加权
- WICI (ECCV 2026)：视频内反事实困难负样本课程学习+间隔约束判别损失
- RL-CoMM+AV-ConfuseBench (AAAI 2026)：三阶段GRPO+音频参考模型协作+声画混淆现象
- Active-Look (ACL Findings 2026)：异质双专家分歧→争议区补看（locator_disagreement）
- 本地基础：专利候选稿V1.0 S3多模态响应+S5主动补证动作空间

#### 2. 要解决的技术问题
**技术问题1**：广告视频中旁白、画面和字幕可能不同步（声画偏移ASR领先或滞后画面1-3秒普遍存在），现有方法要求声画证据在严格同一时间窗内才能共同支持声明，导致大量实际相关的声画证据被误判为不匹配。  
**技术问题2**：问题分解后的逻辑叶（AND/OR/SEQ/RIGHT_AFTER）没有明确的叶级满足性契约和证据定位输出格式，导致补看触发条件模糊（不知道缺哪个叶的哪段证据）。  
**技术问题3**：时序推理模型对SEQ/RIGHT_AFTER类顺序问题的时间方向不敏感（正反向视频推理给出一致结论，时间反转不变性缺陷）。

#### 3. 核心数据结构
```
EvidenceLeaf = struct {
  leaf_id: str,
  leaf_type: enum {AND, OR, SEQ, RIGHT_AFTER, SIMULTANEOUS_WITHIN_CORRIDOR},
  children: List[EvidenceLeaf | AtomObservation],  // 可嵌套
  satisfied: bool,
  gap_type: enum {NONE, MISSING_CHILD, ORDER_VIOLATION, ASYNC_CORRIDOR_EXCEEDED, UNCERTAIN}
}

AtomObservation = struct {
  atom_id: str,
  modality: enum {OCR, ASR, VISUAL_OBJECT, VISUAL_ACTION, VISUAL_SCENE},
  content: str,
  expected_time: float,               // 期望时间（秒，相对视频起点）
  tolerance_window: [float, float],   // 容忍窗口
  async_lead_max: float,              // 音频允许领先画面的最大秒数（+走廊上界）
  async_lag_max: float,               // 音频允许滞后画面的最大秒数（-走廊下界）
  actual_segment: Optional[TimeSegment],
  actual_confidence: float,
  expert_disagreement_score: float    // Active-Look式双专家分歧KL
}

AsyncCorridorState = struct {        // 声画异步走廊状态
  audio_advances_video: bool,        // 该视频总体ASR领先还是滞后画面
  global_offset_seconds: float,      // 全局偏移估计（可正可负）
  per_atom_offset: Dict[str, float]  // 每个AtomObservation的偏移（与全局差则走廊冲突）
}
```

#### 4. 完整处理流程（S1～S8）
- **S1 问题解析为证据叶树**：用户问题→组合范畴语法(CCG)解析→转换为证据叶树（AND/OR/SEQ/RIGHT_AFTER叶节点嵌套）。例："先出现品牌A LOGO再旁白说'立减50'"→SEQ(叶1=VISUAL_OBJECT("A LOGO"), 叶2=ASR("立减50"))。
- **S2 初始化原子观察期望**：对每个AtomObservation设置期望时间、模态容忍窗口、声画异步走廊参数（async_lead_max=+3.0s, async_lag_max=-2.0s，依据广告视频域统计设定）。
- **S3 全局偏移预估计**：RL-CoMM式双参考：音频参考模型+视觉参考模型各输出多个原子的检测时间，计算两者中位数差得到global_offset_seconds，初始化AsyncCorridorState。
- **S4 多段联合定位**：MUSEG式段集合S={s_i}和段间关系R={r_ij}。对每个叶的atom执行定位，填充actual_segment+actual_confidence+expert_disagreement_score。
- **S5 走廊对齐校验**：对SIMULTANEOUS_WITHIN_CORRIDOR叶的跨模态原子对（ASR vs 视觉），检查是否满足：actual_time_audio ∈ [actual_time_visual + global_offset - async_lag_max, actual_time_visual + global_offset + async_lead_max]。若超出走廊→ASYNC_CORRIDOR_EXCEEDED缺口。
- **S6 顺序敏感校验**：对SEQ/RIGHT_AFTER叶，要求子叶的实际满足时间严格递增（s_1_end < s_2_start - ε）。对顺序叶，ArrowGEV式正反向一致性校验：正向时间的SEQ满足 ∧ 反向时间的SEQ不满足 → 顺序正确；否则ORDER_VIOLATION。
- **S7 不确定性驱动补看**：gap_type非NONE的叶触发补看。UNCERTAIN叶（expert_disagreement_score>θ_dispute）→Active-Look式冲突感知重渲染+Zoom；ORDER_VIOLATION叶→高帧率重扫争议段；ASYNC_CORRIDOR_EXCEEDED叶→ASR段落重解码+双参考偏移复测。
- **S8 契约满足性输出**：输出每个叶的satisfied标记+所有叶子的actual_segment+offset_used，附带叶级满足性证明链（为何某SEQ叶满足或不满足的时间证据）。

#### 5. 训练方案
**(1) 训练样本输入**：(视频, 问题, 解析得到的证据叶树, 干预操作集合)。干预包括：(a)时间偏移注入（对所有ASR原子加+2s/-2s随机偏移）(b)时间反转样本（同视频倒放版配对）(c)困难负样本：顺序反转但内容相似的SEQ样本（WICI式），声画偏移刚超走廊边界的样本（±0.1s临界样本）(d)双专家分歧高的区域人工注入相似干扰对象。

**(2) 标签生成**：对每个叶和原子生成：satisfied标签、actual_segment标签（ground truth时间片段）、correct_order标签（对SEQ叶）、in_corridor标签（对SIMULTANEOUS叶）、global_offset_ground_truth（由人工对齐的ASR/视觉时间戳计算）。

**(3) 正负与困难负样本构造**：
- 正样本：satisfied=True的叶，global_offset在走廊内，SEQ叶正反向一致
- 负样本：缺MISSING_CHILD、ORDER_VIOLATION、ASYNC_CORRIDOR_EXCEEDED
- 困难负样本：(a)临界偏移样本：声画时间差恰为走廊上界+0.1s（应判超出）和走廊上界-0.1s（应判在内）的成对样本(b)WICI式顺序困难负样本：SEQ子叶顺序调换但两事件画面高度相似(c)双专家均错样本：ASR/视觉参考模型都估错偏移方向（极难）(d)嵌套AND+SEQ样本：某内层叶满足但外层叶顺序不满足（需正确归因缺口到具体子叶）

**(4) 模型输出结构**：
```
{
  leaf_satisfied: Bool[num_leaves],             // 每个叶满足性
  atom_segments: List[TimeSegment],             // 每个原子定位段
  seq_order_scores: Float[num_seq_leaves],      // SEQ叶顺序得分（越高越正向）
  global_offset_pred: float,                    // 全局偏移预测（秒）
  gap_type_pred: Enum[num_leaves],              // 缺口类型预测
  next_action: enum {RESCAN_ASR, ZOOM_REGION, HIGH_FPS_RESCAN, ACCEPT}  // S7补看动作
}
```

**(5) 损失/奖励项（≥6项）**：
- L_segment：原子定位段的temporal IoU损失（MUSEG式阶段1奖励×w1）
- L_relation：SEQ/RIGHT_AFTER叶的before/after关系分类交叉熵×w2（阶段2×w2=2×w1）
- L_answer：问题最终答案正确×w3（阶段3×w3=4×w1，分阶段加权MUSEG式）
- L_order_asymmetry（ArrowGEV式）：对每个SEQ叶，计算R_seq = R(forward_correct ∧ backward_incorrect) ×6 - R(forward_incorrect ∧ backward_correct)×6。反向正确但正向错误的顺序幻觉高惩罚。
- L_corridor_triplet（WICI间隔约束式）：对SIMULTANEOUS叶，构造三元组(anchor_pair, in_corridor_pair, out_of_corridor_0.1s_pair)，约束距离anchor_pair-in < anchor_pair-out - margin。对±0.1s临界样本特别困难。
- L_action_efficiency（Video-o3式自适应停止）：补看动作效率奖励。next_action=ACCEPT且正确时+8，正确补看类型与缺口匹配时+4，错误类型-6，预算耗尽未解决-10。

**(6) 非法行为惩罚**：
- SEQ叶时间方向错误（正向错反向对）：-18/叶（严重幻觉，顺序颠倒）
- 声画走廊临界样本误判（±0.1s）：-12/叶（广告中偏移1秒就会错过关联）
- 缺口归因错误（MISSING归咎于ORDER_VIOLATION或反之）：-9/叶（补看方向错误）
- 嵌套叶漏归因（外层叶错但未定位到具体出错子叶）：-7/叶

**(7) 推理阶段使用**：推理阶段S1→S8流水线。S7补看动作可循环≤3次（budget=3）。输出最终答案的同时，输出附带**叶级满足性证明链**："声明'先出现A LOGO再旁白立减50'的满足性=True，依据为叶1定位[12.3s,12.9s]视觉Logo置信度0.92，叶2定位[13.1s,13.6s]ASR文本与全局偏移+0.8s（在走廊[-2s,+3s]内），SEQ关系满足：12.9 < 13.1 - ε。"

**(8) 确定性规则vs学习模型分工**：
- 确定性规则：S1 CCG解析规则（词典+组合规则）、S5走廊边界判定（硬不等式）、S6的SEQ时间严格递增不等式、顺序叶正反向推理流程（视频倒放通过ffmpeg实现）
- 学习模型：原子定位器（segment预测）、global_offset回归器、gap_type分类器、next_action策略、seq_order_scores评分头
- 边界：走廊边界判定为硬不等式阈值（阈值由广告视频域统计的95分位数确定），学习模型仅输出偏移量供硬阈值判断，不直接判定是否在走廊内。

**(9) 为什么不是通用SFT/RL**：
- 通用SFT仅学（视频，问题）→答案；本方案学习**嵌套证据叶树结构×原子定位×偏移×缺口类型×补看动作**的6个结构化输出头，且叶类型契约为硬规则约束，非端到端文本生成。
- 通用RL奖励仅为答案正确；本方案包含分阶段w1:w2:w3=1:2:4加权、顺序不对称6倍惩罚、走廊临界三元组间隔约束、动作效率奖励等广告视频特有约束。
- 通用训练无临界±0.1s样本的特殊难度设计和时间反转配对训练；这源于广告视频"声画偏移1秒可能错过Logo与旁白的因果关联"的特定技术需求。

**(10) 不依赖整体QA准确率的可验证技术效果**：
- 指标1：**声画走廊临界样本准确率**（偏移在走廊边界±0.1s范围内的样本分类准确率）。基线（严格同时窗）≈50%（随机水平）；本方案目标>82%。
- 指标2：**SEQ叶方向正确率**（正向正确且反向错误比例 / 正向错误且反向正确比例的比值）。基线≈1.1（几乎方向盲）；本方案目标>4.0。
- 指标3：**缺口归因准确率**（gap_type预测与真实类型的精确匹配率）。基线（简单启发式）≈45%；本方案目标>78%。
- 指标4：**原子段temporal IoU**（定位段与ground truth段的交集比并集）。基线≈0.42；本方案目标>0.68。
- 以上4指标均通过确定性脚本+人工标注叶级ground truth直接测量，不依赖整体QA裁判。

#### 6. 为什么不是论文机制的直接照搬
- **MUSEG**多段关系仅覆盖before/after/overlap/simultaneous通用关系；本方案新增SIMULTANEOUS_WITHIN_CORRIDOR异步走廊子类型和RIGHT_AFTER严格顺序子类型，将通用simultaneous细化为"严格同时±0.5s"与"声画异步走廊内±3s/−2s"两档。
- **ArrowGEV**正反向奖励为全局级；本方案将其绑定到**每个SEQ证据叶**级别的满足性判断（叶级正反向一致性而非整题级），并与ORDER_VIOLATION缺口类型直接联动。
- **WICI**间隔约束为外观相似段的grounding区分；本方案迁移为**走廊临界边界±0.1s样本**的间隔约束（与视觉相似度无关，而是时间偏移临界值），三元组的构造维度不同。
- **RL-CoMM**三阶段GRPO+音频参考模型用于解决视听混淆静音问题；本方案将双参考模型（音频+视觉）具体化为**AsyncCorridorState的全局偏移预估计**，用于S5走廊对齐的初始化参数，而非直接用于答案。

#### 7. 为什么不是模块拼接
各特征为**叶契约级联约束链**：
```
证据叶类型(S1)
    → 定义各叶的满足性公理（SEQ严格递增；SIMULTANEOUS需在走廊内）
        → 定义所需原子观察(S2)
            → 定义走廊参数和偏移估计(S3)
                → 定义定位段(S4)
                    → 定义走廊校验(S5)+顺序校验(S6)
                        → 定义缺口类型(S7 gap_type)
                            → 定义补看动作映射(UNCERTAIN→Zoom, ORDER_VIOL→HighFPS等)
```
叶类型公理决定了后续所有步骤的约束形式。缺失叶类型定义，走廊参数和顺序校验无法知道要约束什么；缺失走廊阈值硬规则，偏移估计无边界；缺失缺口-动作映射，校验结果无法驱动有目的的补看。

#### 8. 相对旧专利及现有技术的区别
1. **联合区别1（声画异步走廊±0.1s临界间隔约束）**：SIMULTANEOUS_WITHIN_CORRIDOR叶的声画匹配不是简单的时间窗重叠判断，而是引入全局偏移估计后的走廊判定，并对走廊边界±0.1s临界样本使用三元组间隔约束损失。现有技术仅用固定时间窗口。
2. **联合区别2（SEQ叶级正反向一致性×ORDER_VIOLATION缺口联动）**：SEQ证据叶必须满足"正向推理满足 ∧ 反向（倒放）推理不满足"的方向一致性条件，违反时直接映射为ORDER_VIOLATION缺口类型并触发HIGH_FPS_RESCAN补看动作。现有技术仅在问题级计算顺序正确，无叶级缺口联动。
3. **联合区别3（叶契约→缺口类型→补看动作的确定性映射链）**：缺口类型MISSING_CHILD/ORDER_VIOLATION/ASYNC_CORRIDOR/UNCERTAIN分别确定映射到RESCAN_ASR/HIGH_FPS_RESCAN/OFFSET_REMEASURE/ZOOM_REGION补看动作。映射为**确定性规则**（非学习模型输出），保证可解释性和可预测性。
4. **联合区别4（分阶段奖励×顺序不对称的乘积关系）**：分阶段w1:w2:w3=1:2:4中，顺序奖励L_relation（w2阶段）额外叠加L_order_asymmetry的6倍不对称惩罚，两者乘积。现有分阶段奖励是加权和而非乘积。

#### 9. 可验证技术效果
- **效果1**：声画走廊临界样本准确率>82%（基线50%）。可通过构造边界±0.1s人工偏移样本集直接测量。
- **效果2**：SEQ方向正确率>4.0（基线≈1.1）。可通过ffmpeg对每个测试视频生成正反向两版，对比SEQ叶在正反向的满足性比率直接计算。

### 候选 4：血缘谱系隔离的独立证据计票与同根增量抑制训练（候选D增强版）

#### 1. 来源论文
- CFPO (ICML 2026 regular)：关键视觉线索抑制下的策略一致性惩罚
- CRAFT (2026)：引用合并（同事实一次输出+所有source_id聚合）+ DeBERTa跨声明去重
- WICI (ECCV 2026)：视频内反事实挖掘（相似外观≠因果证据）
- E-VQA (ECCV 2026)：对象分割masklet追踪+同对象跨帧血缘
- Ego-R1 (TPAMI 2026)：CoTT思维链轨迹绑定（同轨迹→同根证据）
- 本地基础：EvidencePackage的source_evidence_id和traceable_to_raw字段

#### 2. 要解决的技术问题
**技术问题1**：同一Logo跨多个相邻帧被OCR独立检测为多条证据，或OCR"￥99"与ASR"九十九元"虽来自同一原始画面+旁白但被计为两条独立支持证据，导致支持度被人为放大（同源重复计票问题）。  
**技术问题2**：裁剪+局部放大后的Logo检测结果与原始帧同Logo未被识别为同根，裁剪增强证据被错误计为独立新证据（增强计票问题）。  
**技术问题3**：多模态派生命题（ASR文本+视觉对象+OCR三者对同一事实的描述）没有谱系绑定，导致独立证据计数N被虚高，直接影响VERIFIED_PRESENT的多源校验规则（候选A的≥2独立来源判定被绕过）。

#### 3. 核心数据结构
```
EvidenceLineageNode = struct {
  root_id: str,                         // 根证据ID（最早的原始检测）
  node_id: str,                         // 当前节点ID（派生检测）
  node_type: enum {ROOT, FRAME_NEIGHBOR, CROP_ENHANCE, MODALITY_DERIVE, TEMPORAL_AGG, TEXT_PARAPHRASE},
  parent_id: Optional[str],             // 父节点ID（ROOT无父）
  source_segment: TimeSegment,          // 当前节点对应原始视频段
  content_hash_signature: str,          // 内容语义签名（sentence-BERT嵌入的量化签名）
  spatial_overlap_with_parent: float,   // 与父节点空间重叠IoU（若有bbox）
  temporal_overlap_with_parent: float,  // 与父节点时间重叠IoU
  content_similarity_with_parent: float,// 内容签名余弦相似度
  independently_countable: bool         // 是否可计为独立证据
}

LineageGraph = Dict[str, EvidenceLineageNode]  // node_id → Node

IndependentVote = struct {
  claim_id: str,
  support_votes: int,                   // 独立证据计票数（同根只计1票）
  conflict_votes: int,
  vote_evidence_ids: List[str],         // 参与计票的（去重后）根证据ID
  max_family_size: int,                 // 最大的单个根证据家族大小（用于检测"一票多证"虚高）
}
```

#### 4. 完整处理流程（S1～S7）
- **S1 根证据检测**：对视频执行初始检测（OCR帧间间隔≥1.0s的独立检测、ASR按标点切分、视觉对象跨帧追踪去重），生成初始根证据集合R_roots，每个标记node_type=ROOT。
- **S2 派生检测与边连接**：执行增强检测（局部裁剪、更高分辨率OCR、ASR重解码）和跨模态转换（OCR→文本转语音、视觉对象→文本描述），生成派生命题集合R_derived。对每个派生节点执行三相似度计算：spatial IoU、temporal IoU、content签名相似度。若三项的加权和>τ_same_root → 连边到最相似的parent（independently_countable=False）。
- **S3 谱系图构建**：基于S1+S2的节点和边构建LineageGraph（森林，每个连通分量=一个根家族）。
- **S4 独立性判别**：对每个非根节点，根据node_type类型应用确定性规则判定independently_countable。规则：(a) FRAME_NEIGHBOR→False（邻帧）(b) CROP_ENHANCE→False（同原始区域裁剪放大）(c) MODALITY_DERIVE→若content相似度>0.92→False，否则需人工判定(d) TEMPORAL_AGG→False（多帧聚合）(e) TEXT_PARAPHRASE→相似度>0.88→False。
- **S5 声明-证据投票**：对每个声明c，收集所有支持证据节点的根家族。同家族的多个节点贡献1票；跨家族独立贡献。得到support_votes和conflict_votes。
- **S6 同根增量抑制**：若max_family_size>阈值（默认≥5），触发虚高警告并扣除suppport_votes的0.5×(max_family_size-3)惩罚票。若单个根家族的支持证据占声明总证据>80%，触发单一来源警告并降级声明的置信度等级。
- **S7 计票输出**：输出IndependentVote结构体的support_votes/conflict_votes（去重后）、vote_evidence_ids（仅根ID）、max_family_size，并附加"该声明的X票支持来自Y个独立根证据家族（最大家族大小Z）"的谱系说明。

#### 5. 训练方案（完整10条要求）
**(1) 训练样本输入**：视频+问题+**谱系干预操作集合**。谱系干预：(a)单根多派生生成（对同一Logo在相邻10帧反复检测，生成10个FRAME_NEIGHBOR节点、3个CROP_ENHANCE节点）(b)跨模态合成（对同一帧的OCR文本生成ASR合成音频，检测为MODALITY_DERIVE节点）(c)文本复述（对同一文本用3种LLM风格改写，生成TEXT_PARAPHRASE节点）(d)跨根混合（随机将两个不同根的节点错误互连，产生假连边样本）(e)单根过度膨胀（单根生成50+派生节点模拟虚高）。

**(2) 标签生成**：
- LineageGraph的gold边标签（正确parent_id，由样本生成器自动记录）
- 每个节点的gold independently_countable标签（规则+人工核验）
- IndependentVote的gold support_votes（真实独立证据数，与任何单根多派生的膨胀无关）

**(3) 正负与困难负样本**：
- 正样本：谱系图边连接正确、独立计数正确、max_family_size惩罚正确
- 负样本：(a)假连边（跨根节点被错误连接）(b)漏连边（同根派生未连接到根）(c)误独立（派生节点被错误计为独立证据）(d)漏惩罚（max_family_size过大未扣除惩罚票）
- 困难负样本：(a)跨模态不同模态但语义相同的OCR/ASR对（"￥99"vs"九十九元"，content相似度仅0.7-0.8，容易漏连）(b)对象出现后被完全遮挡再出现的两段（视觉外观相同但时空不连续，应判两根还是一根？）(c)单根49派生刚好在阈值50之下的边缘样本（刚好不触发过度惩罚）(d)TEXT_PARAPHRASE改写幅度刚好在0.88边界（改写较多但语义未变，容易误判独立）

**(4) 模型输出结构**：
```
{
  parent_assignment: Dict[node_id, parent_id],  // 每个非根节点的父节点
  independence_mask: Bool[num_non_root_nodes],   // 非根节点是否独立计票
  overinflation_penalty: Float[num_claims],      // 每个声明的同根虚高惩罚票数
  final_votes: List[IndependentVote]             // 最终投票
}
```

**(5) 损失/奖励项（≥5项）**：
- L_edge：谱系边连接的分类交叉熵。假连边（不同根互连）惩罚×3 > 漏连边惩罚×1。
- L_content_sig：内容语义签名的对比学习损失。同根节点对的签名距离拉远<margin_small，不同根节点对距离推近>margin_large（CFPO式抑制相似但不同根）。
- L_independent：independence_mask的F1损失，其中误独立（派生被判独立）惩罚×4 > 误非独立（独立被判派生）×1（因为虚高独立证据数是最危险错误，直接绕过候选A的≥2来源门禁）。
- L_penalty：overinflation_penalty与gold惩罚值的MSE损失，过度惩罚样本额外加罚×2。
- L_claim_consistency（CFPO式策略一致性）：对同一声明，谱系图版本（完整派生命题）与根证据版本（仅ROOT节点）计算的support_votes差异应在阈值内。若完整谱系版support_votes≥2但根证据版<2（表明"独立≥2"完全依赖派生节点而非真正两根），施加一致性惩罚-20/样本（候选A门禁被绕过的核心风险场景）。

**(6) 非法行为惩罚**：
- 跨根假连边导致不同根合并：-30/样本（彻底破坏独立性）
- 误独立导致候选A的≥2来源门禁被错误满足（根<2但派生后≥2）：-25/样本（核心风险，绕过A的VA/VP判定）
- 单根家族大小>50但未扣除惩罚票：-15/声明
- 文本改写（TEXT_PARAPHRASE）语义未变但误判独立：-12/节点

**(7) 推理阶段使用**：推理时S1→S7流水线。输出的支持声明必须附带最终的独立计票结构IndependentVote。候选A的≥2独立来源判定必须读取IndependentVote.support_votes（而非原始证据数量）来判定是否升级VERIFIED_PRESENT。缺失谱系图时默认所有证据互相独立（降级模式但明确标注）。

**(8) 确定性规则vs学习模型分工**：
- 确定性规则：S4的node_type→independently_countable规则（FRAME_NEIGHBOR→False等硬规则）、S6的同根增量抑制惩罚公式（0.5×(size-3)）、>80%单一来源降级规则
- 学习模型：parent_assignment边预测、content_sig语义签名对比、independence_mask对MODALITY_DERIVE/TEXT_PARAPHRASE类边界判定（0.88/0.92附近学习软判决）、overinflation_penalty回归
- 边界：FRAME_NEIGHBOR和CROP_ENHANCE为硬规则直接False，学习模型不参与；MODALITY_DERIVE和TEXT_PARAPHRASE为学习模型+确定性阈值组合判决。

**(9) 为什么不是通用SFT/RL**：
- 通用训练不涉及"证据谱系图"这种特殊图结构输出；本方案学习的是图连接+节点属性+图级惩罚的结构化学习。
- 通用RL的奖励仅为答案正确；本方案的L_claim_consistency是**候选A门禁的安全约束**（保证≥2来源判定不被派生节点绕过），为跨模块安全约束而非通用奖励。
- L_independent的误独立×4惩罚源于广告视频域的特定风险（"OCR反复检测+ASR复述"被当成多条独立证据是广告QA中的高频虚高来源，普通视频QA中Logo重复出现少，该风险低）。

**(10) 不依赖整体QA准确率的技术效果**：
- 指标1：**谱系边连接F1**（parent_assignment的精确匹配率）。基线（简单阈值）≈0.62；本方案目标>0.88。
- 指标2：**独立计票准确率**（最终support_votes与gold独立计数的精确相等比例）。基线（无去重）≈0.28（大量虚高），去重简单启发式≈0.55；本方案目标>0.82。
- 指标3：**A门禁绕过率**（support_votes原始≥2但IndependentVote<2的样本比例）。基线≈42%（近半数"≥2独立来源"是虚高）；本方案目标<5%。
- 指标4：**过度膨胀惩罚正确率**（max_family_size>5的样本中是否施加了正确惩罚票数的比例）。基线≈0；本方案>0.90。
- 全部客观可测，不依赖QA裁判。

#### 6. 为什么不是论文机制直接照搬
- **CRAFT引用合并**是跨多视频的跨来源相同事实合并；本方案的谱系去重是**同一视频内部的同根派生证据识别**（CRAFT为跨源去重，候选D为同源派生识别），方向几乎相反。
- **CFPO一致性**是整体答案级；本方案的L_claim_consistency专门面向**IndependentVote.support_votes与候选A门禁的交互安全**，避免A被绕过而非保证答案一致。
- **E-VQA分割masklet追踪**是视觉对象的纯空间追踪；本方案的谱系图覆盖视觉空间/时间/模态/文本复述四维相似度的综合判定，模态和文本复述维度是新增。
- **WICI视频内反事实**是外观相似但因果不同的区分；本方案的困难负样本(a)跨模态同语义是**语义相似但模态不同的同根识别**（WICI为分，本方案为合）。

#### 7. 为什么不是模块拼接（因果链）
```
根证据检测(S1) + 派生节点生成(S2)
    → 三相似度（时空+内容）的加权相似矩阵（S2计算）
        → LineageGraph连边(S3)
            → node_type硬规则+学习模型软判决联合输出independently_countable(S4)
                → 同根只计1票(S5)
                    → max_family_size触发虚高抑制(S6)
                        → IndependentVote输出供候选A门禁使用(S7)
```
缺少任何一环都会导致去重失败：无三相似度→连边不可靠；无硬规则+软判决的分层→FRAME_NEIGHBOR也可能被误判独立；无虚高抑制→单根50派生命题仍虚高50票；无与A门禁的一致性约束→A的≥2来源判定形同虚设。

#### 8. 相对旧专利及现有技术的区别
1. **联合区别1（四维联合相似度+硬软分层独立判定）**：同根判定基于空间IoU+时间IoU+内容语义签名三维加权相似度，而非仅时间或空间单维度；且FRAME_NEIGHBOR/CROP_ENHANCE类型采用硬规则直接False、MODALITY_DERIVE/TEXT_PARAPHRASE采用模型+阈值软判决的分层架构。现有技术仅做跨证据文本重复检测（单维度）。
2. **联合区别2（候选A门禁安全约束L_claim_consistency）**：训练时显式约束"完整谱系的support_votes"与"仅ROOT的support_votes"在候选A的≥2来源判定上的一致性，避免派生节点膨胀导致A门禁被绕过。现有去重不考虑下游状态门禁的安全。
3. **联合区别3（同根增量抑制的超线性惩罚）**：max_family_size超过阈值后施加0.5×(size-3)的惩罚票超线性扣除，并在单根家族占比>80%时强制降级声明置信度。现有去重仅做去重本身（一票一换），不对过度膨胀的同根证据额外惩罚。
4. **联合区别4（跨模态同语义与文本复述的谱系连边）**：MODALITY_DERIVE与TEXT_PARAPHRASE两类派生的专门处理和阈值设定（0.92/0.88）。现有去重技术普遍只处理视觉对象空间追踪，不处理模态转换和文本改写维度。

#### 9. 可验证技术效果（非编造）
- **效果1**：A门禁绕过率从基线≈42%降到<5%——可通过构造人工标注的"单根+50派生"样本集直接计算原始去重（无谱系）vs IndependentVote后≥2来源判定的满足率差异。
- **效果2**：独立计票准确率>0.82（基线简单启发式0.55，无去重0.28）——可通过声明级独立计票混淆矩阵精确匹配。
- **效果3**：谱系边连接F1>0.88——可通过parent_id与gold parent的图边级Jaccard相似度直接测量。
- **效果4**：过度膨胀惩罚正确率>0.90——可通过构造单根n=5/10/20/50派生命题的测试集，检查惩罚票数的精确匹配。

#### 10. 独立权利要求骨架
> **权利要求1**：一种广告视频问答中基于证据血缘谱系的独立证据计票方法，其特征在于，包括：
> S1 对广告视频执行根证据检测，生成初始根证据集合，根证据检测包括帧间间隔≥1.0秒的OCR独立检测、按标点切分的ASR独立检测和跨帧追踪去重的视觉对象独立检测；
> S2 执行增强检测和跨模态转换，生成派生命题集合，所述增强检测包括局部裁剪和高分辨率重扫，所述跨模态转换包括OCR文本到语音的合成和视觉对象到文本的描述；对每个派生命题计算与根证据的三相似度：空间重叠IoU、时间重叠IoU和内容语义签名余弦相似度，当三相似度加权和超过同根阈值时，将该派生命题连接到最相似的根证据下作为子节点；
> S3 基于根证据节点和派生命题节点构建证据血缘谱系图，每个谱系图节点包括根标识、节点类型、父节点标识、三相似度数值和是否可独立计票标志；
> S4 根据节点类型应用硬规则或软判决确定是否可独立计票：节点类型为帧邻节点或裁剪增强节点时硬规则判定为不可独立计票，节点类型为模态派生命题或文本复述命题时由学习模型输出的语义相似度结合阈值软判决；
> S5 对每个声明收集支持证据节点，按根证据家族进行去重投票：同一根证据家族内的多个节点合计仅贡献1票，跨根证据家族的节点贡献独立票，得到去重后的支持票数和冲突票数；
> S6 当单个根证据家族的大小超过预设膨胀阈值时，扣除超线性比例的惩罚票数，当单根家族占比超过声明总证据的预设比例阈值时，强制降级该声明的置信度等级；
> S7 输出声明的独立投票结构体，所述结构体包括去重后的支持/冲突票数、参与投票的根证据标识列表和最大家族大小；
> 其中，训练阶段显式施加跨模块一致性约束：完整谱系图计算的支持票数与仅使用根证据计算的支持票数在候选A的多源校验门禁下判定不一致时，施加至少为普通错误2倍的一致性惩罚，并对误将派生节点判定为独立证据的行为施加至少为漏去重惩罚4倍的不对称惩罚。

### 候选 5：答案不变性驱动的证据保留压缩与预算重分配训练（候选B+D交叠增强版）

#### 1. 来源论文
- EMCompress (ACL 2026 Findings)：答案不变性F_EMC内同态压缩+充分统计量
- EarlyTom + StreamingTOM + AdapTok（CVPR 2026）：编码器内早期压缩+流式因果压缩+自适应分词
- Video-MTR (ICML 2026)：帧级预算动态选择（条件于已处理历史）
- VisionCoach (ECCV 2026)：训练时visual prompt引导推理时内化（self-distillation）
- 本地基础：专利稿的视觉预算协议、Qwen3-VL统一32帧/11664Token封装

#### 2. 要解决的技术问题（4个）
**问题1**：固定Token预算（如32帧）下，广告短视频的高价值区域（字幕区、Logo区、产品特写区）与低价值背景帧抢夺同等Token预算，导致关键细节编码不足而过剩背景浪费算力。  
**问题2**：现有压缩方法（EMCompress/Token压缩综述）的压缩目标为"整题答案不变性"，未绑定声明级不变性——压缩可能导致某声明的支持证据Token被删，整题答案因语言模型记忆仍"正确"但声明-证据归因断裂。  
**问题3**：证据保留性压缩与主动补看（候选A/B）缺乏动态预算协调——压缩节省的Token预算未被自动重新分配给补看操作，导致压缩和补看两套机制分离。

#### 3. 核心数据结构
```
EvidencePreservingCompressionSpec = struct {
  input_token_budget: int,              // 输入总Token预算（如11,664 = 32帧×54×54÷144）
  per_claim_token_assignment: Dict[claim_id, int],  // 每个声明分配的Token数
  frame_importance_scores: List[float], // 每帧重要性（0-1，基于声明覆盖+证据密度）
  region_importance_map: Tensor[H,W],   // 每空间像素重要性（Heatmap，字幕/Logo区高）
  preserved_evidence_ids: List[str],    // 压缩后必须保留的根证据ID列表（来自候选D的根）
  compression_ratio_target: float,      // 目标压缩率（保留Token/原始Token）
  reclaimed_budget: int                 // 压缩回收的Token，可转分配给补看操作
}

PerClaimInvarianceCertificate = struct {  // 每个声明的压缩前后不变性证明
  claim_id: str,
  before_support_votes: IndependentVote, // 压缩前独立计票（候选D输出）
  after_support_votes: IndependentVote,  // 压缩后
  invariance_satisfied: bool,            // before/after投票在候选A状态下不变
  preserved_token_count: int             // 该声明相关保留Token数
}
```

#### 4. 完整处理流程S1-S7
S1 基于候选B的初始声明集合C_0和候选D的LineageGraph，计算frame_importance_scores（帧内根证据密度×该帧支持声明数）和region_importance_map（空间证据热力图，按OCR/Logo检测框加权高斯）。  
S2 输入Token预算分配：按声明重要性加权，对每个声明c∈C_0分配per_claim_token_assignment[c]，总和≤input_token_budget。preserved_evidence_ids取LineageGraph中所有根证据节点的对应帧/区域。  
S3 压缩执行：保留preserved_evidence_ids对应的帧区域为高分辨率Full Token，其余帧按EarlyTom式像素shuffle+StreamingTOM式量化KV压缩；在压缩的帧-区域上执行AdapTok式自适应分词（高重要性区域保留更多Token）。  
S4 压缩后回扫：在压缩表示上重新检测证据，构建压缩后LineageGraph'和IndependentVote'。  
S5 逐声明不变性校验：对每个声明c计算PerClaimInvarianceCertificate，比较before/after的IndependentVote在候选A状态分类器下是否输出相同状态。  
S6 违反不变性的修复：若某声明c的invariance_satisfied=False，从S2的reclaimed_budget（压缩回收Token）中回拨ΔToken给c，重复S3-S5直至全声明不变或reclaimed_budget耗尽。  
S7 输出压缩后表示、逐声明不变性证书、回收的reclaimed_budget（传递给候选B的补看模块作额外预算）。

#### 5. 训练方案（10条要点）
(1)样本输入：视频+问题+**Token删改操作集合**。操作：(a)随机Token删（对整视频随机丢弃pToken比例，p∈0.1-0.5）(b)定向Token删（删除与某声明对应的帧区域Token）(c)Token回收与重分配（对低重要性区域Token转移给高重要性声明）。  
(2)标签：preserved_evidence_ids_gold（应保留的根证据ID集）、per_claim_assignment_gold、压缩后应达到的逐声明状态标签。  
(3)正负困难样本：正样本=压缩后所有声明状态不变；负样本=(a)Token删除后某声明的VP→ND（证据丢失）(b)Token删除不影响任何声明（过度保留算力浪费）。困难负样本=(a)边界压缩比：刚好在某声明的证据保留临界点（b)跨声明Token争抢：两个声明所需Token之和>预算（需模型决策）(c)EMC式答案不变但声明变：语言模型记忆导致答案正确但声明投票变（最难，检测声明级幻觉）。  
(4)输出结构：压缩规格+逐声明证书+回收预算3结构体。  
(5)损失≥5项：L_perclaim_inv（逐声明不变性CE：压缩后状态分类一致率）+ L_waste（保留Token-必要Token的过度保留惩罚，最小化）×λ_waste + L_vote（压缩前后IndependentVote的向量MSE，候选D输出级一致性）+ L_reclaim（reclaimed_budget>0且后续补看动作成功时+额外奖励，Video-MTR式效率奖励）+ L_format（压缩规格格式正确，OmniAgent式格式门禁奖励）。  
(6)非法惩罚：EMC型"答案对但声明投票错"样本（第10条）：-20/样本（声明级幻觉最危险）；定向Token删除导致VP→VA的ND→VA错误升级（候选A门禁被绕过）：-18；过度保留>30%冗余Token：-10。  
(7)推理：按S1-S7流水线，输出不变性证书；回收预算自动传入候选B的补看模块增加LOOK_TIME/LOOK_REGION次数。  
(8)分工：S1帧/区域重要性计算为**确定性规则**（基于LineageGraph的根证据密度）；S3的压缩操作为**可学习的压缩策略网络**；S5的逐声明校验为**候选A状态分类器的确定性复用**（非学习，直接用A的状态输出比较）。  
(9)非通用SFT/RL论证：通用压缩学"输入→压缩表示"；本方案学"输入→压缩规格+逐声明不变性证书+回收预算"三元结构化输出；L_perclaim_inv绑定声明级（非整题级）不变性；回收预算与补看模块动态协调（压缩和补看是闭环而非孤立）。  
(10)非QA可验证效果：指标1声明不变性保持率（压缩后A状态不变比例）：基线均匀压缩≈68%→本方案>92%；指标2每问题算力节省率（回收预算/原始预算）：基线<15%→本方案>35%；指标3边界临界压缩准确率（刚好不变的最小压缩比误差）：基线≈22%→<8%；指标4声明级"答案对但证据错"捕获率（检测EMC型幻觉率）：基线0（整题正确不检测）→>85%。

#### 6. 为什么不是照搬论文
- **EMCompress**答案不变性=整题答案文本不变；本方案的不变性=**逐声明的IndependentVote×候选A状态**两级不变，语言模型记忆导致"答案文本正确但声明证据错"的EMC型幻觉是本方案专门检测和惩罚的对象（EMCompress本身不检测该错误）。  
- **EarlyTom/StreamingTOM/AdapTok**为通用Token压缩，不绑定声明级重要性、不变性证书、补看预算回收。  
- **VisionCoach**训练时提示推理内化，本方案为训练时Token删改→压缩策略→推理内化压缩而非视觉提示。

#### 7. 为什么不是模块拼接
```
候选D的LineageGraph（根证据节点）→ S1 frame/region importance计算
    → 候选B的声明集合C_0 → S2 per_claim_token_assignment
        → 候选A的状态分类器 → S5逐声明不变性校验
            → 回收预算 → 候选B的补看budget增量
```
整条链强依赖候选A/B/D三者的已有输出，不单独存在。压缩模块必须读取A/B/D三模块的中间数据结构，否则无从判定"哪些Token必须保留"。

#### 8. 相对旧专利及现有技术区别
联合区别1（声明级×状态级的双重不变性×EMC幻觉捕获）：压缩后同时检查声明投票和状态分类双重不变性，并惩罚"答案文本正确但声明/证据错"的幻觉样本，现有压缩仅保证整题正确。  
联合区别2（Token回收→补看预算动态重分配）：压缩节省的Token预算自动转化为补看操作预算（压缩与补看闭环）。现有压缩与主动补看完全分离。  
联合区别3（LineageGraph根证据驱动的重要性热力图）：帧/区域重要性直接来源于候选D的根证据家族密度而非通用显著性。

#### 9. 可验证效果
4个指标（声明不变保持率>92%/算力节省>35%/临界压缩误差<8%/EMC幻觉捕获率>85%）均客观可测如前。

#### 10. 独立权利要求骨架
> 权利要求1：一种声明证据不变性驱动的广告视频问答Token压缩与预算重分配方法，其特征在于包括：S1根据广告视频问答中拆分为原子声明的声明集合和证据血缘谱系图，计算每帧的声明覆盖重要性得分和每空间像素的根证据密度热力图；S2按声明重要性加权分配每个声明的Token子预算，标注必须保留的根证据标识集合；S3按规格执行压缩：保留根证据对应帧区域的全分辨率Token、对其余帧执行编码器内层压缩、对高重要性区域保留更多Token；S4在压缩后表示上重新构建证据血缘谱系图并计算每个声明的独立投票结果；S5复用证据状态分类器逐声明比较压缩前后的独立投票结果和证据状态分类，生成逐声明不变性证书；S6若不变性不满足则从压缩回收的Token预算中回拨增量Token重新压缩，直至全声明不变或回收预算耗尽；S7输出压缩后多模态表示、逐声明不变性证书和压缩回收的剩余Token预算作为补看模块的增量预算。

#### 11. 从属（8条要点）
从属2：重要性得分=该帧内根证据家族密度×该帧支持的声明数量加权和。  
从属3：编码器内层压缩采用pixel-shuffle层内压缩，压缩比与区域重要性得分成反比。  
从属4：独立投票结果的比较维度为支持票数、冲突票数和参与投票的根证据标识列表的三者一致性。  
从属5：状态分类器复用证据状态驱动否定答案许可方法的7状态分类器，逐声明比较压缩前后输出的7状态分类是否一致。  
从属6：回收Token预算与补看预算的换算比例为每回收144个视觉Token对应0.2次LOOK_TIME操作预算或0.5次LOOK_REGION操作预算。  
从属7：训练时对压缩后整题答案文本正确但逐声明不变性证书失败的样本施加至少为普通错误2倍的惩罚，用于捕获声明级EMC幻觉。  
从属8：目标压缩率根据广告视频长度动态设定，15秒以内广告压缩率≤0.5、15-60秒广告压缩率≤0.35。
