# V4 最终方案冻结说明

更新时间：2026年8月23日  
用途：作为 V4 专利初稿、代理人沟通、后续附图和实施验证的统一规格。  
状态：方案文字规格已冻结；不等于代码、实验、正式查新或法律定稿已经完成。

## 1. 一句话讲清楚

> 只有被本轮新增视频证据逐项证明、并在同一扩展证据下通过核验的答案变化，才按相互依赖的一小组声明一起更新；更新失败时，只保留当前证据下仍然可信的内容，不能机械恢复已经失效的旧答案，最终文本也不能再编出未经核验的新事实。

## 2. 发明名称

推荐名称：

> 一种基于增量视频证据与声明依赖闭包的视频问答答案更新控制方法

## 3. 单一发明构思

V4 的核心不是“补证模块＋验证模块＋图算法＋门控模块”的并列组合，而是：

> **增量视频证据条件下的声明事务状态控制。**

所有步骤都处理同一个技术状态：某条答案声明在特定视频证据下是否受支持、是否允许改变，以及改变后哪些关联声明必须共同提交或回退。

## 4. 最终主流程

```text
视频 V + 问题 Q
→ 选择初始视频证据 E0
→ 生成初始答案 A0
→ 把 A0 拆成原子声明，判断支持 / 不足 / 冲突
→ 若问题必填槽存在证据缺口，从同一视频取得 E0 未覆盖的 ΔE
→ 形成唯一扩展证据快照 E+ = E0 ∪ ΔE
→ 只输入 Q 和 E+ 独立生成 A2，不把 A0 作为待改写文本
→ 把 A0、A2 都放到同一个 E+、同一核验器和同一配置下复核
→ 按“事件 + 主体角色 + 谓词”映射新旧声明，找出实质变化
→ 为每项变化绑定 ΔE 中的帧、区域或 ASR 时间段见证
→ 沿有向依赖边建立小型下游事务闭包，上游前提只作为证明上下文
→ 闭包内全部必要迁移通过：整闭包一次提交
→ 任一必要迁移失败：整闭包候选状态不写入
→ 依据 E+ 下的当前状态继续取证、保留、不确定、撤回或拒答
→ 仅用已提交或保留的受支持声明重组答案
→ 终检最终文本没有新增事实
```

## 5. 五个必须写死的技术规则

### 5.1 A2 必须是独立候选

A2 的生成输入包含问题和 E+，但不把 A0 作为“请验证、修改或润色”的文本输入。这样候选生成和候选采纳是两个独立步骤。

### 5.2 A0 与 A2 必须同 E+ 复核

最终更新时不能比较 `A0|E0` 与 `A2|E+`。必须比较：

```text
state(A0 | E+) 与 state(A2 | E+)
```

二者还必须具有相同的 `snapshot_id` 和验证器配置标识。

### 5.3 每项变化必须由 ΔE 逐槽见证

不是“找到一张新帧就算有证据”。变化声明的全部必要槽都要被 ΔE 覆盖。例如价格声明至少要识别数量、单位和价格语境；孤立的“99”不能自动证明“价格为99元”。

### 5.4 闭包必须全成或全败

同一闭包中任一必要迁移失败，候选闭包的实质变化状态全部不写入。不得从 A2 挑一半、从 A0 挑一半，拼成同一事实槽互相矛盾的答案。

### 5.5 回退目标不是固定 A0

候选失败后的固定顺序为：

1. 还有预算且能形成新的取证动作：继续取证；
2. 对应旧声明在 E+ 下仍受支持且不与已提交状态冲突：保留旧声明；
3. 旧声明证据不足：标记不确定，不能静默删除，也不能当作可信事实恢复；
4. 旧声明受到冲突且无受支持替代：撤回；
5. 问题必填槽不能由受支持声明唯一填充：输出证据不足或拒答。

## 6. 声明映射与依赖闭包

### 6.1 声明映射键

主映射键固定为：

```text
(event_id, subject_role, predicate)
```

时间范围用作相容条件，声明值不进入主映射键。值只用于区分保持、替换和等价压缩。因此“价格199元”和“价格99元”仍会映射为同一价格事实槽的替换，不会误判为两个无关声明。

### 6.2 双域结构

若边 `X→Y` 表示“Y 的成立依赖 X”，则：

- 从变化声明沿出边取得下游事务闭包；这些声明共同提交或回退；
- 沿入边取得上游证明上下文；这些声明参与核验，但不因被读取而自动回滚。

### 6.3 稀疏边规则

边类型优先限制为：

- `attribute_of`
- `quantity_of`
- `time_of`
- `cause_of`

只有两端对应同一已消歧事件、时间关系相容且关系置信条件满足时才建边。仅共享品牌、实体、视频帧或证据标识不建边。初稿实施方式采用一跳、最多三个节点；这是示例参数，不写死在主独权中。

## 7. 迁移类型与不对称证明义务

| 迁移 | 提交条件 |
|---|---|
| 保持 | 旧声明在 E+ 下仍为支持 |
| 新增 | 新声明为支持，全部必要槽具有 ΔE 支持见证 |
| 替换 | 新声明为支持；旧声明为冲突，或旧声明不足但新旧值互斥且新值获得正向见证 |
| 撤回 / 不确定化 | 直接冲突才允许撤回；单纯不足只能进入不确定，不能静默删除 |
| 等价压缩 | 事实槽和值保持等价，压缩后的表达仍受 E+ 支持 |

## 8. 跨闭包规则

每个闭包记录状态写入集合 `W` 和证明引用集合 `R`。若闭包 B 改变的事实槽被闭包 A 用作证明前提，即：

```text
W_B ∩ R_A ≠ ∅
```

则 B 处理后必须重新核验 A。若重核验仍产生非等价目标值或证明上下文冲突，禁止 A、B 分别提交，并合并为联合闭包；联合闭包全部通过才提交，否则整体不写入候选状态。

## 9. 最终答案的生成限制

最终重组器只能读取允许输出集合 `C_allow`：

```text
C_allow = 已提交候选声明 + E+ 下仍受支持且无冲突的旧声明
```

输出后再次拆声明。任何输出声明不能映射到 `C_allow` 时，先删除并重组；再次失败时回到最后一个受支持状态，必填槽缺失则拒答。

## 10. 独立权利要求必须保留的内容

1. 支持缺口触发同视频未覆盖 ΔE；
2. A2 不以 A0 为待改写输入；
3. A0/A2 声明映射和实质变化识别；
4. 有向下游事务闭包与上游证明上下文；
5. 同 E+、同核验定义下的支持 / 不足 / 冲突复核；
6. 每项实质变化的 ΔE 必要槽见证；
7. 闭包全成或全败，以及不复活失效旧声明的安全状态机；
8. 仅基于已提交 / 保留声明的受限重组和无新增声明终检。

## 11. 放到从属权利要求或实施例的内容

- 一对一、一对多、多对一和未匹配声明映射；
- 一跳、节点上限、具体边类型和置信条件；
- 数值绝对阈值和同 E+ 相对提升裕量；
- 跨闭包 `W/R` 失效传播；
- 必填槽与附加槽的局部撤回 / 整体拒答；
- 匹配反事实见证必要性；
- MMR、OCR、ASR、区域视图、Token 预算和审计字段；
- 验证器训练方法，建议由代理人决定并案、分案或另案。

## 12. 三个实施例的固定结论

1. **成功替换**：旧价格在 E+ 下冲突，新价格由 ΔE 的 OCR/ASR 逐槽支持，相关价格闭包整体通过，提交新价格。
2. **局部回退**：核心产品特点受支持，但候选附加价格证据不足；价格闭包不提交，特点闭包保留，最终只输出受支持特点。
3. **拒答**：A0、A2 都不能填充问题必填价格槽，预算耗尽；不恢复 A0、不采用 A2，输出证据不足。
