# 基于视频证据与答案双差分配准的更新控制 V4.4.1 查新后收紧建议

版本定位：V4.4 的查新后收窄分支；不覆盖 V4.4 原文件。  
目的：把分散的“观测、验证、门控、闭包”压成一个双差分状态转换机制。

## 一、一句话方案

系统先在不读取 A0/A2 候选值的情况下，从新增且此前未使用的视频证据 ΔE 计算 `E0→E+` 的事实状态差分并冻结为许可；许可字段在 A2 冻结前对 A2 生成器不可见，A2 又不接收 A0；随后系统在同一 E+ 下计算 `A0→A2` 的答案事实差分，只有与前述证据事实差分在槽、上下文、值和 ΔE 见证上逐项对应的迁移，才允许按语义依赖闭包原子写入。

## 二、为什么比 V4.4 更集中

V4.4 的表面步骤包括槽模式、补证、观测、冻结、独立生成、同证据复评、值匹配、禁写和闭包。查新后，这些零件分别都有近邻。

V4.4.1 不再把它们分别当创新，而只主张一个机器状态关系：

```text
证据状态差分：ΔObs = Normalize(E+) − Normalize(E0)
答案状态差分：ΔAns = Normalize(A2 | E+) − Normalize(A0 | E+)

Commit(ΔAns) ⇔
  PermitFrozenBeforeA2(ΔObs)
  ∧ HiddenFromGenerator(ΔObs)
  ∧ InjectiveMatch(ΔAns, ΔObs, slot, context, value, witness)
  ∧ ClosureComplete(ΔAns)
```

也就是：**答案只能改变到新增视频证据确实新增或改变了的事实状态。**

## 三、两个计算通道

### 3.1 证据许可通道

输入仅包括：问题 Q、任务规则、E0、ΔE 和 E+。

输出：`EvidenceDeltaPermit`。

```json
{
  "permit_id": "P_price_001",
  "slot_key": "product.promo_price",
  "old_observation_state": "UNRESOLVED",
  "new_fact": {
    "subject": "product_1",
    "predicate": "promo_price",
    "value": 79,
    "unit": "CNY",
    "qualifiers": {"price_type": "limited_offer"}
  },
  "delta_witness_ids": ["frame_11.2_roi_07"],
  "old_snapshot_id": "E0_hash",
  "new_snapshot_id": "Eplus_hash",
  "resolution_state": "RESOLVED",
  "competition_group_id": "CG_price_01",
  "created_before_A2": true,
  "answer_value_blind": true,
  "generator_hidden": true
}
```

许可只在以下条件成立时生成：

1. 见证属于 E0 未使用的同视频 ΔE；
2. 对应槽在 E0 下为未解析、旧值或缺少所需限定条件；
3. 对应槽在 E+ 下由 ΔE 解析为具体事实值；
4. 同一上下文中不存在达到竞争条件的非等价值；
5. 构造许可时未用 A0/A2 候选事实值检索、抽取或筛选证据。

### 3.2 候选生成通道

输入仅包括：问题 Q 和冻结的 E+ 原始视频证据表示。

明确不包括：

- A0 的语义文本或事实元组；
- `EvidenceDeltaPermit`；
- 许可中的规范化值、解析状态、许可 ID、竞争组或映射键；
- 根据 A0/A2 候选值生成的检索查询。

输出：A2。A2 生成后立即冻结候选标识和内容哈希。

## 四、生成器隔离如何技术化

不要只写“模型不知道许可”，应至少公开一种机器实现：

1. 许可存放于与生成器上下文存储区不同的受控存储区；
2. 生成器服务账户的访问控制列表不含许可读取权限；
3. 生成 API 的输入模式拒绝 `permit_id`、`normalized_value`、`resolution_state` 和 `mapping_key` 字段；
4. 在 A2 内容哈希写入后，控制服务才取得许可与 A2 的联合读取权限；
5. 审计日志记录 A2 输入哈希、许可冻结时间和首次联合读取时间，要求：

```text
t_freeze_permit < t_start_A2 < t_freeze_A2 < t_joint_read
```

A2 仍可读取 E+ 中的原始帧、OCR 原始结果或 ASR 片段；隔离的是证据许可通道形成的规范化结论及控制状态，而不是把视频证据完全藏起来。

## 五、答案差分与许可配准

A0 与 A2 均在同一 E+ 和同一配置下拆为规范化事实元组。映射产生以下实质迁移：

- 新增：`∅→f_new`；
- 替换：`f_old→f_new`；
- 撤回：`f_old→∅/uncertain`；
- 保留和等价压缩不作为实质写入迁移。

每项实质迁移必须满足：

```text
Match(m, p) =
  SameSlot(m, p)
  ∧ SameEntityPredicate(m, p)
  ∧ CompatibleQualifiers(m, p)
  ∧ ValueCompatible(m.new_fact, p.new_fact)
  ∧ WitnessSubset(p.delta_witness_ids, ΔE)
  ∧ SnapshotValid(p, E0, E+)
```

并采用一一映射约束：

- 一个许可不得同时授权两个互不相容的新事实；
- 一个实质迁移不得拼接多个不同上下文许可来凑出新值；
- 确定性派生值必须记录上游许可 ID、运算符、输入单位和舍入规则。

## 六、写入状态机

| 条件 | 状态动作 |
|---|---|
| 新事实匹配唯一有效许可，且旧事实在 E+ 下受冲突或不再适用 | 允许替换 |
| 新增事实匹配唯一有效许可，且槽允许新增 | 允许新增 |
| A2 值与许可值不匹配 | 禁止写入 A2 值 |
| 同上下文存在竞争许可 | 不发放许可，继续取证或输出不确定 |
| A2 未变化但 E+ 已直接冲突 A0 | 不机械保留 A0；进入撤回/不确定/拒答分支 |
| 许可快照失效或见证被撤销 | 撤销依赖许可的暂存迁移并重核验 |
| 闭包中任一实质迁移无许可 | 整个闭包不提交 |

核心问句对应闭包整体失效且无可支持答案时拒答；仅附加声明失效时撤回该附加声明并保留其余已支持内容。

## 七、独立权利要求 1 骨架

> 一种基于视频证据差分与答案事实差分配准的视频问答答案更新控制方法，其特征在于，包括：
>
> 获取针对视频问题的初始证据快照 E0 及初始答案 A0，并根据所述视频问题确定规范化事实槽；
>
> 针对在 E0 下未解析的事实槽，从所述视频取得区别于 E0 中已使用证据单元的增量视频证据 ΔE，并固定由 E0 与 ΔE 构成的扩展证据快照 E+；
>
> 分别确定所述事实槽在 E0 和 E+ 下的规范化观测状态，在 E0 下的观测状态与 E+ 下由 ΔE 形成的观测状态存在实质事实差分时，生成关联旧观测状态、新事实元组、ΔE 时空见证及 E0/E+ 快照标识的证据差分许可，其中生成所述证据差分许可时不以 A0 或候选答案的候选事实值作为证据检索、抽取或选择目标；
>
> 在候选答案生成前冻结所述证据差分许可，并通过存储访问控制或单向数据接口，使所述证据差分许可中的规范化值、解析状态及映射标识在候选答案冻结前不能被候选答案生成器读取；
>
> 在冻结所述证据差分许可后，以所述视频问题和 E+ 生成候选答案 A2，其中 A2 的生成输入不包括 A0 的语义内容和所述证据差分许可；
>
> 在相同 E+ 及相同规范化配置下分别将 A0 和 A2 转换为事实元组，确定 A0 至 A2 的实质答案事实迁移；
>
> 将所述实质答案事实迁移与所述证据差分许可进行事实槽、实体、谓词、限定上下文、规范化值和 ΔE 时空见证的逐项配准；
>
> 仅在同一语义依赖闭包中的全部实质答案事实迁移分别与有效证据差分许可配准成功、且不存在同一上下文的非等价竞争事实时，原子写入该语义依赖闭包的目标状态；否则禁止写入未获许可的目标状态，并输出 E+ 下最后受支持的事实状态、不确定状态或拒答状态。

该骨架是查新后的讨论稿，不是可直接提交的法定权利要求文本；正式用语需由代理人结合说明书支持和中国审查实践调整。

1. ΔE 已使用单元排除、时间段/帧/ROI/ASR 见证；
2. E0/E+ 观测状态的差分判定；
3. 许可字段、哈希、冻结时序及失效；
4. ACL、独立进程、单向接口或不可读缓存隔离；
5. 同上下文竞争组与基数规则；
6. 一对一、一对多、多对一声明映射；
7. 依赖边类型、出边闭包和上游证明上下文；
8. 许可复用冲突及派生值血缘；
9. 快照更新后的撤销传播和跨闭包重核验；
10. 匹配反事实、支持阈值和相对提升门槛；
11. OCR、ASR、区域裁切、Token 预算；
12. 日志、审计、装置、设备和存储介质。

## 九、三个必须写全的实施例

### 9.1 正常替换

E0 未包含价格画面，A0 为“99 元”。ΔE 的 11.2 秒 ROI 清楚显示“限时 79 元”。许可通道先形成 `UNRESOLVED→promo_price=79`，冻结且不传给生成器。A2 从 Q+E+ 独立得到“79 元”。`A0:99→A2:79` 与许可逐项一致，闭包提交。

### 9.2 候选值错误

许可仍是 `promo_price=79`，A2 却生成“59 元”。虽然 A2 可能有较高总分，`ValueCompatible=false`，所以 59 元不能写入。

### 9.3 许可抽取错误但生成器未被带偏

许可通道因 OCR 错误形成“59 元”，原始 E+ 实际显示“79 元”；由于许可值不传给 A2，A2 独立生成“79 元”。两通道不一致使迁移被阻断并触发复核，而不是把错误许可直接注入 A2 后形成虚假的一致。这是“生成器不可见”限制对应的直接技术效果。
