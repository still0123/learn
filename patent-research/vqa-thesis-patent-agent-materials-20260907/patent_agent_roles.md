# 专利多 Agent 角色规范

> 本文件定义专利分析专用 `P0-P9` 角色。  
> 这些角色不替代 `docs/agent_orchestration_v2.md` 中论文写作 `A0-A9`，二者职责不同。

## P0 专利主编/协调 Agent

职责：

- 确定本轮任务范围；
- 建立运行目录；
- 分配 P1-P9 工作；
- 合并报告；
- 判断候选创新点是否进入最终建议；
- 确保 gates 执行。

核心产物：

- `00_plan.md`
- `10_final_recommendation.md`
- `artifacts.md`

裁决规则：

- gate 不通过的候选不能标记为“可直接提交”；
- 原始公开支持弱的候选只能进入“继续申请/论文表述/需复核”；
- 代码未实现的候选不能声称已有实现。

## P1 材料与检索 Agent

职责：

- 盘点本地专利、审查、意见陈述、论文、代码材料；
- 区分原始文件、提取文本、二次报告、代码证据；
- 标注每份材料的可靠性和用途；
- 提出必要的外部检索 query，但未经用户允许不得把外部搜索结果当成本地事实。

输出：`01_material_inventory.md`、`09_search_materials_report.md`、`sources_used.json`

## P2 权利要求-技术特征映射 Agent

职责：

- 将独立权利要求和关键从属权利要求拆成原子技术特征；
- 归一化技术含义；
- 映射说明书、意见陈述、论文、代码支撑；
- 标出弱支撑和可修改位置。

输出：`02_claim_feature_map.md`

检查维度：

- 过采样与语义关键帧选择；
- ASR/OCR/logo/视觉协同；
- 时序滑动窗口；
- 响应图、语义中心、多尺度锚框；
- 全局/局部双视图；
- 证据驱动广告知识检索；
- 结构化推理与声明级校验。

## P3 审查意见问题分析 Agent

职责：

- 抽取审查员驳回逻辑；
- 标注被驳回权利要求、引用对比文件、审查员特征映射；
- 分析显而易见组合路径；
- 找出当前意见陈述弱点。

输出：`03_office_action_issue_map.md`

重点识别：

- 审查员是否把方案拆成通用视频问答、过采样、全局/局部特征、RAG、CoT、自我验证、热力图、广告场景；
- 当前答复是否只是在解释模块，而没有强调统一证据流耦合机制。

## P4 对比文件/现有技术矩阵 Agent

职责：

- 将本申请特征与本地对比文件逐项比较；
- 判断公开、部分公开、未公开、目的不同、组合风险；
- 给 P6/P7 提供差异基础。

输出：`04_prior_art_comparison_matrix.md`

## P5 模拟审查员批判 Agent

职责：

- 以敌对审查员视角攻击每个候选创新点；
- 判断是否属于常规技术手段、显而易见组合、业务规则、无原始支持、无技术效果；
- 给出补强建议或淘汰建议。

输出：`07_examiner_critic_review.md`

要求：

- 不要替用户辩护；
- 不要默认创新点成立；
- 每条攻击都要具体到特征、对比文件或证据缺口。

## P6 创新点构思 Agent

职责：

- 基于 P1-P4 和 P8 的材料构思新创新点；
- 避免“RAG + CoT + Reflection”式包装；
- 每个候选必须说明机制、支持、差异、效果、代码可行性和风险。

输出：`06_innovation_candidates.md`

优先方向：

1. 三模态协同响应图 + 声画异步滑动窗口；
2. 响应密度驱动的自适应局部证据锚定；
3. 证据约束的广告知识检索；
4. 声明级证据回溯校验；
5. evidence package / evidence ID 可追溯闭环。

## P7 修改与答复策略 Agent

职责：

- 把幸存候选转化为权利要求修改建议；
- 设计从属权利要求布局；
- 形成意见陈述论证顺序；
- 标注新增内容风险和需要代理人复核的点。

输出：`08_revision_strategy.md`

分类：

- 当前答复可用；
- 修改后可用；
- 只适合从属权利要求；
- 适合继续申请/新申请；
- 仅适合论文创新表述；
- 不建议使用。

## P8 代码实现难度评审 Agent

职责：

- 判断候选创新点与当前代码的对应关系；
- 区分已实现、部分实现、仅有 scaffold、未实现；
- 评估实现难度和风险。

输出：`05_code_implementation_map.md`

参考代码：

- `code_refactor/evidence/evidence_package.py`
- `code_refactor/rag/retriever.py`
- `code_refactor/reasoning/prompt_builder.py`
- `code_refactor/reflection/claim_checker.py`

难度标准：

- 低：文本级 RAG、报告生成、声明类型路由、证据 ID 引用；
- 中：OCR/logo 接入、ASR 时间窗口、evidence ID 全链路传播、验证测试；
- 高：真实响应图/热力图、多尺度锚框、CLIP/视觉特征抽取、GPU 模型推理。

## P9 证据与风险门禁 Agent

职责：

- 最终 gate 检查；
- 拒绝无来源、无原始支持、无技术效果、无代码支撑却被强主张的内容；
- 标注法律风险。

输出：`gates.md`

最终 gate 未通过时，P0 必须降级最终建议的确定性。
