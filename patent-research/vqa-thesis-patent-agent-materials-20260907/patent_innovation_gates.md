# 专利分析 Gates 门禁规范

每轮专利分析在 `10_final_recommendation.md` 定稿前，必须由 `P9 证据与风险门禁 Agent` 输出 `gates.md`。未通过 gate 的内容不能写成“可直接提交”。

## Gate 1：材料覆盖

必须覆盖：

- 专利文本；
- 审查意见/驳回决定；
- 意见陈述书；
- 本地对比文件或现有技术材料；
- 本地论文/开题材料；
- 相关代码实现。

输出：

```markdown
## Gate 1 材料覆盖
- 结论：通过/不通过/部分通过
- 已覆盖材料：
- 缺失材料：
- 对结论影响：
```

## Gate 2：原始公开支持

每个最终创新点都必须能在原始说明书、权利要求、附图说明或已提交文本中找到支持。

```markdown
## Gate 2 原始公开支持
| 创新点 | 支持来源 | 支撑强度 | 新增内容风险 |
|---|---|---|---|
```

规则：

- 支撑强度为“弱”的内容不得直接写入独立权利要求；
- 无原始支持的内容只能进入“继续申请/新申请/论文表述”类别；
- 不能用当前对话中新构思的内容倒推为原始公开。

## Gate 3：相对现有技术差异

每个最终创新点必须说明它与本地对比文件的差异。

```markdown
## Gate 3 现有技术差异
| 创新点 | D1 | D2 | D3 | D4 | D5 | 总体风险 |
|---|---|---|---|---|---|---|
```

风险判断：

- 高：核心特征已被一个或多个对比文件公开，或容易组合；
- 中：部分特征公开，但耦合关系、应用约束或技术效果仍可争辩；
- 低：核心机制、约束条件和技术效果均有清晰差异。

## Gate 4：技术效果

创新点必须说明客观技术效果，但不得编造实验结果。

```markdown
## Gate 4 技术效果
| 创新点 | 可主张效果 | 证据来源 | 是否需实验补充 |
|---|---|---|---|
```

禁止表述：

- “显著提高准确率”但无数据；
- “大幅降低 token”但未测量；
- “有效避免幻觉”但无验证；
- “保证正确”。

可接受表述：

- “预期降低无关知识注入风险，需实验验证”；
- “通过 evidence ID 约束输出来源，提高可追溯性”；
- “通过局部高分辨率证据保留短时文字/Logo 信息”。

## Gate 5：非模块拼接

必须回答：

1. 是否像普通视频问答套广告场景？
2. 是否像普通 RAG？
3. 是否像 CoT Prompt？
4. 是否像 Self-Refine/自我验证？
5. 是否像热力图/全局局部特征的常规应用？

```markdown
## Gate 5 非模块拼接
| 风险问题 | 结论 | 理由 | 补强建议 |
|---|---|---|---|
```

任一核心创新点被判定为“高风险模块拼接”时，不能进入最终推荐前三。

## Gate 6：代码可行性

必须区分：

- 已实现；
- 部分实现；
- scaffold；
- 未实现；
- 需要外部模型/GPU/OCR/ASR 支撑。

```markdown
## Gate 6 代码可行性
| 创新点 | 代码状态 | 支撑路径 | 难度 | 风险 |
|---|---|---|---|---|
```

禁止把 scaffold 写成完整实现。

## Gate 7：无虚构数据

检查最终报告是否出现未证实数据。

```markdown
## Gate 7 无虚构数据
- 结论：通过/不通过
- 可疑表述：
- 修改建议：
```

## Gate 8：法律表述谨慎

最终报告必须避免确定性授权结论。

禁止：

- “一定具备创造性”；
- “审查员错误”；
- “保证授权”；
- “可以直接提交且无风险”。

推荐：

- “具有较强答辩潜力”；
- “需结合原始公开进一步复核”；
- “建议由专利代理人确认新增内容风险”；
- “更适合继续申请或新申请布局”。

```markdown
## Gate 8 法律表述谨慎
- 结论：通过/不通过
- 需代理人复核事项：
```

## 总体结论

`gates.md` 结尾必须给出：

```markdown
# 总体 Gate 结论

- 本轮是否可进入最终推荐：是/否/部分
- 可当前答复使用的创新点：
- 需修改后使用的创新点：
- 不建议使用的创新点：
- 需代理人复核的事项：
```
