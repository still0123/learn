# Round33：V4.6 权利要求1冻结特征图

以下 R1—R10 必须作为一条连续数据控制链评价，不能把单个模块分别称为创新。

| 编号 | 权利要求1中的必要限定 | 直接技术作用 |
|---|---|---|
| R1 | 从同一视频取得排除 E0 已用来源的 ΔE，并冻结 E+=E0∪ΔE | 固定增量来源和统一复核快照 |
| R2 | 许可服务不能读取 A0/A2 及其派生事实值，且不能以答案值选证 | 阻断待验证结论反向污染证据差分 |
| R3 | 许可依据同槽位 E0→E+ 观测差分及属于 ΔE 的时空模态见证形成 | 把许可绑定到新增视频事实，而非一般置信度 |
| R4 | 满足 `t_p<t_s<t_a<t_j`；A2 冻结前禁止许可字段流入候选服务 | 用可审计时序证明两个差分独立形成 |
| R5 | 候选服务仅读 Q 与 E+ 原始视频表示，不能读取 A0 或许可 | 使 A2 不是 A0 改写，也不是许可值复述 |
| R6 | A0/A2 在同一 E+、同一槽模式和同一核验配置下配对复核 | 排除证据口径不一致造成的偏置 |
| R7 | 将 A0→A2 转为规范化事实迁移，并区分新增、替换、撤回等状态 | 把答案更新变成可检查的事实状态变化 |
| R8 | 每一实质迁移按槽、事件、谓词、上下文、值/状态、快照和 ΔE 见证与唯一许可配准 | 证明“答案变化”确由同一新增视频事实授权 |
| R9 | 沿预定义有向依赖边形成下游写入闭包，并区分上游只读证明引用 | 限定共同提交范围，避免整答案或无界回滚 |
| R10 | 闭包内全通过才原子写入；失败全部禁写，且不复活 E+ 下已冲突旧事实 | 避免部分更新和失败后恢复错误旧事实 |

## 最小不可再删组合

若必须压缩权利要求，至少保留：`R2 + R3 + R4 + R5 + R6 + R8 + R10`。R1、R7、R9提供视频来源、事实粒度与依赖事务的落地边界，也不建议在当前检索结果下删除。

## 不能再单独主张的上位概念

- 低置信/证据不足后补取视频片段；
- 生成第二答案并与当前答案比较；
- 时间戳证据支持候选、冲突当前答案后才替换；
- 句级/事实级答案—证据映射；
- 独立防御通道控制候选输出；
- 许可后提交、失败回滚或一般事务日志。
