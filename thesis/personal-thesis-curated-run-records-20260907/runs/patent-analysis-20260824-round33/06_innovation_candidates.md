# Round33 算法创新候选

## 候选 A：运行时信息流非干扰作为许可有效条件

- **机制**：为许可、候选输入及其派生数据记录来源标签和传递闭包。许可的祖先集合不得含 A0/A2；候选输入及 A2 的祖先集合不得含 A0、许可字段或其派生值。发现跨域传播时，不仅记录安全异常，而且使对应许可、迁移配准和暂存闭包同时失效。
- **与主线耦合**：它把 R2/R4/R5 的读取隔离直接变成 R8/R10 的提交前置条件，防止 ACL 配置存在但共享缓存或中间字段仍造成污染。
- **技术效果**：可机械核验候选变化和证据许可是否在联合读取前独立形成；不主张准确率数值。
- **近案风险**：动态污点分析、数据血缘及独立重算均属成熟技术；不能单独主张“来源跟踪”创新。
- **位置**：从属权利要求5/15或实施方式；不改独权骨架。
- **建议**：**保留为可实施性增强，不作为新主创新点。**

## 候选 B：许可—迁移联合反事实必要性

- **机制**：移除 ΔE 见证并换入匹配非见证后，要求目标观测状态消失、许可失效，并使对应迁移因无唯一有效许可而被闭包禁止写入。
- **与主线耦合**：把现有权14的“见证必要”贯通到 R3→R8→R10，不仅测模型答案变化。
- **近案风险**：Evidence-RL 已覆盖匹配反事实证据对照，PBRC 已覆盖见证与回退；风险高。
- **位置**：仅限缩现有从属权利要求14。
- **建议**：**可优化表述，但不承担创造性。**

## 候选 C：确定性全局配准与版本化闭包提交

- **机制**：构建迁移—许可兼容二部图，要求闭包内存在无竞争的唯一可接受配准；有向依赖图先按强连通分量压缩，再记录证明引用版本，提交前以版本比较和条件原子写入避免 TOCTOU。
- **与主线耦合**：使现有“唯一配准 + 闭包全写/全禁写”可复现。
- **近案风险**：匹配、SCC、版本向量和 CAS 都是常规算法。
- **位置**：具体实施方式和伪代码。
- **建议**：**写入实现细节，不称为新增创新点。**
