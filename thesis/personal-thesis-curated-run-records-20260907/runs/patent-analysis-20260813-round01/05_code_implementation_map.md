# 代码与实验支撑

| 新稿特征 | 状态 | 证据与限制 |
|---|---|---|
| 统一 evidence ID | 基础原型 | `EvidencePackage.evidence_id` 已贯通部分RAG和Prompt；未形成稳定全局谱系 |
| 父子证据追溯 | 仅SPEC/局部审计 | schema无 `source_evidence_id`、操作类型和派生关系 |
| 声明-证据三态矩阵 | 未完整实现 | `ClaimCheckPlan`只做规则分类；三态实验中的 `insufficient` 表现不足 |
| `LOOK_TIME/LOOK_REGION` | 实验原型 | 已运行规则控制器，但未证明优于随机补看或同Token整帧 |
| 反事实充分性 | 原型且效果不稳定 | 可用于依赖分析，不能证明可靠选择正确答案或提升QA |
| 答案替换门控 | 实验系统已实现 | 完整补看+门控在Confirm-600取得小幅正向结果 |

## 可支撑效果

- evidence ID可用于机器可读引用关联。
- OCR/ASR与局部/全局证据能形成可审计输入。
- 低支持触发、补看、重答及保守门控的完整组合取得正向结果。
- 视觉反事实可以作为证据依赖分析工具。

## 不可支撑效果

- 不能称父子证据谱系已完整实现。
- 不能称支持/冲突/缺失三态矩阵已验证。
- 不能称主动路由优于随机或统一补看。
- 不能称反事实充分性能够可靠决定答案替换。
- 不能把完整组合增益归因于统一ID、裁剪、路由或反事实任一单模块。
- 门控不能宣称零伤害；Full-7844仍存在 `right→wrong`。

## 独权影响

当前独权把多个“原型/仅SPEC”特征放入核心链路。若继续保留，必须补充至少一个端到端实施例、字段定义、状态转移和可复现参数；否则存在充分公开和技术效果支撑风险。
