# 最终建议

## 对旧申请驳回的判断

驳回不是因为完全没有区别特征，而是因为原独权把多个相对独立的已知模块放在同一流水线中。审查员能够为每个模块找到相同用途的对比文件或公知常识，并认定组合只产生各自预期效果。

旧答复的主要问题不是文字不充分，而是：

1. 独权过宽，具体算法留在从权。
2. 主要依赖场景差异和“整体协同”定性论证。
3. 没有把协同写成不可拆分的数据依赖和状态转移。
4. 没有提供对应组合的直接技术效果。
5. 第二轮没有继续修改权利要求。

## 对新候选稿的判断

新稿已经绕开旧稿最明显的RAG、CoT、关键词反思拼接，但只完成了“方向性绕开”：

- S4声明-证据关系是核心新区别。
- S5缺口驱动补证和父子回溯是最强新区别。
- S2统一ID、S6阈值门控、S7追溯输出单独看仍较常规。
- 当前独权尚未写明S4如何计算、S5如何生成参数、补证后如何更新S4状态。

因此，新稿当前状态仍属于：

> 候选方向 / 修订建议 / 需代理人复核

不属于：

> 可直接提交

## 优先级

1. 放弃旧申请复审，不再投入旧案答复。
2. 将当前候选稿降级为材料库，不直接修改成提交稿。
3. 从空白建立新申请的证据图、父子谱系和参数化路由。
4. 完成同预算路由对照实验。
5. 以新技术问题、新必要特征和新实施例重写独权。

## 新申请隔离原则

- 旧案全部公开内容按现有技术处理。
- 广告视频作为实施场景，不作为创造性来源。
- 旧案的RAG、CoT、双流视觉和关键词校验不得回到新独权。
- 新独权只保护声明状态、补证参数、父子证据回写和同状态门控之间的计算依赖。

## 一句话结论

旧申请被驳回的本质是“技术链条在文字上连续、在权利要求中却仍可拆分”。新申请要过关，必须让上一步产生的结构化状态成为下一步唯一且可计算的输入，而不是再次把已知模块按流程连接。
