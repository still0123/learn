# P7 修改与新申请策略

## 1. 执行结论

本轮建议不再围绕原申请的“视听协同感知、响应图、自适应锚定、广告知识库 RAG、结构化思维链校验”继续扩写独立权利要求。原申请文本已经完整覆盖这些模块，且第一轮最终建议已提示：`RAG + CoT + Reflection`、普通全局/局部视觉输入、普通自验证和普通知识检索容易被现有技术组合吸收。

另案重申请建议改为一条新的系统主线：

> 面向广告视频问答的可追溯多模态证据一致性图谱构建、冲突仲裁与可信证据包约束生成方法。

该主线的核心不是“如何找到局部视觉区域”，而是“如何把问题、视觉、OCR、ASR、广告知识和生成答案之间的支持关系、矛盾关系、证据强度和可引用边界显式结构化，并用该结构约束答案生成”。这样可与原案形成更清晰的技术分工：

- 原案：偏前端感知和视觉证据定位，重点是响应图、锚框、双流视觉表征。
- 新案：偏证据治理和可信生成，重点是证据单元、证据图谱、一致性评分、冲突仲裁和答案引用约束。

本文件仅作为代理人加工底稿，不构成授权结论。所有创造性、新颖性和新增内容风险仍需代理人结合外部检索复核。

## 2. 建议新专利名称

首选名称：

**一种基于多模态证据一致性图谱的广告视频问答可信生成方法及系统**

备选名称：

1. 一种面向广告视频问答的多模态证据包构建、冲突仲裁与答案生成方法
2. 一种基于问题驱动证据路由和一致性校验的广告视频可信问答方法
3. 一种融合视觉、语音、文字与广告知识证据的可追溯问答生成方法

推荐使用首选名称。它避免直接复用原案“视听协同感知与链式校验”的标题关键词，同时突出新案的结构性特征：证据一致性图谱、可信生成。

## 3. 新申请技术问题

建议在背景技术中强调以下问题，避免重复原案的“关键帧定位、局部裁剪、知识库注入”叙事：

1. 广告视频问答中，不同模态证据经常相互矛盾。例如画面展示情绪氛围，旁白描述产品卖点，OCR 出现促销条件，广告知识库给出抽象营销理论，模型生成时容易把不同层级证据混用。
2. 现有多模态问答方法通常只把视觉、OCR、ASR、检索知识作为上下文拼接给大模型，缺少对每个答案声明由哪些证据支持、哪些证据反驳、证据是否过期或跨时间错配的结构化管理。
3. 现有反思校验多依赖再次提示大模型自查，校验过程缺少可计算的证据一致性图谱和冲突仲裁规则，因此难以稳定避免事实性幻觉、跨模态错配和广告理论过度解释。

新申请要解决的技术问题可表述为：

> 如何在广告视频问答中，将视觉对象、OCR 文字、ASR 语音、用户问题和广告知识条目组织为可追溯的证据图谱，并在生成答案前对候选答案声明进行支持度、矛盾度、时序一致性和知识适配度计算，从而约束大模型仅基于可信证据包输出答案。

## 4. 独立权利要求1草案

以下是方法权利要求底稿，代理人可继续调整术语、步骤顺序和保护范围。

### 权利要求1草案

一种基于多模态证据一致性图谱的广告视频问答可信生成方法，其特征在于，包括：

S1、获取待分析广告视频、用户自然语言问题以及与所述广告视频对应的多模态基础证据，所述多模态基础证据至少包括视频关键帧中的视觉对象证据、图像文字证据、品牌或标识证据、语音转写证据以及与广告理解相关的知识条目证据；

S2、对所述用户自然语言问题进行问题意图解析，得到至少一个问题约束项，所述问题约束项包括证据类型约束、时间范围约束、事实属性约束和解释层级约束中的至少一种；

S3、根据所述问题约束项，对所述多模态基础证据进行问题驱动的证据路由，筛选得到候选证据单元集合，并为每个候选证据单元生成证据标识、模态类型、时间位置、空间位置、语义标签、置信度和来源路径；

S4、基于所述候选证据单元集合构建多模态证据一致性图谱，其中，图谱节点对应候选证据单元，图谱边表示不同候选证据单元之间的支持关系、补充关系、矛盾关系、时序邻接关系或知识映射关系；

S5、对所述多模态证据一致性图谱进行一致性评分和冲突仲裁，计算候选证据单元或证据子图相对于所述用户自然语言问题的支持度、矛盾度、时序一致性和知识适配度，并基于预设仲裁规则生成可信证据包；

S6、将所述可信证据包、所述用户自然语言问题和答案生成约束输入多模态大语言模型，约束所述多模态大语言模型在生成答案时引用所述可信证据包中的证据标识，并禁止输出未被所述可信证据包支持的事实性声明；

S7、对生成答案中的至少一个答案声明进行证据回填校验，若答案声明未能映射至所述可信证据包中的证据标识，或与所述多模态证据一致性图谱中的矛盾关系相冲突，则删除、降级或重写该答案声明，输出经证据约束的广告视频问答结果。

### 权利要求1的写法要点

- 不把“响应图、语义重心、多尺度锚框、双流视觉表征”写成独立权利要求核心，避免落回原案。
- 不把“RAG、CoT、自我反思”作为发明点，而把它们降为可选实现或背景组件。
- 必须保留“证据单元 -> 证据图谱 -> 一致性评分/冲突仲裁 -> 可信证据包 -> 证据约束生成 -> 声明回填校验”这一连续链条。
- 权利要求1中“视觉对象证据、图像文字证据、品牌或标识证据、语音转写证据、广告知识条目证据”可以按代理人意见改为“至少两种”或“至少三种”，以平衡保护范围和新颖性风险。

## 5. 从属权利要求布局建议

### 从属权利要求2：证据单元数据结构

限定候选证据单元包括：

- evidence_id；
- modality_type；
- temporal_span；
- spatial_region；
- semantic_label；
- confidence_score；
- source_path；
- extracted_text；
- linked_question_constraint。

目的：把“证据包”从抽象概念落到可执行数据结构。

### 从属权利要求3：问题驱动证据路由

限定问题意图解析根据问题中的词项或语义槽位选择证据类型：

- 包含文字、价格、品牌、logo 等问题时，提高 OCR/Logo 证据权重；
- 包含说、旁白、声音等问题时，提高 ASR 证据权重；
- 包含为什么、意图、策略、受众等问题时，同时路由至视觉证据和广告知识条目；
- 包含时间顺序或变化类问题时，启用时序邻接证据。

目的：区别于普通上下文拼接，强调证据选择由问题约束显式控制。

### 从属权利要求4：证据一致性图谱边类型

限定图谱边至少包括：

- 支持边：两个证据单元指向同一事实声明；
- 矛盾边：两个证据单元在文本、数值、对象、时间或解释结论上冲突；
- 补充边：一个证据单元为另一个证据单元提供背景解释；
- 时序邻接边：两个证据单元在广告视频时间线上相邻或重叠；
- 知识映射边：视频证据与广告知识库条目之间建立概念映射。

目的：使“一致性图谱”具备可审查的结构边界。

### 从属权利要求5：一致性评分

限定一致性评分至少由以下分数加权得到：

- question_relevance_score：证据与问题约束项的相关度；
- cross_modal_support_score：不同模态证据对同一声明的共同支持度；
- contradiction_score：证据间冲突强度；
- temporal_alignment_score：证据时间窗口与声明时间范围的一致程度；
- knowledge_fit_score：广告知识条目与视频证据的适配程度。

目的：为冲突仲裁提供可计算规则，避免“模型觉得可信”的纯提示词表述。

### 从属权利要求6：冲突仲裁规则

限定当证据发生冲突时，按照问题类型和证据来源进行仲裁：

- 对事实文字、价格、品牌名称类声明，优先采用 OCR 或局部视觉证据；
- 对语音内容类声明，优先采用带时间戳的 ASR 证据；
- 对广告意图、说服策略、受众画像类声明，要求视觉证据与广告知识条目同时支持；
- 当矛盾度超过阈值时，生成“不确定”或“证据不足”的受控答案，而不是强行给出结论。

目的：把可信生成与商业场景下的幻觉控制结合起来。

### 从属权利要求7：可信证据包生成

限定可信证据包包括：

- 被采纳证据列表；
- 被排除证据列表及排除原因；
- 支持的候选答案声明；
- 禁止生成的事实声明；
- 证据引用格式；
- 不确定性标记。

目的：进一步强化新案的“证据治理”属性。

### 从属权利要求8：答案生成约束

限定多模态大语言模型输出答案时：

- 每个事实性句子必须关联至少一个 evidence_id；
- 推断性或营销解释性句子必须关联至少一个视频证据和至少一个知识条目证据；
- 未达到支持度阈值的声明被改写为不确定表达；
- 与矛盾边关联的声明不得作为确定性结论输出。

目的：区别于普通结构化提示词或普通 CoT。

### 从属权利要求9：答案声明回填校验

限定对生成答案进行声明抽取，将声明反向匹配至可信证据包，无法匹配时执行删除、降级或重写。

目的：将“校验”从原案的链式反思迁移为“声明-证据映射”的后处理机制。

### 从属权利要求10：系统、装置和介质

建议另设系统权利要求，模块包括：

- 问题意图解析模块；
- 证据路由模块；
- 证据单元构建模块；
- 证据一致性图谱构建模块；
- 冲突仲裁模块；
- 可信证据包生成模块；
- 答案约束生成模块；
- 声明回填校验模块。

同时保留电子设备和计算机可读存储介质权利要求。

## 6. 说明书实施例框架

### 6.1 技术领域

可写为：

本发明涉及多模态视频理解、广告视频问答和可信人工智能技术领域，尤其涉及一种基于多模态证据一致性图谱的广告视频问答可信生成方法及系统。

### 6.2 背景技术重点

背景技术不要重复原案的“关键帧优选、局部裁剪、声画异步”作为主要矛盾。建议改为：

- 多模态大语言模型可同时接收视觉、OCR、ASR 和知识库内容，但多源证据通常以拼接方式输入。
- 拼接式输入缺少证据之间的支持和矛盾关系建模，导致模型在广告场景中容易把品牌文字、旁白、营销理论和画面隐喻混为同一层级事实。
- 现有自我反思校验多依赖语言模型再次生成，缺乏结构化证据标识、冲突边和声明级引用约束，因而校验结果不可追溯、不可稳定复现。

### 6.3 发明内容主线

建议按五个层次组织：

1. 证据单元化：把视觉、OCR、ASR、Logo、广告知识条目统一表示为带来源路径、时间位置和置信度的证据单元。
2. 问题驱动路由：根据用户问题自动选择证据类型和证据时间范围。
3. 一致性图谱：建立证据单元之间的支持、矛盾、补充、时序邻接和知识映射关系。
4. 冲突仲裁与可信证据包：对证据子图评分，生成可引用、可排除、可标注不确定性的可信证据包。
5. 证据约束生成与回填校验：限制答案只能基于可信证据包生成，并对答案声明反向匹配证据。

### 6.4 具体实施例建议

#### 实施例一：价格或促销文字问答

场景：广告视频画面角落出现促销价格或限制条件，旁白同时强调品牌价值。

流程：

1. 问题包含“价格、文字、条件”等约束项；
2. 证据路由优先选择 OCR 和局部视觉证据；
3. ASR 作为辅助证据，广告知识条目不参与事实价格结论；
4. 若 ASR 表述与 OCR 数字冲突，仲裁规则优先采用 OCR；
5. 输出答案必须引用 OCR evidence_id。

技术效果表述：降低价格、数字、优惠条件类事实声明的幻觉风险。

#### 实施例二：广告意图或说服策略问答

场景：用户询问广告为什么采用某种画面或想影响哪类受众。

流程：

1. 问题约束识别为解释层级问题；
2. 路由同时选择视觉对象、情绪氛围、ASR 主题词和广告知识条目；
3. 图谱建立视觉证据与“稀缺性、权威背书、情感诉求、社会认同”等知识条目的映射边；
4. 若只有知识条目而无视频证据支持，则不得输出确定性广告策略判断；
5. 输出答案以“画面证据 + 语音证据 + 知识条目”的组合方式引用。

技术效果表述：减少营销理论过度套用，提高广告解释类答案的证据约束性。

#### 实施例三：声画错配或跨模态矛盾问答

场景：旁白说产品适合年轻人，但画面展示家庭场景，用户询问目标受众。

流程：

1. ASR 证据和视觉证据分别形成节点；
2. 图谱建立补充边或矛盾边；
3. 冲突仲裁不简单二选一，而是生成“语音明确指向年轻人，画面同时包含家庭场景，因此答案中需区分显性话术和隐含受众”的证据包；
4. 生成答案区分“明确证据支持”和“可能推断”。

技术效果表述：提升广告视频中声画异步和隐喻表达下的答案可解释性。

### 7.1 与原申请的区别

| 维度 | 原申请 | 新申请建议 |
|---|---|---|

### 7.2 与第一轮驳回风险的区别

第一轮最终建议指出，链式校验、普通 RAG、普通 CoT 和 evidence package 宽泛表述都存在组合风险。新申请应避免以下写法：

- “检索广告知识后让大模型思维链回答”；
- “再次调用校验代理检查答案是否正确”；
- “将视觉、语音、OCR 输入大模型进行融合推理”；
- “生成证据包以提高可信度”但没有具体结构。

新申请必须改成具体技术链：

- 证据单元具备统一字段；
- 证据之间有明确边类型；
- 支持度、矛盾度、时序一致性和知识适配度可计算；
- 冲突时有仲裁规则；
- 答案声明必须反向匹配 evidence_id；
- 不满足证据约束时执行删除、降级、重写或不确定输出。
