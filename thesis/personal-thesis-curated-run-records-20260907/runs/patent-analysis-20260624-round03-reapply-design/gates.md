# Gate 检查

## Gate 1 材料覆盖
- 结论：通过。
- 已覆盖原申请文本、驳回决定/审查意见、意见陈述、第一轮多 Agent 分析、现有代码和多 Agent 规范。

## Gate 2 原始公开支持
- 结论：部分通过。
- 原案支持“多模态证据、ASR/OCR/Logo、证据回溯、结构化生成”等基础，但不完整支持“证据一致性图谱、冲突仲裁、可信证据包”作为原案修改内容。
- 因此这些内容应定位为另案申请，而非原案复审补丁。

## Gate 3 现有技术差异
- 结论：有差异，但风险中高。
- 只有在权利要求中限定节点类型、边类型、一致性评分、冲突仲裁规则和声明级约束生成时，才能与普通 RAG、多模态融合、知识图谱、自验证形成区别。

## Gate 4 技术效果
- 结论：谨慎通过。
- 可主张机制性效果：证据可追溯、跨模态冲突可识别、无证据声明可降级、答案受可信证据包约束。
- 不得主张未经实验支持的准确率提升、幻觉率下降或延迟降低。

## Gate 5 非模块拼接
- 结论：条件通过。
- 必须把方案写成“证据单元 -> 证据路由 -> 一致性图谱 -> 冲突仲裁 -> 可信证据包 -> 声明回填校验”的连续状态链。
- 如果只写“OCR + ASR + RAG + verifier”，则不通过。

## Gate 6 代码可行性
- 结论：通过但未完成。
- 现有代码有 `EvidencePackage`、`claim_checker`、`prompt_builder` 和 RAG 基础。
- 核心图谱、路由、仲裁、可信证据包模块尚未实现。

## Gate 7 无虚构数据
- 结论：通过。
- 本轮未编造准确率、token、延迟、人工评估或消融数据。

## Gate 8 法律表述谨慎
- 结论：通过。
- 本轮仅给出新申请策略，不作授权保证；明确要求代理人复核。
