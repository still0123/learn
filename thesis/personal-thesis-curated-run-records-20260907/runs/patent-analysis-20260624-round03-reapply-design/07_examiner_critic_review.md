# P5 模拟审查员批判报告

## 批判对象

- 新申请方向：多模态证据一致性图谱、问题驱动证据路由、冲突仲裁、可信证据包约束生成。
- 使用材料：
  - `source_texts/patent_office_action_pdf_extract.txt`
  - `source_texts/patent_opinion_statement.txt`
  - `runs/patent-analysis-20260623-round01/10_final_recommendation.md`
  - `runs/patent-analysis-20260623-round01/06_innovation_candidates.md`

## 总体敌对判断

从审查员视角看，新申请不能只把原案的“三模态响应图、双流视觉表征、链式校验”换成“证据图谱、路由、仲裁、可信证据包”的工程名词。第二次审查意见已经明确给出拆解路径：D1 覆盖视频问答主框架，D2 覆盖自验证与修正，D3 覆盖全局/局部视觉特征与知识检索，D4 覆盖多模态对齐与约束解码，D5 和公知常识覆盖热力图/ROI/多模态融合。若新申请仍停留在“多模态证据 + RAG + verifier + 结构化输出”，高概率会被认定为本领域技术人员对已知模块的常规组合。

新申请必须把核心收窄到可执行的数据结构和状态转移规则：证据节点如何生成，跨模态一致性边如何计算，问题类型如何驱动路由，冲突如何按可验证规则仲裁，答案生成如何被证据包硬约束。否则“图谱、路由、仲裁、可信”都会被打成抽象功能效果或业务规则。

## C-01 图谱只是多模态融合/知识图谱的常规表达

### 攻击结论

- 风险等级：高。
- 可能结论：不具备创造性；如果权利要求只写“构建多模态证据一致性图谱”，还可能被认为技术特征不清楚或功能性限定过宽。

### 攻击理由

- 审查员可沿用第二次审查意见中对 D3、D4、D5 的组合：视觉、文本、语音特征对齐和融合属于多模态处理常规手段；热力图、ROI、全局/局部特征和外部知识检索也已有公开。
- “图谱”容易被认为只是把已知证据、OCR、ASR、帧、知识条目用节点和边表示，属于数据组织方式，不必然产生新的技术效果。
- “一致性”如果仅指相似度高、语义一致、互相支持，会被认为是多模态相似度计算或知识图谱置信边的常规用法。

### 当前证据弱点

- 第一轮报告已提示 evidence package / evidence ID 在原案公开中支持弱，适合继续申请而非当前答复主线。
- 现有创新候选 I-05 主要来自代码结构，缺少原始专利文本中对统一证据图谱的明确支持。
- 目前没有定义图谱的节点类型、边类型、边权更新规则、冲突状态和生命周期。

### 如何补强

- 权利要求：不要只写“构建图谱”。至少限定节点包括视频帧节点、局部区域节点、OCR 文本节点、ASR 片段节点、广告知识节点、候选答案声明节点；边包括时间对齐边、空间包含边、语义支持边、语义矛盾边、来源派生边，并限定边权由时间偏移、空间响应密度和语义相似度共同生成。
- 说明书：补充图谱初始化、边权计算、冲突传播、证据包导出的完整流程图和伪代码，强调它不是泛化知识图谱，而是面向视频问答证据状态管理的中间表示。
- 代码实验：实现一个最小 `EvidenceGraph`，输出每个答案声明关联的支持边和矛盾边；用样例证明无图谱时证据断链，有图谱时可定位冲突来源。

## C-02 问题驱动证据路由会被打成检索/注意力/任务路由常规手段

### 攻击结论

- 风险等级：高。
- 可能结论：在 D1 的问题驱动候选区域检索、D3 的查询向量检索、D4 的语义解析策略基础上显而易见。

### 攻击理由

- 第二次审查意见已认定：根据自然语言问题提取关键意图、进行多粒度检索、筛选关键视觉信息，是对比文件1公开或容易想到的内容。
- 如果路由规则只是“价格问题查 OCR、旁白问题查 ASR、画面问题查关键帧、营销问题查知识库”，审查员会认为这是基于问题类型选择数据源的常规工程规则。
- “为节省算力而按需触发/按需检索”在审查意见中已被明确称为惯用技术手段。

### 当前证据弱点

- 原案的高风险触发关键词已被审查员打成按需校验的常规优化。
- 第一轮 I-04 也承认触发式多模态证据回溯最容易被 D2 吸收成“自验证 + 修正”。
- 现有代码中 `claim_checker.py` 的 claim type 路由若只是类型到证据源映射，难以支撑创造性。

### 如何补强

- 权利要求：把“路由”写成多阶段约束，而不是简单分类。例如：先将问题解析为声明槽位和证据需求向量，再按证据需求向量在图谱中激活候选子图，再根据候选子图的支持/矛盾边密度决定补采 OCR、ASR 或局部视觉证据。
- 说明书：强调路由结果不是固定规则表，而是由“问题槽位、证据节点可用性、一致性缺口、冲突类型”共同决定。
- 代码实验：对比固定规则路由与图谱缺口驱动路由；统计命中证据节点数量、无证据回答比例、错误引用 OCR/ASR 的比例。

## C-03 冲突仲裁会被认为是投票、置信度排序或自验证修正常规化

### 攻击结论

- 风险等级：高。
- 可能结论：不具备创造性；容易被 D2 自验证、D3 置信度重排序、D5 注意区域筛选以及常规 ensemble/voting 吸收。

### 攻击理由

- 审查员已经把“确认令牌/修正令牌”视为常规反馈形式，把二次核查视为显而易见。
- 如果冲突仲裁只是比较 OCR、ASR、视觉、知识库的置信度，然后选择最高置信证据，属于常规排序或投票。
- 如果仲裁由 LLM 直接判断，审查员会认为本质仍是把上下文再次输入大模型进行自我验证，与 D2 差异不足。

### 当前证据弱点

- 第一轮最终报告把链式校验列为高风险创新点。
- 目前“冲突仲裁”还没有明确的可计算冲突类型，例如数值冲突、时间冲突、主体冲突、因果冲突、模态来源冲突。
- 没有证明仲裁规则与广告视频问答的技术问题有刚性对应关系。

### 如何补强

- 权利要求：限定冲突仲裁的输入和规则，例如针对同一答案声明生成支持证据集与反证证据集；当 OCR 数值与 ASR 数值冲突时，以时间对齐窗口内局部视觉 OCR 节点优先；当画面主体与旁白主体冲突时，以问题槽位指定的证据类型优先；当广告知识条目与原始视频证据冲突时，禁止知识条目覆盖原始证据。
- 说明书：补充冲突类型表、优先级矩阵和仲裁状态机，避免看起来像自然语言判断。
- 代码实验：构造广告视频问答冲突样例集，至少覆盖价格/OCR、旁白/ASR、品牌/logo、因果解释四类冲突，展示仲裁前后答案来源变化。

## C-04 可信证据包约束生成会被打成 RAG 引用来源或结构化提示词

### 攻击结论

- 风险等级：中高。
- 可能结论：相对于 D3 外部知识检索、D4 约束解码、D2 证据链验证显而易见。

### 攻击理由

- 审查员已明确认为：将全局、局部、问题和知识上下文拼接为多模态输入序列供大模型生成，是 D3 基础上的显而易见做法。
- 结构化语义约束和链式生成协议已被审查员归入大语言模型提示词/约束解码常规手段。
- “证据包”如果只是把 evidence ids 放入 prompt 并要求模型引用，会被认为是 RAG 的来源引用。

### 当前证据弱点

- 代码中 `evidence_package.py` 已有 evidence package 雏形，但第一轮报告指出完整视觉证据链未实现。
- 若新申请只依赖现有代码字段，容易被认为是软件工程封装，没有解决明确技术问题。

### 如何补强

- 权利要求：限定证据包的硬约束生成方式。例如答案中的每个原子声明必须绑定至少一个证据节点；未绑定证据节点的声明进入待核查状态并禁止输出；证据包含支持证据、反证证据、来源时间戳、局部区域坐标和知识条目来源。
- 说明书：把“可信”具体化为可校验约束，不写成主观评价。建议定义可信证据包为满足完整性、无冲突或已仲裁、来源可追溯、声明全绑定四个条件的数据结构。
- 代码实验：在 prompt builder 前增加 evidence package validator；对比自由生成、RAG 引用生成、证据包约束生成三种输出中的无证据声明数量。

## C-05 广告视频场景仍可能被认为是应用领域限定

### 攻击结论

- 风险等级：中高。
- 可能结论：把通用视频问答、多模态检索、自验证应用到广告视频领域，对本领域技术人员显而易见。

### 攻击理由

- 第二次审查意见已明确说“广告视频问答方法是视频问答中的具体内容场景应用到广告中”。
- 广告知识库、广告说服策略、情感激发机制、受众画像，如果只作为知识内容，会被认为是业务内容或知识库主题，不是技术特征。
- 若权利要求没有体现广告视频导致的具体技术困难，场景限定很难撑起创造性。

### 当前证据弱点

- 原案意见陈述虽强调广告视频具有诱导性视觉元素和说服性语言，但审查员未接受。
- 新申请若继续强调“广告学专业知识”，会重复落入 D3 通用外部知识库可替换内容的攻击。

### 如何补强

- 权利要求：将广告场景转化为技术约束，例如短时 OCR 数字、品牌 logo、旁白时间偏移、视觉隐喻标签和目标受众标签如何进入证据图谱，而不是只写“广告知识库”。
- 说明书：用广告视频典型失败模式解释技术问题：价格短暂闪现、旁白与画面错位、夸张因果表达、logo 与产品主体分离。
- 代码实验：不要只测通用 VQA；建立广告特有错误集，展示图谱路由和冲突仲裁对这些错误的改善。

## C-06 技术效果不足，容易被认为只是可预期叠加

### 攻击结论

- 风险等级：高。
- 可能结论：即使各模块组合存在差异，也只是已知技术的并列组合，效果是可预期的准确率/可追溯性提升。

### 攻击理由

- 第二次审查意见的核心逻辑是 KSR 式组合：采样、global/local、OCR、RAG、verification、热力图都是已知部件，组合后提高准确率属于预期效果。
- 第一轮最终报告也提示不能无实验地主张“显著提升准确率、显著减少幻觉率、显著降低延迟”。
- “可追溯、可信、减少幻觉”如果没有指标和消融，会被认为只是愿望式效果。

### 当前证据弱点

- 现有材料主要是定性论证。
- 最强视觉特征如协同响应图、自适应锚定当前代码未完整实现；新申请的图谱和仲裁也未见完整实验链。

### 如何补强

- 权利要求：尽量把效果内化为过程约束，例如“未绑定证据的声明不输出”“冲突未仲裁的证据包不进入生成”，减少依赖结果性效果。
- 说明书：提供消融实验设计，即无图谱、仅 RAG、仅自验证、有图谱但无仲裁、完整方案五组对比。
- 代码实验：最小指标包括无证据声明率、冲突声明漏检率、证据引用错误率、需二次核查比例、平均证据节点数量。

## C-07 原始支持与新申请边界风险

### 攻击结论

- 风险等级：中。
- 可能结论：如果作为当前案修改可能超范围；作为新申请则要避免依赖原案未公开内容造成优先权/支持不足问题。

### 攻击理由

- 第一轮结论已指出 evidence package / evidence ID 原始公开支持弱，更适合继续申请/新申请。
- 新申请可以新增内容，但若主张与原案同一发明构思或要求优先权，审查员/代理人会检查原案是否充分公开。
- 如果权利要求中写入代码层字段、ID、package、validator，但说明书没有足够实施例，会被质疑公开不充分。

### 当前证据弱点

- 现有代码实现是后验工程材料，不能自动等同于专利原始公开。
- 新方案中的“证据一致性图谱、问题驱动路由、冲突仲裁”需要完整说明书实施例支撑。

### 如何补强

- 权利要求：新申请可以大胆写工程结构，但要确保说明书同步公开每个模块的数据结构、输入输出和处理规则。
- 说明书：新增系统架构图、证据图谱示意图、冲突仲裁表、证据包格式表、生成约束伪代码和至少两个广告视频实施例。
- 代码实验：把代码作为实施例支撑，而不是仅作为研发记录；需要能跑通从证据抽取到答案生成的闭环。

## C-08 容易被认为是抽象算法或规则，技术性表达不足

### 攻击结论

- 风险等级：中。
- 可能结论：部分特征被认为偏算法规则、信息组织或业务知识处理，没有限定具体技术手段。

### 攻击理由

- “可信”“一致性”“冲突”“路由”都是抽象概念，若不落到视频帧、时间戳、局部区域坐标、OCR/ASR 置信度、边权计算，就缺少技术限定。
- 广告知识维度和目标受众画像容易被认为是认知内容或业务规则。
- 大模型提示词约束若只写输出格式，也容易被认为是非技术的呈现规则。

### 当前证据弱点

- 原案的结构化语义约束已被审查员归入常规提示词/约束解码。
- 新申请若仍以 LLM prompt 为主，会重复该风险。

### 如何补强

- 权利要求：多写机器处理对象和可计算状态，少写主观效果。例如用“时间戳差值、局部区域坐标、归一化响应密度、边权阈值、冲突标签、证据节点绑定状态”替代“可信、准确、专业”。
- 说明书：把 LLM 约束前置为 evidence package validator 和 decoder gate，说明不满足证据约束时系统如何阻断或改写输出。
- 代码实验：证明约束不是提示词口号，而是程序检查生成输入/输出，能稳定拒绝无证据声明。

## 建议的幸存主线

若要提高新申请抗打能力，建议不要把独立权利要求写成“四个模块并列”：证据图谱、问题路由、冲突仲裁、证据包生成。更强的写法是把它们写成一个连续状态机：

1. 从视频帧、局部区域、OCR、ASR、广告知识条目生成证据节点。
2. 基于时间偏移、空间包含、语义相似度和来源派生关系生成一致性边与矛盾边。
3. 将用户问题解析为声明槽位和证据需求向量，在证据图谱中激活候选子图。
4. 对候选子图中的支持证据和反证证据执行冲突仲裁，得到已仲裁证据子图。
5. 由已仲裁证据子图导出可信证据包，要求答案中的每个原子声明绑定证据节点；未绑定或冲突未解决的声明禁止输出或进入补证流程。

这条主线的优点是把“可信生成”从泛泛的大模型自验证，改成可计算、可追溯、可阻断输出的证据状态管理流程。仍需补充检索现有技术和工程实验，否则创造性风险仍为中高。
