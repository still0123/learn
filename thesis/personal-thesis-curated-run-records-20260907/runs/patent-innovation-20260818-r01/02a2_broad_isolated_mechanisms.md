## 1. 证据约束

本地证据给出四项硬约束：

1. 空间定位改善不等于 QA 改善。OCR 将 Region Recall 提高到 `10/10`，但 Confirm-300 QA 未提高；错误或无关 ROI 会干扰抽象问题。见 `docs/创新点一阶段性负结果与论文降级方案.md:42-70`。
2. 时间相关性集中会产生叙事空洞。MMR32 的证据帧精度高于 Raw32，但最大时间空洞明显扩大，独立集 QA 增益不稳定。见 `docs/创新点一时间证据定位最终结论与复现索引.md:23-44`。
3. 现有代码已预留时间窗、OCR、Logo、局部视图和来源置信度，但当前轻量构建器仍主要填充 ASR、元信息和弱先验。见 `code_refactor/evidence/evidence_package.py:9-37,79-98`。
4. 当前闭环已有冻结正结果，但 Full 未稳定超过 MMR，局部裁剪未证明相对同锚点全帧控制的必要性。见 `docs/AdsQA实验结果总表与复现索引.md:4096-4121`。

## 2. 候选机制

### M01 短时文字与 Logo 的“显隐脉冲记忆”

- **failure_id**：`ADV-TRANSIENT-TEXT-01`
- **本地证据路径/行号**：
  - `docs/AdsQA实验结果总表与复现索引.md:199-204`：当时 OCR 只是语义代理，不能声称跨帧文字稳定性已实现。
  - `docs/AdsQA实验结果总表与复现索引.md:459-488`：已有查询条件化缓存 OCR 和严格缓存校验，但仍以帧级响应场参与裁剪。
  - `code_refactor/evidence/evidence_package.py:24-35`：已有 `timestamp`、`time_window`、`ocr_text`、`logo_text` 字段。
- **广告特性**：价格、折扣、品牌 Logo、CTA 和免责声明可能只出现数帧，且常在片尾快速闪现。
- **根因**：按帧取最大响应会把“短但决定性”的证据与“长但无关”的文字混在一起；均匀采样还可能完全跨过短时曝光。
- **核心状态量/数据结构**：`TextPulseTrack`，字段至少包括规范化字符串、字符/Logo 嵌入、起止时间、累计可见时长、最大可读尺度、跨帧一致性、重复次数、所在区域轨迹、首次/末次出现及问题槽位匹配。
- **最小处理链**：低成本密集缩略帧扫描 → OCR/Logo 候选跨帧关联 → 合并为显隐脉冲 → 按问题中的品牌/数值/CTA 槽位召回原分辨率关键帧 → 将脉冲摘要和原帧共同交给一次回答器。
- **为何不依赖现有闭环**：在任何初始答案生成前完成事件化；不需要先检测低支持答案，也不生成 A0/A2 后比较。
- **删除测试**：保持总视觉 Token、回答器和问题不变，仅把 `TextPulseTrack` 替换为相同帧数的逐帧 OCR Top-K；比较短时文字召回、数值/品牌精确匹配和 QA。
- **实现状态**：`PARTIAL_BUILDING_BLOCKS`。OCR 缓存、时间字段和 Logo 字段存在；脉冲生命周期、短曝光补采和轨迹聚合未实现。
- **可验证指标**：按可见时长分桶的文字事件 Recall；品牌/价格 exact match；事件边界误差；每千视觉 Token 的决定性文字召回；对应题型 Strict/Relaxed。
- **申请归类**：`CURRENT_APPLICATION_ENHANCEMENT`。可作为“新增证据”的结构化生成与选择方式，也可抽出从属项。
- **不可声称效果**：不得声称跨帧 OCR 稳定性、短时文字 QA 增益或 Logo 识别增益已经实现；既有 OCR 实验只证明局部定位改善，未证明整体 QA 改善。

### M02 声画时延假设格

- **failure_id**：`ADV-AV-LAG-02`
- **本地证据路径/行号**：
  - `docs/AdsQA实验结果总表与复现索引.md:175-204`：早期 ASR 为视频级整段文本，没有时间戳，声画偏移估计未启用。
  - `docs/AdsQA实验结果总表与复现索引.md:4073-4082`：后续已有 9,481 个带状态的 ASR 句段，可作为实现基础。
  - `evaluation/tools/build_evads_avfunnel_manifest_entropy_v1.py:138-159`：现有时间线把 ASR/OCR 与视觉时间按固定距离衰减匹配。
- **广告特性**：旁白常提前铺垫后续画面，或画面先出现、口播随后解释；配乐高潮也可能滞后于品牌/产品揭示。
- **根因**：固定同刻或单一距离衰减隐含“声画同步”假设，容易把真正相关的跨模态事件拆开。
- **核心状态量/数据结构**：`LagHypothesisLattice`，以视觉事件和 ASR/音频事件为两侧节点，边保存候选时延、方向、相关性、局部峰宽、冲突标记和问题相关槽位。
- **最小处理链**：切分视觉事件与 ASR 句段 → 在有界正负时延窗内计算多峰关联 → 保留若干互斥时延假设 → 依据问题所需动作/属性联合取证 → 一次性回答并输出采用的时延边。
- **为何不依赖现有闭环**：处理对象是声画事件关系，不是答案支持度；回答前已形成跨模态证据边。
- **删除测试**：把所有时延边强制设为零，其他候选事件与 Token 完全相同；比较 speech/audio、产品演示和叙事题。
- **实现状态**：`NOT_IMPLEMENTED`。已有时间戳 ASR 和固定距离匹配代码，但没有多假设时延估计、方向状态或时延消融。
- **可验证指标**：人工声画配对的 lag MAE/Recall；跨模态事件召回；错配边比例；speech/audio 子集 QA；零时延对照下的配对差与置信区间。
- **申请归类**：`NEW_APPLICATION`。核心是时延假设格驱动的前置证据组合，已超出现有补看闭环。
- **不可声称效果**：不得声称已实现声画异步对齐或已提高语音题精度；整段 ASR 代理实验不能支撑该主张。

### M03 重复营销元素的复现拓扑

- **failure_id**：`ADV-RECUR-MOTIF-03`
- **本地证据路径/行号**：
  - `docs/创新点一时间证据定位最终结论与复现索引.md:55-59`：去重复惩罚未造成退化，现有重复抑制不能作为主要贡献。
  - `docs/AdsQA实验结果总表与复现索引.md:897-928`：冻结方案含重复惩罚，但消融显示贡献很小。
  - `code_refactor/evidence/evidence_package.py:55-75`：现有广告证据类型只是关键词弱先验，没有跨时复现结构。
- **广告特性**：Logo、口号、包装、产品 hero shot 和 CTA 会在不同叙事阶段重复出现；重复本身可能表达品牌锚定，而非冗余。
- **根因**：普通去重/MMR 只惩罚相似帧，无法区分“无信息重复”和“跨阶段复现”；因此可能删除广告刻意重复的结构证据。
- **核心状态量/数据结构**：`MotifRecurrenceGraph`，节点为规范化营销元素，出现实例带时间、镜头、区域、模态和叙事阶段；边表示复现间隔、上下文变化及视觉/文本同一性。
- **最小处理链**：检测 Logo/口号/包装/CTA → 跨镜头实体归并 → 建复现图 → 计算“上下文变化后的复现增量” → 每个高价值元素保留首现、转义复现和末次收束实例。
- **为何不依赖现有闭环**：复现图在首次回答前构建；不依据某个答案是否低支持才决定保留重复元素。
- **删除测试**：将复现图退化为普通相似度去重，保持最终帧数一致；比较品牌、主题、CTA 和叙事题。
- **实现状态**：`NOT_IMPLEMENTED`。仅有普通重复惩罚及其负消融，没有元素级跨镜头复现图。
- **可验证指标**：营销元素 track purity；跨阶段复现 Recall；重复帧有效率；品牌/主题/CTA QA；相同预算下的唯一事件覆盖率。
- **申请归类**：`NEW_APPLICATION`。
- **不可声称效果**：不得声称“重复越多证据越强”或现有重复惩罚有效；必须区分同一元素复现与无信息近重复。

### M04 快速镜头的曝光补偿式突发采样

- **failure_id**：`ADV-FASTCUT-BURST-04`
- **本地证据路径/行号**：
  - `docs/创新点一时间证据定位最终结论与复现索引.md:35-44`：相关性选择提高帧精度但扩大最大时间空洞。
  - `docs/创新点一时间证据定位最终结论与复现索引.md:46-59`：覆盖约束有价值，但固定 `3 Raw + 1 evidence` 又损失证据单元。
  - `evaluation/methods/common/qwen_video_budget.py:12-31,71-155`：已有固定视图数、精确 Token 和禁止二次采样的审计基础。
- **广告特性**：广告常在数秒内连续快切，短镜头的语义权重可能高于其时长占比。
- **根因**：均匀采样按时长分配，相关性采样按峰值分配，两者都没有显式补偿短镜头曝光不足。
- **核心状态量/数据结构**：`ShotExposureLedger`，记录镜头边界、时长、切换强度、镜头内语义变化、已分配样本、曝光欠账和跨镜头实体连续性。
- **最小处理链**：低成本镜头切分 → 每镜头至少一个代表视图 → 对短时高变化镜头形成边界前/中/后突发组三帧 → 按曝光欠账回收长静态镜头预算 → 经统一处理器审计后回答。
- **为何不依赖现有闭环**：预算在视频结构解析阶段一次分配，不需要初答或答案风险分数。
- **删除测试**：用相同视图数的 Uniform 和相关性 Top-K 分别替换曝光补偿分配；比较短镜头召回、最大空洞和 QA。
- **实现状态**：`PARTIAL_BUILDING_BLOCKS`。公平 Token 审计、时间覆盖指标和候选帧基础存在；镜头曝光欠账及突发组三帧未实现。
- **可验证指标**：短镜头 Recall；每镜头覆盖率；归一化最大空洞；关键转场事件 Recall；QA/Token；快速剪辑子集配对 Bootstrap。
- **申请归类**：`CURRENT_APPLICATION_ENHANCEMENT`，也适合作为独立证据获取从属机制。
- **不可声称效果**：不得声称更多帧或更高 Token 单调增精；本地 Smoke 已显示增加 Token 不具有单调收益，见 `docs/AdsQA实验结果总表与复现索引.md:3868-3886`。

### M05 产品实体—属性绑定账本

- **failure_id**：`ADV-ATTRIBUTE-BIND-05`
- **本地证据路径/行号**：
  - `code_refactor/evidence/evidence_package.py:18-35`：有全局/局部视图和文字字段，但没有实体、属性及其绑定关系。
  - `code_refactor/reflection/claim_checker.py:18-26`：当前仅按关键词把声明粗分为 OCR、ASR、营销或视觉检查。
  - `docs/AdsQA实验结果总表与复现索引.md:3872-3886`：盲目增加高清整帧或 PiP 证据会放大非决定性区域。
- **广告特性**：颜色、材质、型号、容量、接口、配方、包装版本等细粒度属性常在局部特写中出现，且多个产品/版本会交替剪辑。
- **根因**：局部图只提高可见性，却不保存“该属性属于哪个产品实例、哪个版本、何时成立”，容易发生跨镜头属性串绑。
- **核心状态量/数据结构**：`EntityAttributeLedger`，键为跨镜头产品实体，值为属性槽；每个槽保存候选值、视觉区域、OCR span、时间、来源模态、支持/冲突和身份连续性。
- **最小处理链**：产品候选检测/跟踪 → 跨镜头身份归并 → 局部属性读取 → 属性写入带 provenance 的槽位 → 问题解析为实体和属性键 → 只提交对应槽位原帧及冲突值。
- **为何不依赖现有闭环**：答案由结构化实体—属性状态直接生成；不先产生自然语言初答再验证。
- **删除测试**：打乱同一视频内实体 ID，但保留属性值和帧；若绑定机制有效，属性题应显著退化，而非属性题变化应较小。
- **实现状态**：`NOT_IMPLEMENTED`。局部视图字段存在，实体连续性和属性槽位不存在。
- **可验证指标**：实体 track IDF1；属性抽取 F1；属性串绑错误率；细粒度产品题 exact match；按属性类型分层的 QA/Token。
- **申请归类**：`NEW_APPLICATION`。
- **不可声称效果**：不得把裁剪清晰度或 OCR 字符正确率等同于属性绑定正确率，也不得声称局部裁剪已经提高细粒度产品 QA。

### M06 时间化多模态冲突张量

- **failure_id**：`ADV-MODAL-CONFLICT-06`
- **本地证据路径/行号**：
  - `docs/AdsQA实验结果总表与复现索引.md:429-438`：已有视频/ASR 与标准答案或元信息冲突实例。
  - `docs/AdsQA实验结果总表与复现索引.md:3797-3822`：声明支持分类从 AUROC `0.5409` 提升到 `0.6599`，但 OCR 分层未通过。
  - `evaluation/tools/build_modality_counterfactual_train_v1.py:62-73,141-178`：已有按声明类型选择 ASR/OCR/视觉/联合模态及单因素反事实的基础。
- **广告特性**：旁白、屏幕文字、包装、演示动作和背景元信息可能互相冲突；冲突还可能因“前后版本”而只在局部时段成立。
- **根因**：单一支持分数把模态冲突和证据缺失压成一个标量，无法区分“看见 A、听见 B”“早期 A、片尾 B”与“没有证据”。
- **核心状态量/数据结构**：`ConflictTensor[claim, modality, time_bin]`，单元状态为支持、反驳、缺失、不可判定，并保存强度、来源、时效和冲突边；另有 `ResolutionPolicy` 指定题型所需的优先模态与时间语义。
- **最小处理链**：问题拆为可核查槽位 → 对各模态各时段产生带符号证据 → 构建冲突张量 → 区分同时冲突、时序更新和缺失 → 回答器只使用已解析状态，并显式保留未解析项。
- **为何不依赖现有闭环**：状态张量在回答前构建，核心输出是冲突类型和解析后的事实，不是 A0/A2 的同口径分数。
- **删除测试**：将张量沿模态维求均值退化为单支持分数；比较冲突识别、错误自信和最终 QA。
- **实现状态**：`PARTIAL_BUILDING_BLOCKS`。支持/冲突分类、证据依赖审计和模态反事实已有；时间化四状态张量及冲突解析未实现。
- **可验证指标**：冲突检测 macro-F1；缺失/反驳区分率；冲突题 ECE/Brier；错误自信率；QA；按模态和时序冲突类型分层结果。
- **申请归类**：`CURRENT_APPLICATION_ENHANCEMENT`。可增强声明验证器，也可作为验证器训练方法的新监督结构。
- **不可声称效果**：不得将 `0.6599` 归因于反事实排序或冲突张量；该数值只支撑真实正反声明分类训练，且不是 QA 增益。

### M07 广告叙事阶段图

- **failure_id**：`ADV-NARRATIVE-PHASE-07`
- **本地证据路径/行号**：
  - `docs/创新点一阶段性负结果与论文降级方案.md:66-80`：受众、情绪、叙事策略、隐喻和品牌使命依赖跨时间叙事而非单个 ROI。
  - `code_refactor/data/adsqa_loader.py:9-39`：任务覆盖视觉概念、情绪、主题、说服策略和受众建模。
  - `docs/创新点一时间证据定位最终结论与复现索引.md:35-44`：时间空洞可解释相关帧精度未转化为 QA。
- **广告特性**：广告常包含“情境建立—问题/欲望—产品演示—证明—报价—CTA/品牌收束”等阶段，但不同广告可跳步、回环或交错。
- **根因**：逐帧相关性把视频当作无结构帧集合，容易只看到产品或片尾，却丢失问题、转折和结果，导致主题/受众/情绪推断失真。
- **核心状态量/数据结构**：`NarrativePhaseGraph`，节点为数据驱动阶段事件，边为时间先后、因果、对照、重复收束；节点保存角色、目标、动作、情绪、产品和证据跨度，不强制固定模板齐全。
- **最小处理链**：镜头/ASR 事件切分 → 生成阶段候选 → 以转折词、角色变化、产品揭示和 CTA 信号建图 → 根据问题选择最小连通叙事子图 → 以阶段顺序编码后回答。
- **为何不依赖现有闭环**：直接改变视频表示单位，由“帧”变成“叙事阶段图”；无需初答触发补看。
- **删除测试**：保留相同事件节点但随机打乱阶段边，或仅提交节点 Top-K；比较主题、情绪、策略和受众题。
- **实现状态**：`NOT_IMPLEMENTED`。现有任务类型和时间覆盖可用于评测，但没有叙事阶段识别或图结构。
- **可验证指标**：阶段边界 F1；阶段覆盖率；叙事连通率；Type_2 至 Type_5 QA；长跨度问题的配对增益；阶段打乱敏感性。
