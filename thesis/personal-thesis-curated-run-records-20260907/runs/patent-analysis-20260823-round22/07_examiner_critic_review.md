# P7｜V4.2 敌对审查门禁

日期：2026-08-23  
审查对象：`deliverables/patent/基于增量视频证据与声明依赖闭包的视频问答答案更新控制专利申请候选稿_V4.2_20260823.md`  
结论：**PASS-WITH-FIXES（可作为递交候选稿继续收口；尚非“已通过完整查新、可无条件递交”的法律结论）**。

## 1. 敌对结论

V4.2 已不再是“补证模块 + 验证模块 + 门控模块”的并列拼接。独立权利要求把数据对象连续锁为：

`E0/A0 的必填槽缺口 → 同视频未覆盖位置 ΔE → 冻结 E+ → 非 A0 改写载荷的 A2 → 同 E+ 配对核验 → 声明映射/迁移记录 → ΔE 必要差异见证 → 写入闭包/只读证明上下文 → 原子提交或 E+ 下非陈旧安全状态 → 无新增声明重组`。

该链条针对的是“不同证据口径造成新旧答案不可比、以及整体改写掩盖单条事实变化”的控制问题；各阶段复用 E+、规范化事实槽、迁移记录和闭包状态，不是功能彼此独立的常规集合。

但需承认最危险的组合攻击：D1 `CN121388101A` 可提供视频迭代取证，D2 `CN117744802A` 可提供初答核验/修订，D5 `CN121350217A` 可提供候选评分；旧案 `202610425757.8/CN121962369A` 是同源、同场景的最贴近起点。`CN121147827B`、`CN120804272B`、`CN121029784A`、`CN119782469B` 又分别逼近视频证据链、声明片段冲突处置、候选/来源约束和多轮多模态核验。因此不得把“增量取证”“逐声明证据”“冲突处置”“受限输出”单独作为区别点。答辩和独权均应坚持上面的完整因果链，尤其是 **同 E+ 同核验定义的 A0/A2 配对比较 + 本轮 ΔE 的必要差异见证 + 闭包级非陈旧状态控制**。

## 3. 可立即修正的 P1

以下均不改变主线，建议主控直接改入 V4.2；没有发现必须推翻方案的 P0。

### P1-1：把“未匹配声明”纳入同 E+ 核验，避免新增/撤回没有明示核验对象

**问题**：权利要求1现写“映射至同一规范化事实槽的 A0 原子声明和 A2 原子声明”，文字上未覆盖权利要求3中的“仅 A2 出现的新增”和“仅 A0 出现的撤回”。审查员可据此质疑新增/撤回的状态由何对象、何口径确定。

**建议替换句**（替换权利要求1中“在相同的 E+ … 支持状态”起始句）：

> 在相同的 E+ 和相同的声明核验定义下，分别确定声明映射中每一对已映射 A0 原子声明和 A2 原子声明、以及未匹配 A0 原子声明或未匹配 A2 原子声明的支持状态；对于已映射声明，以共同的规范化事实槽关联其核验结果；

### P1-2：独权中的“预设迁移条件”至少落入状态授权关系，避免提交条件过于结果导向

**问题**：权利要求1将原子提交的关键前提写为“满足预设迁移条件”，而具体迁移条件只在从属权利要求6。这样会弱化独权与“迁移记录—同 E+ 核验”的因果约束，也给清楚性和创造性留下空间。

**建议在权利要求1的“当所述受影响声明闭包内的每一迁移记录均满足预设迁移条件”之后插入**：

> ，所述预设迁移条件至少要求对应候选原子声明在 E+ 下处于支持状态，且对于替换或撤回迁移，所对应旧原子声明在 E+ 下处于冲突状态，或者在旧原子声明处于证据不足状态时，新旧槽值互斥并由 ΔE 正向支持候选槽值，

若希望维持独权更宽，可把上述“替换或撤回”的细化保留在权利要求6，但至少应保留“候选目标状态由 E+ 下支持状态和迁移记录共同授权”的句子。

### P1-3：权利要求9应依附权利要求4，并统一“写入集/证明引用集”来源

**问题**：权利要求9直接依附权利要求1，却使用“状态写入集合”“证明引用集合”。这两个双域集合在权利要求4才明确通过出边/入边构造，依附关系不够紧。

**建议将权利要求9开头改为**：

> **9. 根据权利要求4所述的方法，其特征在于，**当第一受影响声明闭包的状态写入集合与第二受影响声明闭包的证明引用集合……

并在权利要求4末尾补充：

> 所述下游受影响声明构成状态写入集合，所述上游声明构成证明引用集合。

### P1-4：固定“证据不足标识”和“拒答”的选择边界

**问题**：权利要求1写“必填槽无法唯一填充时拒绝回答”，权利要求10又写“输出证据不足标识或拒绝回答”。二者会被认为输出策略尚未确定。

**建议将权利要求10末句改为**：

> 当任一必填语义槽在取证预算耗尽后仍没有对应受支持声明，或者存在多个相互冲突的受支持声明时，在系统输出协议允许结构化不充分结果时输出证据不足标识；在所述输出协议不允许结构化不充分结果时拒绝回答。

并把权利要求1末段的“拒绝回答”改为“按照预设输出协议输出证据不足标识或拒绝回答”。

### P1-5：将“失效声明”改为可判定状态，避免未定义概念

**问题**：权利要求10的“失效声明”不是前序权利要求的明确定义，且可能包含证据不足或冲突两种不同后果。

**建议将权利要求10首句改为**：

> 当处于冲突状态且不存在受支持替代声明的旧原子声明仅对应非必填语义槽时，撤回该旧原子声明并保留其他受支持声明；

### P1-6：使“异常状态”的最终动作闭环

**问题**：权利要求7称异常状态触发安全状态转移，但权利要求1的安全分支只明确旧声明的支持/不足/冲突。正式审查可要求说明异常且预算耗尽时的输出。

**建议在权利要求1“当不写入候选目标状态时”前增加或在权利要求7末尾增加**：

> 当核验为异常状态且取证预算耗尽时，将对应必填语义槽视为不能由受支持声明唯一填充，并按照预设输出协议输出证据不足标识或拒绝回答。

## 4. 非 P0/P1、建议保留的从属保护

1. 权利要求8中“必要差异证据槽仅由 ΔE 覆盖”须与实施方式三的限定一起解释：基础身份槽可由 E0 支持，只有使迁移区别于保持状态的差异槽必须由 ΔE 覆盖。该写法已比“所有证据必须来自 ΔE”合理，不建议删弱。
2. 权利要求13的匹配反事实是较窄但有价值的从属备选；不要上提至独权，以免把验证器训练/反事实实验硬塞入推理主线。
3. 权利要求12的 MMR、OCR/ASR、区域视图均易被 D1 或一般视频处理覆盖，应维持从属，不作为创造性论证中心。
4. V4.2 的示例三已正确说明“满199减100”仅冲突旧的最终价，不能正向支持“最终价99元”；此处应保持。

## 6. 递交前结论

在完成 P1-1 至 P1-6 后，技术文本可冻结为“代理人撰写和形式审查用候选稿”。这不等于授权把握已确认：旧案 `202610425757.8/CN121962369A` 的官方著录、公开范围和有效日，以及覆盖近邻的分类号、同义词和引证链检索，仍是递交前外部必做门禁。若该官方查新出现单篇同时公开“同 E+ 的旧/新答案配对复评、变化槽仅由本轮视频 ΔE 授权、依赖闭包原子提交和非陈旧回退”，则本结论应重新评估。
