# Round 11：主动感知 / 动态裁剪 / 视觉查询规划

## 1. 本轮方向

- 方向名称：主动感知、动态裁剪、视觉查询规划、zoom-in reasoning、tool-use VLM。
- 检索范围：2023-2026 年围绕 VQA/MLLM 的高分辨率视觉问答、视觉搜索、训练-free 裁剪、RL 工具调用、迭代视觉提示和视觉信息检索。
- 目标问题：找到一个不是“给 VLM 加 zoom 工具”的候选专利点，而是能围绕“问题驱动逐步请求局部证据”形成单一技术机制，并能被实验快速验证。

## 3. 热点趋势判断

- 当前领域真正关注的问题：
  - 静态单次图像编码无法可靠处理小目标、远距离文字、图表局部、局部属性、复杂空间关系。
  - 高分辨率图像直接全量输入成本高，盲目 multi-crop 又浪费 token，必须按问题动态获取最小必要视觉证据。
  - VLM 工具调用正在从手工流程转向 RL 学习或内部表示驱动，典型路线包括 tree search zoom、KV/attention 裁剪、GRPO 工具调用、低分辨率到高分辨率自适应获取。
  - 审稿/专利层面已经把“会 zoom 的 VLM”视为明显热点，单纯把 crop/zoom 接到 VQA 后面很容易被判为常规组合。
- 已经成熟、不能作为创新点的部分：
  - 给 VLM 添加裁剪、放大、OCR、检测、搜索工具。
  - 低分辨率先看全图，高分辨率再看局部的 coarse-to-fine 框架。
  - 基于 attention/KV/gradient/object detector 生成相关区域。
  - 通过 RL 奖励正确答案和工具调用，训练模型学会何时 zoom。
  - 多轮“生成坐标-裁剪-再回答”的通用流程。
- 仍有空白或可迁移空间的部分：
  - 多数方法优化“看哪里”或“是否调用工具”，但较少把每次裁剪动作绑定到可验证的“证据缺口”。也就是说，系统为什么必须再看某个区域，现有方法通常只给相关性分数或工具调用概率。
  - 现有 zoom 方法容易产生无约束探索：裁剪可能提升答案，但不能说明某个局部证据是否已经满足回答中某个具体声明。
  - 可以把主动感知和项目既有“声明级证据许可状态机”结合：不是让模型自由 zoom，而是先把问题转成待证明的证据槽，只有当某个槽处于“分辨率不足/局部缺失/冲突待复核”状态时才许可裁剪。
  - 这个机制的技术效果可以直接验证：在相同裁剪预算下，提高困难细节题准确率、降低无效裁剪次数、降低视觉越权回答比例。

## 4. 候选创新点

```text
候选名称：证据缺口驱动的局部裁剪许可状态机
解决的具体技术问题：
现有主动感知 VQA 方法通常根据区域相关性或工具调用概率决定是否裁剪，但缺少“本次裁剪服务于哪个回答证据缺口”的约束，导致无效 zoom、重复 zoom、凭局部弱证据越权回答，尤其在小目标、OCR、细粒度属性、空间关系题中明显。
输入：
原始图像 I、用户问题 Q、基础 VLM 对全图的初步回答 A0、初步证据声明集合 C={c1...cn}、每个声明对应的证据需求槽 E={对象/属性/文字/空间关系/计数/比较}、裁剪预算 B。
核心处理步骤：
1. 将问题 Q 和初步回答 A0 拆成若干待许可声明 ci，并为每个 ci 生成证据需求槽 ei，例如“对象是否存在”“属性是否可分辨”“文本是否完整可读”“两个对象空间关系是否可判定”。
2. 对全图低分辨率视觉编码结果计算每个 ei 的证据满足状态，状态至少包括：已支持、已冲突、分辨率不足、区域未定位、局部遮挡/歧义、跨区域待比较、越权不可判。
3. 只有当 ei 处于分辨率不足、区域未定位、局部遮挡/歧义或跨区域待比较时，状态机才生成裁剪请求；裁剪请求必须携带“证据槽 id + 期望观测谓词 + 区域候选 + 停止条件”，而不是只携带 bbox。
4. 裁剪后重新计算对应 ei 的证据满足状态；若状态从不足转为支持/冲突，则锁定该证据槽，不再允许重复裁剪；若连续 k 次仍不足，则将该声明标记为不可许可并触发降级/拒答。
5. 最终答案只允许引用已支持的声明；冲突声明必须改写或拒绝；不足声明必须降级表达，不能被语言先验补全。
输出：
最终回答 A、每个声明的证据许可状态、每次裁剪的证据槽绑定记录、被阻断或降级的声明列表。
为什么不是简单组合：
核心不在“用 zoom 工具”，而在“裁剪动作的许可条件和停止条件由声明级证据状态驱动”。现有 ZoomEye/FOCUS/ViCrop/DeepEyes 主要解决区域搜索或工具学习，本方案把主动感知动作变成证据状态迁移：只有未满足的证据槽能申请视觉输入，且裁剪结果必须改变该槽状态，否则触发阻断/降级。
可实验数据集：
V* / V*Bench、HR-Bench 4K/8K、TextVQA、DocVQA、ChartQA、MME-RealWorld-Lite、VizWiz、VLR-IF 干扰项集合。
主要风险：
1. “声明拆分”和“证据槽生成”若只靠 prompt，容易被审查员认为是 CoT/self-check。
2. FOCUS 和 ZoomEye 已覆盖动态裁剪，DeepEyes/AdaptVision 已覆盖主动工具调用，需要强调本方案的差异是“裁剪许可状态机”而非“搜索策略”。
3. 若没有状态迁移日志和无效裁剪下降的实验，技术效果不够硬。
```

```text
候选名称：反事实遮罩驱动的必要裁剪选择
解决的具体技术问题：
VLM 可能知道相关区域但不知道是否真的需要高分辨率局部证据；裁剪选择容易被 attention 偏差带跑。
输入：
图像 I、问题 Q、候选区域 R={r1...rm}、基础回答分布或答案置信度。
核心处理步骤：
1. 对每个候选区域执行遮罩/模糊/低分辨率替换，观察答案稳定性变化。
2. 将答案变化最大的区域视为“必要证据区”，优先申请高分辨率裁剪。
3. 裁剪后若答案仍不稳定，则继续搜索互补区域或输出证据不足。
输出：
必要证据区域、裁剪后回答、答案稳定性变化记录。
为什么不是简单组合：
不是用 attention 直接找区域，而是用视觉反事实扰动判断“缺失该区域是否会改变答案”。
可实验数据集：
V*、TextVQA、MME-RealWorld、POPE 幻觉样本。
主要风险：
反事实遮罩和 saliency/occlusion sensitivity 是成熟技术；若仅用于裁剪选择，创造性偏弱。
```

```text
候选名称：跨区域比较题的双裁剪同步许可机制
解决的具体技术问题：
比较类问题需要两个或多个局部证据同时满足，单点 zoom 容易只看其中一处就越权回答。
输入：
图像 I、比较型问题 Q、候选对象/区域集合、裁剪预算。
核心处理步骤：
1. 识别问题中的比较谓词，例如更大、更近、颜色是否相同、数量谁多。
2. 为比较双方分别建立证据槽，并要求双方状态均达到“可比较”才允许输出比较结论。
3. 若一方可见一方不可见，则继续请求不可见方裁剪；若预算耗尽则输出无法比较。
输出：
比较结论、双方证据槽状态、比较许可/拒绝原因。
为什么不是简单组合：
强调比较关系的“双侧证据齐备”许可，而不是普通多区域裁剪。
可实验数据集：
V* spatial split、GQA、NLVR2、多图/单图比较题子集。
主要风险：
覆盖面较窄；容易被认为是候选 1 的子机制。
```

## 5. 模拟审查员攻击

- 是否只是应用场景替换？
  - 对候选 1：不是单纯把主动感知换到 VQA 场景，因为它定义了“证据槽状态-裁剪许可-状态迁移-声明降级”的闭环规则。风险在于需要把状态集合和迁移条件写得足够算法化，否则仍会被认为是抽象规则。
  - 对候选 2：风险较高，occlusion sensitivity/反事实遮罩已是常见解释方法，迁移到裁剪选择可能被认为是直接应用。
  - 对候选 3：有一定场景特化，比较题双侧证据许可有用，但范围偏窄。
- 是否只是 RAG / CoT / self-check / 置信度阈值？
  - 候选 1 的关键防线：裁剪许可不由语言自检或置信度阈值触发，而由具体证据槽状态触发；每次裁剪必须带有目标谓词和停止条件，并更新声明许可状态。
  - 若实现中只是让模型说“我需要看这个区域”，会被打成 CoT/tool-use prompt。必须落到结构化状态字段、状态转移和裁剪预算消耗规则。
  - 候选 2 如果只看答案置信度变化，容易被认为是置信度/敏感性阈值。
- 是否只是现有 grounding / VQA / OCR / 图表解析方法组合？
  - 候选 1 可以使用 grounding/OCR/VQA 作为观测器，但独立技术动作是“证据槽未许可时才允许主动感知，并以状态迁移约束最终声明输出”。它不依赖特定 OCR 或 grounding 模型。
  - 审查员会引用 ZoomEye、FOCUS、ViCrop、DeepEyes、AdaptVision 指出现有技术已经有裁剪、区域搜索、工具调用和 RL。因此权利要求不能写成“根据问题裁剪图像再回答”，必须写成“按证据需求槽生成裁剪许可请求并根据观测结果迁移许可状态”。
- 是否能被一篇或几篇论文自然组合推出？
  - 最强组合攻击：ZoomEye 的树搜索 + FOCUS 的内部相关性区域 + DeepEyes 的主动 zoom + AVIS 的状态转移图。审查员会说，把这些组合起来就能得到动态裁剪 VQA。
  - 反驳点：上述组合仍主要解决“区域选择/工具选择”，没有将“回答声明是否允许输出”作为视觉查询的前置条件和后置约束。候选 1 的非显而易见性要落在“声明级证据槽驱动视觉采样，而不是视觉采样辅助回答”。
  - 还可以强调技术效果：在固定裁剪预算下减少无效裁剪和越权声明，而非仅提升准确率。
- 是否缺少可验证技术效果？
  - 候选 1 可验证：平均裁剪次数、无效裁剪率、证据不足拒答准确率、答案准确率、声明级 hallucination rate、同预算下 VQA accuracy。
  - 最快实验：Qwen2-VL/LLaVA-OneVision 上实现 prompt/规则版状态机，对 V*、TextVQA、VizWiz、VLR-IF 采样 200-500 题，与 baseline、随机裁剪、ZoomEye/ViCrop 类策略对比。
  - 风险：如果只提升少量准确率但增加耗时，价值不足；应重点报告“无效裁剪下降”和“视觉越权回答下降”。

## 6. 本轮最佳候选

本轮只保留：**证据缺口驱动的局部裁剪许可状态机**。

- 为什么选它：
  - 它与当前项目主线“声明级证据许可状态机”一致，能把主动感知从“看哪里”提升为“哪个声明缺哪类证据，因此是否允许继续看”。
  - 它避开了 ZoomEye/FOCUS/ViCrop/DeepEyes 已经拥挤的核心点：不主张发明裁剪、区域搜索或 RL 工具调用，而是主张裁剪请求的生成、执行、停止和最终回答许可由证据槽状态统一控制。
  - 它可实验，且不要求训练大模型。先用规则/prompt 生成声明和证据槽，再调用现成 VLM 对全图/裁剪图打状态即可跑小规模验证。
- 为什么淘汰其他候选：
  - 反事实遮罩驱动必要裁剪：技术直觉强，但 saliency、遮罩敏感性、反事实干预已有大量先例，专利创造性不稳。
  - 双裁剪同步许可机制：适合比较题，但覆盖面太窄，更适合作为最佳候选中的一个状态类型“跨区域待比较”，不应单独成主案。
- 如果写专利，独立权利要求应该抓住哪个技术动作：
  - 抓住“根据问题和初步回答生成声明级证据需求槽；根据每个证据需求槽的满足状态生成带有证据槽标识和期望观测谓词的局部裁剪请求；根据裁剪观测结果迁移该证据需求槽的许可状态；仅输出许可状态满足预设条件的回答声明”。
  - 关键限定不要写泛泛的“调用裁剪工具”，而要写：裁剪请求必须绑定证据槽；裁剪后必须更新状态；未迁移到支持/冲突的槽在预算耗尽后触发降级或阻断。
- 如果做实验，最快怎么证明：
  - 数据：V* 100-200 题、TextVQA 100-200 题、VizWiz 100-200 题、VLR-IF 干扰题 100-200 题。
  - Baseline：直接 VLM；固定中心/网格裁剪；问题相关性裁剪；ZoomEye/ViCrop 类训练-free 裁剪；候选 1 状态机。
  - 指标：Accuracy、平均裁剪次数、无效裁剪率、证据不足拒答 F1、声明级 hallucination rate、同裁剪预算下的正确率。
  - 预期最硬结果：在相同最多 2 次裁剪预算下，候选 1 不一定显著超过最强裁剪方法的总 accuracy，但应显著降低无效裁剪和越权回答；这更贴合专利的技术效果表述。
