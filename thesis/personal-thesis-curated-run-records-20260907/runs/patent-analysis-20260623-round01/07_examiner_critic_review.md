## C-01 针对 I-01（三模态协同响应图与声画异步滑动窗口）

### 1. 攻击结论

- 结论：**修改后通过**

### 2. 攻击理由

- 可被视为常规手段的部分：跨模态对齐、滑动窗口、热力图/响应图本身。
- 可被对比文件组合得到的部分：D3 的图文对齐 + D4 的跨模态同步 + D5 的热力图思路，似乎都能提供启示。
- 可被认为是业务规则或场景限定的部分：若只强调“用于广告视频”，容易被看作应用场景切换。

### 3. 当前证据弱点

- 原始公开弱点：虽然有“三流特征提取”，但仍需要更明确强调三者共同约束同一响应图。
- 对比文件差异弱点：尚缺对 D3/D4/D5 的逐段差异证据。
- 技术效果弱点：目前更多是定性效果，缺少实验量化。
- 代码实现弱点：当前代码无真实响应图实现。

### 4. 如何补强

- 权利要求限定建议：把“问题语义 + ASR 语义 + OCR 语义 + 时序滑动窗口 + 加权融合”写成连续技术步骤。
- 说明书/意见陈述补强建议：强调广告视频中的“短时文字/Logo + 声画异步”是该组合出现的技术动机。
- 代码或实验补强建议：后续补一版原型或消融实验规划，而不是直接许诺已有结果。

### 5. 是否幸存

- 结论：修改后通过
- 理由：这是当前最像“有耦合机制”的主创新点，但必须避免写成“跨模态对齐 + 热力图”的常规堆叠。

## C-02 针对 I-02（响应密度驱动自适应锚定与双流视觉表征）

### 1. 攻击结论

- 结论：**修改后通过**

### 2. 攻击理由

- 可被视为常规手段的部分：全局/局部双流、ROI、局部裁剪。
- 可被对比文件组合得到的部分：D3 的 global/local + D5 的局部关注区域。
- 可被认为是业务规则或场景限定的部分：如果只说“用于广告视频更需要细节”，不足以支撑创造性。

### 3. 当前证据弱点

- 原始公开弱点：需要更突出“语义重心 + 多尺度候选锚框 + 归一化响应密度”而不是“局部区域”。
- 对比文件差异弱点：尚未充分证明 D3 的 ROI 与本申请的自适应锚定不同。
- 技术效果弱点：缺少对“不是简单 token 压缩”的控制表述。
- 代码实现弱点：当前代码中无真实 anchor/crop 算法。

### 4. 如何补强

- 权利要求限定建议：把最佳局部区域的确定依据写成数学或步骤约束，而不是泛泛说“局部精细视角”。
- 说明书/意见陈述补强建议：强调该特征解决的是“保留高信息密度局部证据且不丢全局语境”。
- 代码或实验补强建议：后续增加一个简化版局部锚定实验设计。

### 5. 是否幸存

- 结论：修改后通过
- 理由：如果坚持“自适应锚定链条”，其说服力高于单纯“双流视觉表征”。

## C-03 针对 I-03（证据约束的广告知识检索）

### 1. 攻击结论

- 结论：**需谨慎，作为从属/辅助特征更合适**

### 2. 攻击理由

- 可被视为常规手段的部分：RAG、Top-K 检索、外部知识库增强。
- 可被对比文件组合得到的部分：D3 已足以吸收大部分“外部知识库 + 上下文注入”表述。
- 可被认为是业务规则或场景限定的部分：广告说服策略、受众画像可能被说成业务知识，不一定是技术手段。

### 3. 当前证据弱点

- 原始公开弱点：虽然写了多维广告宣传知识库，但“证据约束”这个强表述需要更谨慎地从文本中抽出。
- 对比文件差异弱点：缺少对 D3 检索查询构造差异的明确论证。
- 技术效果弱点：容易被质疑只是让答案“更专业”，而不是技术效果。
- 代码实现弱点：已有 evidence_score，但还是较轻量。

### 4. 如何补强

- 权利要求限定建议：不要单独主打“RAG”，而写成“基于问题与双流视觉证据提取语义关键词并检索广告专业知识条目”。
- 说明书/意见陈述补强建议：强调其作用是减少与当前视频证据无关的知识注入。
- 代码或实验补强建议：后续设计“question-only RAG vs evidence-constrained retrieval”的对比实验。

### 5. 是否幸存

- 结论：修改后通过
- 理由：只能作为证据流闭环的中间环节，不能单独承担创造性。

## C-04 针对 I-04（触发式多模态证据回溯链式校验）

### 1. 攻击结论

- 结论：**高风险，需修改后使用**

### 2. 攻击理由

- 可被视为常规手段的部分：自我验证、触发条件、反馈令牌。
- 可被对比文件组合得到的部分：D2 基本已经提供“验证问题 → 比对 → 修正”的框架。
- 可被认为是业务规则或场景限定的部分：如果高风险关键词只是手工配置词表，容易被视为规则工程。

### 3. 当前证据弱点

- 原始公开弱点：虽然专利文本写得很全，但仍容易被审查员归并为 D2 的推广应用。
- 对比文件差异弱点：需要更强证明“回溯多模态原始证据”与“纯文本验证上下文”有本质差异。
- 技术效果弱点：缺少能证明触发式设计必要性的外部支持。
- 代码实现弱点：只有 claim type 路由雏形，没有完整 verifier loop。

### 4. 如何补强

- 权利要求限定建议：收紧到“针对文本细节/逻辑因果/语音内容三类高风险声明的多模态证据回溯校验”。
- 说明书/意见陈述补强建议：弱化“链式反思”字眼，改强调“声明级证据核查”。
- 代码或实验补强建议：后续增加声明类型与证据类型映射案例。

### 5. 是否幸存

- 结论：需代理人复核
- 理由：当前最容易被 D2 吸收，需要非常谨慎地限定表述。
