## I-01：三模态协同响应图与声画异步滑动窗口

### 技术机制

- 核心步骤：
  1. 以用户问题、ASR 文本、OCR/Logo 关键词分别生成语义向量；
  2. 将三类语义向量与关键帧视觉特征做跨模态交互；
  3. 通过时序滑动窗口对 ASR 与关键帧做局部时间对齐；
  4. 加权融合形成视听-文字综合响应图。
- 输入：关键帧序列、对齐后的 ASR、OCR/Logo 关键词、用户问题。
- 输出：可用于后续锚定和裁剪的综合响应图。
- 与现有流程的连接点：这是“证据定位”阶段的核心机制。

### 为什么不是模块拼接

- 不是简单把 OCR、ASR、视觉和问题并列拼接，而是要求三类文本信号共同约束同一张响应图。
- 关键耦合关系：ASR 的时间窗口决定候选语义上下文，OCR/Logo 决定细粒度文字显著性，问题语义决定定位方向。
- 解决的广告视频特有技术问题：广告视频中声画异步、瞬时文字/Logo、说服性旁白与画面并不同步出现。

| 视听-文字协同响应图 | `source_texts/patent_docx.txt` | 摘要与 S2 中“三流特征提取”“视听-文字综合响应图” | 强 |
| 声画异步滑动窗口 | `source_texts/patent_docx.txt` | 摘要、发明内容第一点中“时序滑动窗口”“解决声画异步” | 强 |
| OCR 语义增强 | `source_texts/patent_docx.txt` | S21 关于 OCR 语义向量和关键词集合 | 强 |

| D2 | 否 | D2 关注文本自验证，不涉及证据定位 | 低 |

### 技术效果

- 可合理主张的技术效果：提升广告视频中短时文字、Logo、旁白与视觉证据的联合定位能力；降低因声画异步造成的证据错配风险。
- 不能主张或需实验补充的效果：显著提升准确率、显著减少 token、显著降低延迟。

- 新增内容风险：低。

### 代码实现依据和难度

- 现有代码支撑：`evidence_package.py` 中已有 ASR/OCR/logo/global/local 字段，可作为工程落点。
- 需要新增实现：真实响应图、三模态向量计算、滑动窗口融合。
- 难度：高。
- 主要风险：当前更多是专利/论文设计，未见完整可运行视觉算法实现。

### 模拟审查员攻击预测

- 可能攻击点：跨模态对齐、滑动窗口、热力图/响应图本身都是常见手段；另外，`TVQA` 一类工作已覆盖“局部时序证据定位 + 字幕/视觉联合推理”的宽泛表述。
- 反制证据：不是单一对齐或单一热力图，而是“问题 + ASR + OCR/Logo”三源协同和广告视频声画异步的针对性设计。

## I-02：响应密度驱动的自适应锚定与双流视觉表征

### 技术机制

- 核心步骤：
  1. 根据综合响应图计算语义重心；
  2. 以语义重心为中心生成多尺度候选锚框；
  3. 对候选框计算归一化响应密度；
  4. 选择得分最高的局部区域，与全局帧共同构成双流视觉表征。
- 输入：综合响应图、原始关键帧、多尺度候选参数。
- 输出：全局上下文 + 局部精细视角的双流视觉输入。
- 与现有流程的连接点：这是“证据压缩”阶段的核心机制。

### 为什么不是模块拼接

- 不是普通 ROI 裁剪，因为锚框不是预定义，而是由语义重心和响应密度共同自适应生成。
- 关键耦合关系：响应图决定语义重心，多尺度候选框决定局部观察粒度，归一化响应密度决定最终局部证据区域。
- 解决的广告视频特有技术问题：广告中的品牌标识、价格数字、短时字幕等往往是全局视角看不清但局部视角极关键的证据。

### 原始公开支持

| 支持点 | 本地来源路径 | 摘录/章节 | 支撑强度 |
|---|---|---|---|
| 响应密度指标与多尺度锚框 | `source_texts/patent_docx.txt` | 公式说明与 S2 对锚框优选的描述 | 强 |
| 全局 + 局部双流视觉表征 | `source_texts/patent_docx.txt` | 摘要、S2、发明内容第一点 | 强 |

### 相对对比文件的差异

| 对比文件 | 是否公开 | 差异说明 | 风险 |
|---|---|---|---|
| D1 | 部分 | D1 有候选区域/关键帧，但无响应密度 + 语义重心 + 多尺度优选链条 | 中 |
| D2 | 否 | D2 不涉及视觉证据提取 | 低 |
| D3 | 部分 | D3 有 global/local + ROI，但更像静态图像 ROI，不是自适应锚定 | 中 |
| D4 | 否 | D4 不足以公开该锚定逻辑 | 低 |
| D5 | 部分 | D5 有热力图关注区域，但不等于响应密度自适应锚定 | 中 |

### 技术效果

- 可合理主张的技术效果：在保留全局语境的同时，更稳定地保留局部高信息密度证据（如短时字幕、Logo、价格标签）。
- 不能主张或需实验补充的效果：明确的 token 压缩比例、检测提升百分比。

### 权利要求修改路径

- 适合写入独立权利要求：是（与 I-01 联动时更强）。
- 适合写入从属权利要求：是。
- 推荐限定语：基于语义重心定位、多尺度候选锚框和归一化响应密度筛选生成局部精细视角。
- 新增内容风险：低。

### 代码实现依据和难度

- 现有代码支撑：`evidence_package.py` 中已有 `global_view` 和 `local_high_resolution_evidence_view` 字段。
- 需要新增实现：真正的语义重心、候选锚框和局部裁剪流程。
- 难度：高。
- 主要风险：如果没有实验和视觉模块实现，容易被质疑成设计性特征。

### 模拟审查员攻击预测

- 可能攻击点：全局/局部双流和 ROI 提取在 D3/D5 中已有思路。
- 反制证据：我方不是普通 ROI，而是“语义重心 + 多尺度 + 响应密度”的自适应锚定链条。
- 仍需补强：需要更明确地区分普通 ROI 与自适应锚定的技术效果差异。

## I-03：证据约束的广告知识检索

### 技术机制

- 核心步骤：
  1. 从问题和双流视觉表征中提取关键词/语义标签；
  2. 在多维广告知识库中检索最相关条目；
  3. 仅将与当前视频证据匹配的知识条目作为专家上下文注入模型。
- 输入：问题、双流视觉表征、广告知识库。
- 输出：带有证据关联的专家上下文。
- 与现有流程的连接点：属于“证据解释”。

### 为什么不是模块拼接

- 不是把 RAG 贴到后面，而是要求知识检索由“视频证据 + 问题”共同驱动。
- 关键耦合关系：视觉标签与广告知识维度共同决定知识注入，不是 question-only 检索。
- 解决的广告视频特有技术问题：通用模型不理解营销策略、视觉隐喻和受众画像，容易把广告解释成普通事实问答。

### 原始公开支持

| 由问题与视频内容关键词共同驱动检索 | `source_texts/patent_docx.txt` | S32 | 强 |
| 过滤噪声知识并保留高置信上下文 | `source_texts/patent_docx.txt` | S33 | 中 |

| D2 | 否 | D2 为文本自验证 | 低 |
| D3 | 部分 | D3 有外部知识库检索，但不是广告领域多维知识，也未强调 evidence-constrained 检索 | 中高 |

- 可合理主张的技术效果：减少与当前视频证据不相关的营销知识注入；增强广告学维度解释能力。

- 适合写入从属权利要求：是。
- 推荐限定语：检索查询同时来自问题和双流视觉证据，知识条目需经匹配和重排序。

## I-04：触发式多模态证据回溯链式校验

### 技术机制

- 核心步骤：
  1. 检测高风险触发关键词；
  2. 仅在高风险问题下启动核查；
  3. 保持模型参数冻结，输入问题、初始答案和双流视觉表征；
  4. 回溯关键帧与对齐语音等多模态证据；
  5. 输出确认令牌或修正令牌完成迭代优化。
- 输入：问题、初始答案、双流视觉表征、关键帧与语音证据。
- 输出：保留或修正后的最终答案。
- 与现有流程的连接点：这是“证据校验”阶段核心机制。

### 为什么不是模块拼接

- 不是一般自我反思，因为这里有触发式启动、多模态证据回溯、参数冻结和结构化反馈四个绑定条件。
- 关键耦合关系：只有当问题命中高风险类型时才回查原始多模态证据，而不是让模型泛泛再想一遍。
- 解决的广告视频特有技术问题：涉及价格、逻辑归因、语音内容时，模型更容易被广告中的诱导性元素误导。

### 原始公开支持

| 确认令牌 / 修正令牌 | `source_texts/patent_docx.txt` | S53 | 强 |

## I-05：evidence package / evidence ID 可追溯闭环

### 技术机制

- 核心步骤：
  1. 将视觉、ASR、OCR、Logo、知识条目统一写入 evidence package；
  2. 在检索和回答时保留 evidence id；

- 输出：可追溯的中间状态与答案来源链。
