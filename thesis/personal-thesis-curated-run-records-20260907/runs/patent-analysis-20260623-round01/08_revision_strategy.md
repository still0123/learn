# P7 修改与答复策略

## 独立权利要求修改建议

当前最值得保留并强化的主线，不是继续泛化地强调“RAG + CoT + Reflection”，而是把独立权利要求的逻辑收束为：

```text
证据定位 → 证据压缩 → 证据解释 → 证据校验
```

建议在独立权利要求的论证或后续修改中，优先突出以下连续链条：

1. **问题语义 + ASR 语义 + OCR/Logo 语义共同生成响应图**；
2. **针对广告视频声画异步，采用时序滑动窗口与加权融合**；
3. **基于语义重心、多尺度候选锚框和归一化响应密度生成局部精细视角**；
4. **将局部精细视角与全局上下文共同组成双流视觉表征**；
5. **在此基础上再进行广告专业知识检索与结构化推理**；
6. **必要时对高风险声明进行多模态证据回溯校验**。

换言之，应把“证据定位与自适应锚定”置于主线前部，把“广告知识检索”和“链式校验”降为依附于主线的后续环节。

## 从属权利要求布局

### 可优先放入从属权利要求的内容

1. **广告知识检索的限定**
   - 检索查询同时来自用户问题和双流视觉表征；
   - 知识库至少包含广告说服策略、情感激发机制、视觉隐喻映射、目标受众画像特征；
   - 对检索结果进行重排序和噪声过滤。

2. **链式校验的限定**
   - 仅在命中高风险触发条件时启动；
   - 高风险触发条件至少包括文本细节、逻辑因果、语音内容三类；
   - 回溯关键帧与对齐后的语音文本等多模态证据；
   - 输出确认令牌或修正令牌。

3. **结构化语义约束的限定**
   - “观察—分析—推理—答案”协议；
   - 动作细化约束；
   - 情感效价量化约束；
   - 视觉文本锚定约束。

### 可进一步拆分的从属方向

- 三模态响应图的构建方式；
- 声画异步的时间窗口策略；
- 多尺度锚框与响应密度计算方式；
- 高风险声明分类与证据回溯对应关系。

## 推荐意见陈述论证顺序

### 1. 先承认审查员拆解路径成立的“外观”，但指出其忽略了连续耦合机制

建议表述方向：

- 审查员把本申请拆成了通用视频问答、全局/局部、RAG、自验证、热力图等模块；
- 但本申请的技术贡献不在于单个模块，而在于面向广告视频高信息密度与声画异步问题，把这些步骤组织成了连续的证据流闭环；
- 该闭环的核心在于三模态协同响应与自适应锚定，而不是一般的视频问答框架。

### 2. 把最强区别点集中到“证据定位 + 证据压缩”

建议先打：

- 三模态协同响应图；
- 声画异步滑动窗口；
- 语义重心 + 多尺度候选锚框 + 响应密度；
- 全局/局部双流视觉表征。

这些点比“RAG”“CoT”“链式反思”更像真正的技术机制。

### 3. 再把广告知识检索解释为“证据约束解释层”，而不是单独的 RAG 模块

建议避免：

- “引入 RAG 增强广告知识”；
- “通过外部知识库提升专业性”。

建议改写为：

- 仅在问题与双流视觉证据共同确定的语义上下文中检索广告知识；
- 广告知识只是对证据进行专业解释，而不是替代视频证据。

### 4. 最后谨慎使用链式校验作为补强，而非唯一创新主轴

当前链式校验最容易被 D2 吸收。因此：

- 不应把“链式校验”单独立为主创新点；
- 更适合强调“高风险声明触发 + 多模态证据回溯”的专用核查机制；
- 应避免空泛的“自我反思减少幻觉”表述。

## 不建议主张的内容

1. 不建议把“RAG”本身作为主要创造性来源。
2. 不建议把“结构化 CoT/观察-分析-推理-答案”单独主张为核心创新。
3. 不建议把 `evidence package / evidence ID` 作为当前答复的主打特征，因为原始公开支持不足。
4. 不建议主张任何未经实验支持的准确率、token、延迟收益。
5. 不建议作出“必然授权”或“显然不属于现有技术组合”的确定性法律判断。

## 新增内容风险

### 低风险

- 三模态协同响应图；
- 声画异步滑动窗口；
- 响应密度与多尺度锚定；
- 广告知识库的多维结构；
- 高风险触发关键词与确认/修正令牌。

### 中风险

- 将“证据约束检索”表述得过强时，需确保能在原文中找到对应支撑。
- 将“声明级证据回溯”写得过细时，需避免超出原始公开。

### 高风险

- evidence ID 全链路追踪；
- 明确的软件架构层/中间表示层设计；
- 任何代码实现细节若在原说明书中未明确写出，不宜写入当前权利要求。

## 代理人复核事项

1. 当前是否需要对独立权利要求1作进一步限缩，以突出“协同响应图 + 自适应锚定”主线。
2. “证据约束检索”和“声明级证据回溯”哪些表述已被原始公开充分支撑，哪些更适合转入从属权利要求或继续申请。
3. 链式校验部分是否需要主动降格为从属或次级特征，以降低被 D2 直接覆盖的风险。
4. 是否应准备一套新的分案/继续申请主题，围绕 evidence package / evidence ID 可追溯闭环做系统工程布局。
