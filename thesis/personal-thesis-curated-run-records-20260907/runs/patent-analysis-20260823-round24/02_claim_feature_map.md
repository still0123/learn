# 02｜V4.4 候选特征图

| 编号 | 候选特征 | 在单一控制链中的作用 |
|---|---|---|
| H1 | 由问题和任务规则确定带值类型、限定字段、槽基数和允许模态的事实槽模式 | 规定可观测的机器状态和冲突判定边界 |
| H2 | 从同一视频取得 ΔE，并固定 E+ 快照 | 给本轮观测确定来源和版本 |
| H3 | 从 ΔE 抽取 `(主体, 谓词, 值, 单位, 限定字段)` 及视频时空/区域/模态来源 | 把“覆盖了槽”变成“实际观测到具体事实” |
| H4 | 按上下文和槽基数建立竞争组，输出 RESOLVED/AMBIGUOUS/INSUFFICIENT/QUALITY_ONLY | 阻止清晰但冲突或无具体值的证据授予写入权限 |
| H5 | 在 A2 前冻结观测记录，形成过程不以 A0/A2 候选值为检索、抽取或选证目标 | 防止候选生成后反向挑证据 |
| H6 | A2 不接收 A0 语义内容作为改写输入 | 区别旧案和 D2 的初答回输改写 |
| H7 | A0/A2 在同一 E+ 和配置下规范化、映射、复评 | 形成可比较的新旧事实迁移 |
| H8 | 实质迁移必须在槽、上下文和值上匹配 RESOLVED 观测，并绑定该记录的 ΔE 见证 | 核心事实写入许可 |
| H9 | 不匹配、竞争或快照失效时禁止候选状态写入，并输出 E+ 下安全状态 | 直接阻断错误状态污染 |
| H10 | 获许可迁移按依赖闭包暂存并全量提交（强从属） | 防止相关事实部分更新 |

## 发明中心

发明中心不是 H1、事实抽取、证据映射或事务提交本身，而是 `H3→H4→H5→H8→H9`：在候选答案存在前冻结的具体视频事实观测，后来成为同一事实状态能否写入的必要许可。
