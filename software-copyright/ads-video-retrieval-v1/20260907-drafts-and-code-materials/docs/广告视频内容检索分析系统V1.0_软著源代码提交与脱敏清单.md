# 广告视频内容检索分析系统V1.0 软著源代码提交与脱敏清单

## 1. 文档说明

本文档用于整理广告视频内容检索分析系统V1.0 的软件著作权源代码提交建议、代码模块映射、可提交文件范围、不建议提交内容以及提交前脱敏检查事项。

本软件当前代码主要位于：

```text
${PROJECT_DIR}/ad_video_analysis_system
${PROJECT_DIR}/code_refactor
${PROJECT_DIR}/rag_mvp
${PROJECT_DIR}/代码
```

其中，`ad_video_analysis_system` 目录是当前软著系统的完整运行主体，包含 Flask 后端、SQLite 存储、前端界面、素材管理、内容预处理、语义检索、问答分析和历史记录管理等代码；`code_refactor` 目录可作为算法流程和论文实验代码补充；`rag_mvp` 可作为早期原型或补充代码；`代码` 目录多为论文实验和多模型推理脚本，不建议整体作为软著核心源码提交。

## 2. 推荐提交主体

建议以以下目录作为软著核心代码主体：

```text
${PROJECT_DIR}/ad_video_analysis_system
```

该目录结构较清晰，包含 Web 服务入口、SQLite 持久化、素材登记、证据包构建、广告知识检索、问答分析、历史记录和前端界面等模块，能直接运行并对应软件著作权说明书中的用户操作页面。`code_refactor` 中的数据读取、证据包构建、知识检索、提示生成和声明校验代码可纳入代码材料后半部分，用于体现论文、专利和系统算法之间的衔接。

## 5. 可作为补充材料的代码

以下文件可以作为研发过程或功能补充材料，但不建议作为核心源码主体：

```text
rag_mvp/rag_retriever.py
代码/inference.py
代码/eval_adqa.py
代码/eval_adQA_qwen2d5-7b_v2.py
代码/eval_qwen2vl_fix.py
代码/eval_qwen3.py
代码/eval_minicpm_fix.py
代码/eval_llavavision.py
```

原因如下：

1. 这些文件实验脚本痕迹较重；
2. 部分脚本依赖第三方模型权重；
3. 部分脚本可能包含绝对路径或服务器环境信息；
4. 部分脚本主要用于论文实验，不适合作为软件系统主体代码；
5. 部分脚本调用外部开源模型，应避免让材料看起来将第三方模型作为自研软件提交。

如需补充代码页数，可在完成路径脱敏和依赖边界说明后，选取其中较能体现自研流程编排的片段作为补充。

```text

```

原因：这些属于实验数据或第三方数据集相关文件，不是程序源代码。


原因：这些属于内容资源或知识条目数据，不是核心程序代码。如需展示，可使用少量脱敏样例或字段格式说明。


原因：索引文件属于程序运行生成的中间结果，可由代码重新生成。

### 6.4 输出结果文件

```text

```

原因：输出结果、运行摘要、预测文件和样例结果不属于源代码。

### 6.5 测试文件


原因：测试代码可作为内部研发证明，但通常不作为软著核心源码主体。若源码页数不足，可视情况少量保留。

### 6.6 日志、失败列表和临时文件

```text

*.log
*.tmp
```

原因：这些文件不属于软件核心源代码，且可能包含运行环境信息。

## 7. 第三方模型和依赖边界

```text

LLaVA-OneVision
CLIP
sentence-transformers
BAAI/bge-m3
```

建议写：

> 本软件支持调用第三方或开源多模态模型作为推理底座，软件自研部分主要包括广告视频问答数据适配、多源证据组织、广告营销知识检索、结构化提示生成、推理流程编排、答案声明校验计划和结果统计等程序代码。

不建议写：

> 本软件自主研发多模态大模型。

## 8. 提交前脱敏检查清单

提交软著源代码前，建议逐项检查并处理以下内容：

### 8.1 路径脱敏

检查是否存在：

```text
${USER_HOME}/...
${DATA_DIR}/...
user@<internal-ip>...
${HOME}/...
/private/...
```

建议替换为：

```text
${PROJECT_DIR}
${DATA_DIR}
${MODEL_DIR}
${OUTPUT_DIR}
```

### 8.2 账号和服务器信息脱敏

检查是否存在：

1. 用户名；
2. 服务器 IP；
3. SSH 地址；
4. 内网路径；
5. 远程实验目录；
6. 个人主机名。

如存在，建议删除或改为配置占位符。

### 8.3 密钥与凭证检查

检查是否存在：

1. API Key；
2. Token；
3. 密码；
4. Cookie；
5. 访问凭证；
6. 数据库连接串。

如存在，必须删除，不应进入软著提交材料。

### 8.4 数据集内容检查

检查代码页中是否直接包含大量 AdsQA 问题、标准答案、视频路径或 ASR 文本。如存在，建议改为样例格式或配置读取，不提交完整数据。

### 8.5 第三方版权检查

检查代码中是否包含第三方开源库源码、第三方版权声明或非本人权属代码。软著提交代码应以自研逻辑为主，第三方依赖应通过引用或 import 的形式体现，不应直接混入第三方源码。

### 8.6 论文实验痕迹检查

建议删除或弱化以下内容：

1. “待补”；
2. “待运行”；
3. “待复核”；
4. “最终论文实验”；
5. “baseline 对比未完成”；
6. “显著提升”等未确认结论；
7. 过多硬编码实验路径。

## 9. 说明书与代码一致性检查

提交前应确认说明书中的功能与代码实际能力一致。

| 说明书功能 | 当前建议写法 | 风险说明 |
|---|---|---|
| OCR/Logo 识别 | 写“预留字段、支持接入外部 OCR/Logo 结果” | 当前未确认完整 OCR/Logo 检测器实现，不宜写已完整实现 |
| 向量检索 | 写“支持 embedding/hybrid 检索扩展接口” | 默认流程更偏词法检索和 TF 余弦，不宜写正式 FAISS/bge-m3 引擎 |
| 声明级校验 | 写“生成声明校验计划” | 当前更像规则型 check plan，不宜写自动判定所有声明真伪 |
| 性能提升 | 写“支持评估与统计” | 不宜写准确率显著提升、幻觉率显著下降 |
| 多模态模型 | 写“支持调用第三方模型” | 不宜写自研 Qwen、LLaVA、MiniCPM 等模型 |
| AdsQA | 写“兼容 AdsQA 数据格式” | 不宜写自主构建 AdsQA 数据集 |
