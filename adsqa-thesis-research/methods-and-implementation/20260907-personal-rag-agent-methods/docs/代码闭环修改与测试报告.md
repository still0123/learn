### 2.2 Evidence Package

文件：

```text
code_refactor/evidence/evidence_package.py
```

功能：

- 定义 `EvidencePackage`；
- 定义 `EvidenceField`；
- 从 AdsQA 现有 question、answer、meta_info、ASR 构建文本级 evidence package；
- 为后续 image/crop/bbox/OCR/Logo 字段预留 schema；
- 根据问题、答案、meta_info 和 ASR 轻量推断 `ad_evidence_types`。

说明：

当前 evidence package 是文本级桥接版本，不等于第3章最终理想的视觉证据包。它的作用是让 RAG、Prompt 和测试先跑通。

### 2.3 Marketing KB 转换

文件：

```text
code_refactor/rag/marketing_kb.py
```

功能：

- 读取原始 `patent_marketing_knowledge_base_deduplicated.json`；
- 将 268 条知识转换为统一 `MarketingKnowledgeItem`；
- 自动生成 `knowledge_id`，如 `MK0001`；
- 保留 `trigger_features`、`marketing_logic`、`dimension`、`industry_context`；
- 标记 `source_seed_id` 和 `potential_leakage`；
- 添加风险提示：若含 `source_seed_id`，最终实验前需确认 train/test 隔离。

重要风险：

这个知识库条目带 `source_seed_id`，可能来自具体样本。如果这些 seed 来自测试集，论文中必须说明知识库构建过程，避免数据泄漏质疑。

### 2.4 Evidence-aware RAG Retriever

文件：

```text
code_refactor/rag/retriever.py
```

功能：

- 无外部依赖；
- token overlap + TF cosine；
- query = question + evidence text；
- score = semantic + keyword + evidence match；
- 输出：`knowledge_id`、`score`、`supporting_evidence_ids`、`risk_notes`、`potential_leakage`。

这实现了论文第4章中的“证据驱动广告知识检索”的最小版本。

### 2.5 Prompt Builder

文件：

```text
code_refactor/reasoning/prompt_builder.py
```

功能：

- 构建“观察—知识匹配—分析—答案”Prompt；

文件：

