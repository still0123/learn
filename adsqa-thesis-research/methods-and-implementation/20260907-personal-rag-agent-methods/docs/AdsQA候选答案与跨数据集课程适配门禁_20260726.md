# AdsQA 候选答案与跨数据集课程适配门禁

**日期：** 2026-07-26  
**目的：** 在不启动多条新候选的前提下，比较“候选答案学习”与“E-VAds→AdsQA 课程适配”哪条增精路线值得继续。  
**当前状态：** Oracle、数据兼容性、单折训练/推理及当前裁判版本下的成对统一重评均已完成；课程适配准确率门禁失败，不扩展其余四折。

## 1. 候选答案 Oracle：多适配器候选有上限，单适配器候选不足

本阶段只读取同一 AdsQA Train-500 视频级五折 OOF 上已经冻结的预测与历史 DeepSeek 分数，GPU/API 调用均为 `0`，没有重新推理或修改旧分数。

| 候选池 | A0 Strict/Relaxed | Oracle Strict/Relaxed | 增量 | Strict 救援数 | 门禁 |
|---|---:|---:|---:|---:|---|
| 同一冻结 LoRA、8视图 | 21.40% / 40.10% | 23.60% / 42.90% | +2.20 / +2.80 pp | 11 | 失败 |
| 同预算多 LoRA 适配器、8视图 | 21.40% / 40.10% | 30.20% / 50.50% | +8.80 / +10.40 pp | 44 | 通过 |
| 全部可追溯候选 | 21.40% / 40.10% | 61.20% / 76.10% | +39.80 / +36.00 pp | 199 | 仅诊断 |

“全部可追溯候选”混合了干净基座与不同 LoRA、`8/32/40` 视图以及 `4,096/16,384/20,480` Token，不能作为公平部署结果。公平的第一层候选池，即同一个冻结 LoRA 下的 Raw8、RandomPiP8 和 ASR/OCR-PiP8，没有达到预注册的 `+5 pp` 门槛。

同预算多适配器池达到门槛。最小可通过集合为 A0 加 `TrainMatched_AsrOcrRegionToken8`：Strict 上限 `+3.60 pp`，Relaxed 上限 `+5.10 pp`。因此候选答案排序只获得**条件性放行**：后续必须显式报告多个 LoRA 的存储、推理和延迟成本，不能把混合预算 Oracle 写成实际准确率。

## 4. 课程适配准确率：裁判兼容性门禁失败

Frozen answer-only dry-run 表明：历史 AdsQA-only Fold-0 的 `100` 条分数可以全部复用；课程适配答案中 `18` 条与历史答案哈希完全一致，剩余需要 `82` 次新评分。

当前 DeepSeek 服务端已经停用旧请求别名 `deepseek-chat`，直接请求得到 `400`；改用历史响应实际模型 `deepseek-v4-flash` 后，旧 `max_tokens=20` 返回空内容，扩大到 `256` 仍为空。两次正式尝试和一次兼容校准均未产生任何可解析的新分数，不能据此计算 Strict、Relaxed、`wrong→right` 或 `right→wrong`。

失败目录均保留，未覆盖、未伪造结果：

```text
evads_adsqa_curriculum_fold0_v2/judge_frozen_answeronly_v1/
evads_adsqa_curriculum_fold0_v2/judge_frozen_answeronly_v2/
evads_adsqa_curriculum_fold0_v2/judge_compatibility_calibration_v1/
```

用户随后明确授权发送20条历史校准样本及最多82条新评测样本。确定性校准使用相同 Prompt 和解析器、`deepseek-v4-flash`、`max_tokens=1024`，20条均成功解析、重试为0，但只有 `12/20` 与历史分数一致，一致率仅 `60%`。历史分布 `0/0.5/1=7/7/6`，当前分布变为 `8/9/3`；总用量为 `13,399` prompt、`5,380` completion、`18,779` Token。由于未达到预注册的 `20/20`，脚本按门禁停止，授权范围内的82条新样本调用数为 `0`。

这说明当前端点虽仍返回同名 `deepseek-v4-flash`，但不能与历史冻结分数混用；它是**裁判版本/行为漂移**，不是课程模型准确率的负结果。兼容性产物为：

## 5. 当前决策

1. **候选答案学习：** 多适配器同预算 Oracle 已达到门槛，理论上值得继续，但真实排序器尚未验证，而且至少增加一个 LoRA 适配器的成本。
2. **跨数据集课程适配：** 数据、训练和视觉协议可行性成立，但 Fold-0 的 Strict/Relaxed 分别下降 `5.0/3.5 pp`，且伤害多于纠正；准确率门禁失败，冻结该路线，不启动其余四折。
3. **唯一下一步：** 转向同预算多适配器候选答案排序器的成本受控预检。先只用现有 OOF 候选和已冻结分数构造不含参考答案的排序特征，做视频隔离的 CPU Oracle/泄漏/成本审计；门禁通过后再设计50题 smoke，不能直接训练全量排序器。
4. 不启动 FreshQ、3000题、E-VAds课程适配五折、RAG、自由反思或新的视觉候选。

## 6. 多适配器候选排序器 CPU 预检：未放行 Smoke-50

本阶段使用 `AdsSFTLoRA_Raw8` 与最小 Oracle 通过候选 `TrainMatched_AsrOcrRegionToken8`。两组均为干净 Qwen2.5、独立训练的折内 LoRA、Raw8/RegionToken8、8视图、448、4,096视觉Token和同一回答 Prompt。历史预测与冻结裁判均只读，GPU/API 调用为0。

排序输入与监督物理分离。输入仅包含问题哈希、两份候选答案的长度/数字/相互一致性、候选与问题的词重合，以及不含答案的 OCR/ASR 区域计划统计；不读取参考答案、`meta_info`、裁判输出或分数。监督文件单独保存历史 `0/0.5/1` 分数。固定模型为标准化数值特征加 `class_weight=balanced, C=1.0` 的逻辑回归，不扫描阈值或超参数；五折每次仅用其他80个视频训练，对隔离20个视频预测，所有 train/test 视频交集为0。

| 方法 | Strict | Relaxed | 相对 Raw |
|---|---:|---:|---:|
| Raw8 | 21.40% | 40.10% | - |
| ASR/OCR RegionToken8 | 20.80% | 40.50% | -0.60 / +0.40 pp |
| 两候选 Oracle | 25.00% | 45.20% | +3.60 / +5.10 pp |
| 固定 OOF 逻辑回归排序器 | 20.60% | 40.60% | -0.80 / +0.50 pp |

500题中两候选答案完全相同 `202` 条、不同 `298` 条；Region候选胜/平/负=`46/412/42`。排序器触发 `161/500=32.2%`，`wrong→right=8`、`right→wrong=12`，纠正精度仅 `40%`。Relaxed差的100视频聚类10,000次 Bootstrap 95% CI=`[-1.3,+2.3] pp`，Strict差=`[-2.6,+1.0] pp`，均跨0。虽然Relaxed点估计未下降，但“纠正不少于伤害”和“纠正精度至少50%”两个门禁失败，裁决为 `freeze_learned_ranker_no_smoke`。

成本审计显示每个额外 LoRA 约 `38.54 MiB`；五折审计产物的五个额外适配器共约 `192.69 MiB`。最终部署只需一个额外适配器，但每题仍需生成两份答案，理论回答计算约为 Raw 的 `2倍`。旧运行产物没有可靠逐题时延字段，因此不得声称实测延迟。
