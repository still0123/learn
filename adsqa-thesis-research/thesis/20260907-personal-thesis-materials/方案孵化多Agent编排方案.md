# 方案孵化多 Agent 编排方案

> 用途：在正式写论文前，根据 2025-2026 年视觉问答、视频问答、定位、RAG、证据验证等新文献，和现有 AdsQA 技术方案进行整合，反复生成、审查、修改、排序候选技术路线，最终筛出 top3/top5 可继续实验和写入论文的方案。

注意：本文件不替代 `docs/agent_orchestration_v2.md`。  
`agent_orchestration_v2.md` 仍用于正式论文写作、审稿和返修。  
本文件只用于“中期后技术方案孵化”。

---

## 1. 目标

当前问题不是直接写正文，而是：

```text
新文献很多
-> 现有方案需要升级
-> 不能只改表达
-> 需要设计多个真实可做的技术方案
-> 用多 Agent 反复批判和修改
-> 最后筛出 top3/top5
```

本流程的目标是输出：

1. 3-5 个候选技术方案；
2. 每个方案借鉴了哪些文献；
3. 借鉴点如何转化为 AdsQA / 广告视频问答中的技术动作；
4. 每个方案需要改哪些代码、跑哪些实验；
5. 每个方案的创新性、可行性、实验风险、论文风险；
6. 最终 top3/top5 排名与下一步执行建议。

---

## 2. 与正式论文 Agent 的区别

| 项目 | 正式论文 Agent | 方案孵化 Agent |
|---|---|---|
| 目标 | 写论文、审稿、返修 | 构思技术方案、筛选路线 |
| 输入 | 论文草稿、实验结果、参考文献 | 新文献、现有方法、实验结果、代码能力 |
| 输出 | 可并入论文正文 | 候选方案卡、实验路线、排序 |
| 风格 | 保守、严谨、定稿导向 | 发散、批判、迭代、择优 |
| 是否改题 | 不改题 | 可建议方法名/主线调整，但不直接改正式论文 |
| 是否编数据 | 绝不编 | 绝不编，只能提出待跑实验 |

---

## 3. 总体流程

```text
P0 主控设定问题
        ↓
P1 文献吸收 Agent：提取可借鉴技术原语
        ↓
P2 现有方案映射 Agent：梳理当前 pipeline、实验结果、代码能力
        ↓
P3 候选方案生成 Agent：生成多条候选路线
        ↓
P4 可行性 Agent：评估代码改动、数据需求、实验成本
        ↓
P5 文献与创新性审查 Agent：判断是否只是已有工作拼接
        ↓
P6 实验设计 Agent：为每个方案设计主实验和消融
        ↓
P7 反方审稿 Agent：模拟评委/审稿人攻击
        ↓
P8 修改进化 Agent：根据批评修改或合并方案
        ↓
循环 2-3 轮
        ↓
P9 排序决策 Agent：输出 top3/top5 和执行优先级
```

核心是闭环：

```text
生成方案 -> 文献审查 -> 可行性审查 -> 审稿攻击 -> 修改方案 -> 再审查
```

---

## 4. Agent 角色

## P0 主控 Agent：方案搜索总控

职责：

- 设定本轮搜索目标；
- 控制不要污染正式论文主规范；
- 汇总所有 Agent 输出；
- 决定是否进入下一轮迭代；
- 最终裁决 top3/top5。

输出：

```markdown
# P0 总控输出

## 本轮目标

## 输入材料

## 搜索边界

## 禁止路线

## 本轮评价权重
```

默认评价权重：

| 维度 | 权重 |
|---|---:|
| 创新性 | 25 |
| 与广告视频场景贴合度 | 20 |
| 可实现性 | 20 |
| 实验可验证性 | 20 |
| 论文叙事清晰度 | 10 |
| 风险可控性 | 5 |

---

## P1 文献吸收 Agent：从新论文中抽技术原语

职责：

- 阅读本地文献综述与检索笔记；
- 必要时继续补充公开文献；
- 不写论文正文；
- 抽取“可借鉴技术原语”，例如：
  - selective scan compression；
  - visual token pruning；
  - high-res crop；
  - scene-text-aware QA；
  - temporal grounding；
  - video graph RAG；
  - evidence verification；
  - claim-level grounding。

输出：

```markdown
# P1 文献吸收输出

## 技术原语清单
- 原语：
- 来源论文：
- 原论文解决什么问题：
- 原论文怎么做：
- 可迁移到 AdsQA 的部分：
- 不能直接照搬的部分：
- 对本文构成的威胁：

## 可组合方向

## 需要核查的引用
```

---

## P2 现有方案映射 Agent：当前 pipeline 与能力边界

职责：

- 梳理当前 AdsQA 代码、实验、数据；
- 明确已有能力和缺口；
- 防止方案设计脱离当前条件；
- 特别关注：
  - 当前最强 no-RAG evidence pipeline；
  - RAG/verifier 失败原因；
  - Qwen3/Qwen2.5 baseline 口径；
  - 是否已有 ASR/OCR/帧选择/知识库/评测脚本；
  - 哪些改动可以一周内做 MVP。

输出：

```markdown
# P2 现有方案映射输出

## 当前已具备能力

## 当前实验结论

## 当前代码可改动点

## 当前不可依赖能力

## 最小可行修改空间
```

---

## P3 候选方案生成 Agent：生成技术路线

职责：

- 基于 P1/P2 生成多个候选方案；
- 每个方案必须是完整方法，不是单个模块；
- 每个方案必须说明从哪些论文借鉴，如何“化用”而不是照搬；
- 每个方案必须能对应至少一组实验。

输出候选方案卡：

```markdown
# Candidate X

## 方案名

## 一句话目标

## 借鉴文献
- 论文：
- 借鉴点：
- 化用方式：

## 解决的 AdsQA 具体问题

## 技术流程
1.
2.
3.

## 与当前方法的区别

## 需要新增的模块

## 可复用现有模块

## 预期提升的问题类型

## 风险
```

候选方案数量：

- 第一轮至少生成 6-8 个；
- 第二轮合并/淘汰到 4-6 个；
- 最终输出 top3/top5。

---

## P4 可行性 Agent：工程与实验可行性

职责：

- 逐个方案评估实现成本；
- 判断是否需要训练大模型；
- 判断是否依赖缺失数据；
- 判断是否能在现有 AdsQA pipeline 上快速验证；
- 给出 MVP 实现路径。

输出：

```markdown
# P4 可行性评估输出

## 方案可行性表
| 方案 | 代码改动 | 数据需求 | 是否需训练 | 预计实验成本 | 一周内MVP | 风险 |

## 每个方案的 MVP 路线

## 不建议继续的方案
```

---

## P5 文献与创新性审查 Agent：判断是否只是已有工作拼接

职责：

- 从近期文献角度审查候选方案；
- 判断是否被 BIMBA、PruneVid、FOCUS、ZoomEye、ReVisionLLM、ViG-RAG、Entailment Tree 等覆盖；
- 指出方案最像哪篇论文；
- 要求候选方案明确广告视频独有差异。

输出：

```markdown
# P5 创新性审查输出

## 创新性风险表
| 方案 | 最接近已有工作 | 相似点 | 差异点是否足够 | 风险等级 | 修改建议 |

## 需要强化的方案

## 应淘汰的方案
```

---

## P6 实验设计 Agent：把方案变成可验证实验

职责：

- 为每个候选方案设计主实验、消融实验、指标和错误分析；
- 不编结果；
- 优先利用已有 AdsQA 评测流程；
- 指出需要新增的统计脚本或人工 audit。

输出：

```markdown
# P6 实验设计输出

## 主实验矩阵

## 消融实验矩阵

## 分类型评测

## 人工 audit 设计

## 成功判据

## 失败时如何解释
```

---

## P7 反方审稿 Agent：模拟评委/审稿人攻击

职责：

- 不负责鼓励方案；
- 专门找弱点；
- 模拟答辩/审稿问题：
  - 这是不是模块拼接？
  - 这是不是已有论文直接套到广告视频？
  - 为什么 RAG 失败还要保留？
  - 为什么只在某些问题类型提升？
  - 实验是否公平？
  - 是否只是 prompt 工程？

输出：

```markdown
# P7 反方审稿输出

## 每个方案的致命问题

## 答辩可能被问

## 如果我是评委，我会要求补的实验

## 必须修改后才能继续的方案
```

---

## P8 修改进化 Agent：根据批评修订方案

职责：

- 根据 P4/P5/P6/P7 的意见修改方案；
- 合并相似方案；
- 删除不可行方案；
- 将泛泛表述改成具体技术动作；
- 每轮输出 revised candidates。

输出：

```markdown
# P8 修改进化输出

## 保留方案

## 合并方案

## 淘汰方案

## 修改后的候选方案卡

## 下一轮需要重点审查的问题
```

---

## P9 排序决策 Agent：输出 top3/top5

职责：

- 基于多轮输出最终排序；
- 给每个方案打分；
- 输出 top3/top5；
- 给出推荐执行顺序；
- 说明哪一个适合作为主创新、哪一个适合作为辅助创新、哪一个适合作为实验增强。

输出：

```markdown
# P9 最终排序输出

## 排名表
| 排名 | 方案 | 创新性 | 可行性 | 实验性 | 论文叙事 | 总分 | 建议 |

## Top 方案详解

## 推荐组合

## 下一步实验路线

## 不建议继续的方向
```

## 5. 默认候选方向种子

第一轮可以从以下方向生成候选，但 Agent 不能被这些方向限制：

1. 广告证据槽驱动的视听-文字输入重构；
2. OCR/Logo/CTA 类型化证据定位；
3. 证据槽触发式局部高分辨率证据视图；
4. 短广告粗到细 temporal evidence routing；
5. 证据触发式低噪声广告知识检索；
6. 广告答案声明级证据许可；
7. 声画错位补偿的 ASR-visual evidence alignment；
8. 针对 AdsQA 问题类型的 slot-adaptive budget allocation；
9. evidence support audit / unsupported claim evaluation；
10. 面向营销语义题的 evidence-grounded explanation。

## 6. 评分标准

每个方案按 0-5 分打分：

| 维度 | 5 分标准 | 1 分标准 |
|---|---|---|
| 创新性 | 明确区别于 2025-2026 相近论文，有场景特化技术机制 | 基本是已有论文换场景 |
| 广告贴合度 | 深度利用 Logo、价格、CTA、ASR/OCR、营销语义 | 只是通用 VideoQA |
| 可实现性 | 基于现有代码一周内可做 MVP | 需要训练大模型或大量新标注 |
| 实验可验证性 | 有明确主实验、消融、分类型指标 | 只能写概念，难以验证 |
| 论文叙事 | 能形成清晰第3/4/5章结构 | 像模块堆叠 |
| 风险可控性 | 失败也能通过分析形成论文贡献 | 失败后没有可解释空间 |

淘汰规则：

- 创新性低于 3 且广告贴合度低于 3：淘汰；
- 可实现性低于 2：除非特别有价值，否则淘汰；
- 实验可验证性低于 3：降级为未来工作；
- 与当前最强实验结果冲突且无解释：淘汰或重构。

## 8. 何时结束循环

满足以下条件之一即可结束：

1. 已得到 3 个创新性、可行性、实验性都不低于 4 分的方案；
2. 连续两轮排序 top3 不再变化；
3. P7 反方审稿 Agent 不再指出致命问题；
4. P4 可行性 Agent 能给出明确的一周内 MVP 路线；
5. 用户选择某个方案进入实验实现阶段。
