# 中期后技术改造路线：如何借鉴 2025-2026 视觉问答与视频理解工作

记录日期：2026-07-07

目标：不是只修改论文表述，而是在现有 AdsQA 实验基础上，借鉴近期 VideoQA、visual grounding、token compression、Video RAG、evidence verification 的技术思想，设计可以真实实现、可以重跑实验、可以写进毕业论文的方法框架。

---

## 1. 当前基础与问题

### 1.1 当前已有基础

从已有实验看，当前可用基础是：

- 已能跑 AdsQA 本地评测流程；
- 有 Qwen2.5 / Qwen3 系列 baseline；
- 已有 no-RAG evidence pipeline；
- 最新较好结果是 `ours_qwen3_evidence_norag_bal2500_20260629`：
  - strict 约 41.96%；
  - relaxed 约 54.62%；
  - 明显优于 qwen3 raw uniform baseline；
  - RAG/verifier 版本当前反而下降。

这说明当前最有价值的不是“知识库增强”，而是：

```text
选对视频证据 > 检索更多知识
```

### 1.2 当前方法最大问题

当前方法的问题不是没有创新点，而是技术对象还不够“硬”：

- 如果只是 over-sampling + top-k frame 选择，容易被认为是工程策略；
- 如果只是 evidence prompt，容易被认为是提示词；
- 如果 RAG 效果不好，就不能把 RAG 作为强贡献；
- 如果 verifier 只靠模型自检，技术含量和实验说服力都不足。

因此，中期后应把技术重心从：

```text
采样更多帧 + prompt 推理 + RAG
```

改成：

```text
广告证据槽建模 + 证据保留型输入重构 + 低噪声知识触发 + 声明级证据许可
```

## 2. 可借鉴工作一：从 BIMBA / PruneVid / Dynamic-VLM 借鉴“证据保留型压缩”

### 2.1 他们的核心思想

BIMBA、PruneVid、Dynamic-VLM 等工作的共同点是：

- 视频视觉 token 冗余极高；
- 均匀采样会浪费预算，也可能漏掉关键瞬间；
- 压缩不能只看帧数，要看保留的信息是否对问题有用；
- 问题相关信息应被优先保留。

### 2.2 不能直接照搬的地方

这些工作大多关注通用长视频或 VideoLLM 效率：

- 目标是减少 token 或加速；
- 不专门处理广告字幕、Logo、价格、CTA；
- 不强调 OCR/ASR/视觉错位；
- 不一定输出可追溯 evidence package。

### 2.3 本文应如何化用

把“token 压缩”改造成“广告证据保留型输入重构”。

具体做法：

```text
输入：视频帧、ASR、OCR、问题 Q

1. 先粗采样获得候选帧集合 F。
2. 对每个候选帧计算多路证据分数：
   - visual_score：帧图像与问题的相关性；
   - asr_score：该帧邻域 ASR 与问题的相关性；
   - ocr_score：该帧 OCR 与问题/广告证据槽的相关性；
   - ad_salience_score：Logo、价格、商品、CTA、人物、品牌字幕等广告显著性；
   - temporal_diversity_score：避免全部选到同一片段。
3. 融合得到 evidence_response_score。
4. 根据问题类型选择不同证据预算：
   - OCR/价格题：保留更多高分辨率局部图；
   - 品牌题：保留 Logo/包装区域；
   - 受众/情绪题：保留人物、场景、音乐/ASR邻域；
   - 行动号召题：保留结尾片段和 CTA 字幕。
5. 输出 global context frames + local evidence crops + ASR/OCR snippets。
```

### 2.4 对现有代码/实验的修改方向

在现有 `ours_qwen3_evidence_norag` 基础上新增一个选择器版本：

```text
ours_qwen3_slot_evidence_norag
```

它与当前 evidence no-RAG 的区别：

- 不再只按统一 top-k 选帧；
- 增加 question type / evidence slot；
- 不同问题类型使用不同帧/局部图预算；
- 每个输入证据带 source_type：
  - visual_frame；
  - local_crop；
  - asr；
  - ocr；
  - logo/product/cta。

### 2.5 需要做的实验

主实验：

| 实验 | 目的 |
|---|---|
| qwen3 raw uniform | 原始 baseline |
| qwen3 evidence no-RAG | 证明证据选择有效 |
| qwen3 slot evidence no-RAG | 证明广告证据槽比普通 evidence 选择更有效 |
| qwen3 slot evidence + local crop | 证明局部证据视图能提升 OCR/Logo/价格类问题 |

消融实验：

| 消融 | 目的 |
|---|---|
| 去掉 ASR score | 看旁白邻域是否有贡献 |
| 去掉 OCR score | 看字幕/文字是否有贡献 |
| 去掉 ad_salience score | 看广告证据类型先验是否有贡献 |
| 固定 top-k vs slot-adaptive top-k | 看问题类型自适应预算是否有贡献 |
| global only vs global + local | 看局部高分辨率视图是否有贡献 |

## 3. 可借鉴工作二：从 FOCUS / ZoomEye / ViCrop 借鉴“局部看图”，但改成证据槽触发

### 3.1 他们的核心思想

FOCUS、ZoomEye、ViCrop 等工作说明：

- VLM 对小目标、小文字、细粒度属性容易看不清；
- 先看全图再看局部是有效的；
- 裁剪区域可以由问题、内部注意力、区域树或工具调用决定。

### 3.2 不能直接照搬的地方

如果本文只是做：

```text
根据问题 crop 相关区域，然后再问 VLM
```

会很像已有工作。

### 3.3 本文应如何化用

把“局部裁剪”改成“证据槽触发的局部证据视图”。

具体规则：

```text
只有当某个问题类型需要局部细节时，才申请局部图。

品牌/商品题：
  触发 Logo、包装、商品主体 crop。

价格/优惠题：
  触发 OCR 文本区域、价格区域、结尾促销区域 crop。

功效/卖点题：
  触发商品演示画面 + 功效字幕 crop。

行动号召题：
  触发视频结尾若干秒 + CTA 字幕/按钮 crop。

受众/情绪题：
  触发人物、场景、情绪表达、背景音乐/ASR邻域，而不是只 crop 商品。
```

### 3.4 可以实现的轻量版本

不需要训练 detector，先做规则/工具版：

```text
1. 用现有 OCR 结果拿文字 bbox。
2. 用 logo/product/object detector 或视觉 caption 生成候选区域。
3. 对候选区域按问题和证据槽打分。
4. 每题最多保留 2-4 个局部 crop。
5. prompt 中明确 local evidence crop 与原始 frame 的关系。
```

如果现在没有可靠 bbox，也可以先做近似版本：

- OCR 区域：由 OCR 输出 bbox 裁剪；
- Logo/商品区域：先用通用检测/CLIP 相似度/中心区域候选；
- CTA：优先视频后 20% 时间段，叠加 OCR。

### 3.5 需要做的实验

建议按问题类型分组报告：

| 问题类型 | 预期提升来源 |
|---|---|
| OCR/价格/文字 | local crop 最可能提升 |
| Logo/品牌 | logo/package crop 提升 |
| 商品属性 | product crop 提升 |
| 行动号召 | ending + OCR 提升 |
| 受众/情绪 | local crop 未必明显，ASR/全局场景更重要 |

如果整体提升不大，但 OCR/Logo/价格类显著提升，也可以写成细粒度证据类问题的优势。

## 4. 可借鉴工作三：从 ReVisionLLM / Grounded Multi-Hop VideoQA 借鉴“粗到细时序证据”

### 4.1 他们的核心思想

这些工作都说明：

- VideoQA 不应该只输入均匀帧；
- 需要先找到相关时间片段；
- 复杂问题可能需要多个时间证据；
- 证据时间段本身可以成为评价对象。

### 4.2 本文应如何化用

广告视频虽然不长，但证据密度高，可以做：

```text
广告视频粗到细证据定位：

粗定位：
  根据 ASR/OCR/视觉相关性找到候选时间段。

细定位：
  在候选时间段内过采样，找短时字幕、Logo、商品细节、CTA。

证据链：
  对每个答案声明记录所依赖的时间片段。
```

### 4.3 与现有方法的区别

不是为小时级视频定位事件，而是为短广告视频定位密集证据：

- 开头吸引注意；
- 中段展示商品和卖点；
- 结尾 CTA；
- 字幕/价格可能只闪现几帧；
- 旁白和画面不一定同步。

### 4.4 需要做的实验

新增一组 temporal ablation：

| 方法 | 说明 |
|---|---|
| uniform frames | 均匀采样 |
| asr-guided segments | 只用 ASR 选时间段 |
| ocr-guided segments | 只用 OCR 选时间段 |
| visual-guided segments | 只用视觉相似度 |
| fused evidence response | ASR+OCR+视觉+广告显著性融合 |

评价不只看 answer accuracy，还可以做小规模人工 audit：

- 选出的证据是否包含答案依据；
- 是否遗漏短时文字；
- 是否选到无关产品镜头；
- 是否过度集中在开头/结尾。

## 5. 可借鉴工作四：从 EgoTextVQA 借鉴“视频文字是核心难点”，但做广告文字类型化

### 5.1 他们的核心思想

EgoTextVQA 说明：

- 视频中的文字理解很难；
- 高分辨率、多帧、时间 grounding、辅助文字输入都重要；
- 现有 MLLM 对 scene text-aware VideoQA 表现仍弱。

### 5.2 本文应如何化用

广告视频中的文字比普通 scene text 更有结构，可以把 OCR 分为：

| OCR 类型 | 例子 | 对问题的作用 |
|---|---|---|
| brand_text | 品牌名、Logo 文字 | 品牌/产品识别 |
| price_text | 价格、折扣、优惠 | 价格/促销问答 |
| claim_text | 功效、卖点、承诺 | 功能/卖点理解 |
| disclaimer_text | 限制条件、小字说明 | 防止错误外推 |
| cta_text | 立即购买、扫码、下载 | 行动号召 |
| audience_text | 学生党、宝妈、上班族 | 目标受众 |

### 5.3 可实现版本

先不训练分类器，用规则 + LLM 分类：

```text
OCR text -> LLM/规则分类 -> ad_text_type
```

规则例子：

- 包含 ¥、折、元、off、% -> price_text；
- 包含 立即、扫码、下载、购买、点击 -> cta_text；
- 包含 无添加、持久、修护、提亮、效率、智能 -> claim_text；
- 包含 适合、专为、学生、妈妈、职场 -> audience_text；
- 很短且重复出现 -> brand_text 候选。

### 5.4 需要做的实验

| 实验 | 目的 |
|---|---|
| OCR raw text only | 证明 OCR 有用 |
| OCR typed slots | 证明广告文字类型化更有用 |
| OCR typed + local crop | 证明文字区域高清图进一步提升 |
| 去掉 disclaimer/limitation | 看模型是否更容易过度承诺 |

## 6. 可借鉴工作五：从 ViG-RAG / VideoRAG 借鉴检索，但只做证据触发式低噪声注入

### 6.1 当前实验提醒

你的 RAG/verifier 实验当前效果不好，说明：

```text
广告知识如果无约束注入，很可能增加噪声。
```

因此不要把 RAG 当主线。

### 6.2 他们的核心思想

ViG-RAG / VideoRAG 的共同思路：

- 将视频 caption/transcript/segment 转为可检索结构；
- 用语义 + 时间信息检索相关片段；
- 用检索结果辅助回答长视频问题。

### 6.3 本文应如何化用

不是做普通 RAG，而是：

```text
证据槽触发式广告知识检索
```

触发条件：

- 只有当 evidence package 中已经有视频证据，才允许检索；
- 检索 query 由 question + evidence slot + observed evidence 共同构成；
- 每个问题最多注入 top-1/top-2；
- 检索结果只能解释视频证据，不能补充视频中未出现事实。

例子：

```text
问题：这个广告主要使用了什么说服策略？
视频证据：
  OCR: "限时优惠"
  ASR: "现在下单立减"
  画面: 结尾展示购买入口
触发槽：
  persuasion_strategy / cta / scarcity
允许检索：
  "限时优惠 稀缺性营销 行动号召"
不允许：
  检索某品牌历史、产品功效、竞品信息后自行补充答案。
```

### 6.4 需要重做的 RAG 实验

不要再只比较 RAG vs no-RAG，要比较：

| 方法 | 目的 |
|---|---|
| no-RAG evidence | 当前强基线 |
| naive RAG | 证明普通 RAG 噪声大 |
| slot-triggered RAG | 证明受控检索才有效 |
| slot-triggered RAG + knowledge-only blocking | 证明知识越权控制降低幻觉 |

如果 slot-triggered RAG 仍然不提升 accuracy，也可以报告：

- unsupported marketing claim 降低；
- 知识噪声率降低；
- 错误解释减少；
- 对营销策略类问题有提升。

## 7. 可借鉴工作六：从 Entailment Tree / EV2-Bench 借鉴证据校验，但改成广告声明许可

### 7.1 他们的核心思想

Commonsense VideoQA with Entailment Tree、EV2-Bench、VideoZeroBench 说明：

- 答案正确不等于证据正确；
- 视频问答应该要求 evidence grounded；
- 复杂答案可以拆成子声明；
- 每个子声明都应回溯到视觉/时序证据。

### 7.2 本文应如何化用

把答案拆成广告声明，并给不同声明不同许可条件。

声明类型：

| 声明类型 | 例子 | 许可条件 |
|---|---|---|
| visual_fact | 画面出现某商品 | 需要视觉帧/局部图支持 |
| text_fact | 字幕写了限时优惠 | 需要 OCR/字幕支持 |
| speech_fact | 旁白提到免费试用 | 需要 ASR 支持 |
| marketing_semantic | 使用稀缺性策略 | 需要视频证据 + 广告知识解释 |
| audience_inference | 面向年轻女性 | 需要人物/场景/文案证据，不能只凭常识 |
| knowledge_only | 某品牌通常代表高端 | 不能单独输出，除非视频触发 |

状态：

```text
supported
contradicted
insufficient
knowledge_only
not_applicable
```

最终动作：

```text
supported -> 保留
contradicted -> 删除或改写
insufficient -> 降级表达
knowledge_only -> 若无视频触发则删除
```

### 7.3 实验怎么做

不一定要全量人工标注。可以做 200-300 条人工 audit 子集：

| 指标 | 定义 |
|---|---|
| answer accuracy | 原始 strict/relaxed |
| evidence support rate | 答案声明是否能被证据包支持 |
| unsupported claim rate | 无证据声明比例 |
| knowledge override rate | 知识覆盖视频证据的比例 |
| downgrade precision | 被降级/删除的声明是否确实证据不足 |

这组实验很适合写论文，因为它能解释：

- 为什么 naive RAG 会降；
- 为什么 evidence no-RAG 稳；
- 为什么受控知识和声明许可是必要的。

## 8. 中期后建议改成的新方法框架

建议方法名：

```text
Ad-EvidenceQA: 广告证据槽驱动的视频问答方法
```

或更学术一点：

```text
Evidence-Slot Guided Advertising Video Question Answering
```

完整流程：

```text
1. 问题分析
   Q -> question_type -> evidence_slots

2. 候选证据构建
   video -> frames / ASR / OCR / logo-object candidates

3. 证据响应图
   score(frame, slot) = visual + ASR + OCR + ad_salience + temporal_diversity

4. 证据保留型输入重构
   output = global_context_frames + local_evidence_crops + typed OCR/ASR snippets

5. 受控广告知识检索
   only triggered by evidence slots
   top-1/top-2 low-noise injection

6. 答案生成
   VLM receives evidence package, not raw random frames

7. 声明级许可校验
   answer -> claims -> claim_type -> evidence requirement -> support state

8. 最终答案改写
   supported claims kept
   unsupported / knowledge-only claims downgraded or removed
```

## 9. 最小可行实验路线

### 阶段一：先做证据槽选择，不碰 RAG

目标：确认“广告证据槽 + 输入重构”是否比当前 evidence no-RAG 更强。

实验：

```text
qwen3_raw_uniform
qwen3_evidence_norag
qwen3_slot_evidence_norag
qwen3_slot_evidence_localcrop_norag
```

优先看：

- strict / relaxed；
- OCR/Logo/价格类问题子集；
- 受众/情绪/策略类问题子集；
- token 数 / 帧数 / 延迟。

### 阶段二：再做受控 RAG

目标：证明不是 RAG 没用，而是 naive RAG 噪声大。

实验：

```text
no-RAG evidence
naive RAG
slot-triggered RAG
slot-triggered RAG + knowledge-only blocking
```

优先看：

- overall accuracy；
- marketing semantics 子集；
- unsupported claim rate；
- knowledge override rate。

### 阶段三：做声明级 audit

目标：让论文不只依赖 accuracy，有可信度指标。

抽样：

- 200-300 条；
- 覆盖不同问题类型；
- 人工标注答案中每个声明是否有证据支持。

指标：

```text
evidence support rate
unsupported claim rate
knowledge-only claim rate
claim downgrade precision
```

## 11. 最推荐的中期后修改优先级

### 第一优先级：实现广告证据槽

这是最值得做的，因为它能贯穿方法、实验、论文叙事。

最小实现：

```text
question_type + evidence_slot prompt/rules
```

不需要训练。

### 第二优先级：实现 typed OCR / ASR 证据

广告视频对文字和口播非常敏感，这部分最容易体现领域差异。

### 第三优先级：实现 slot-adaptive frame/crop budget

不同问题用不同证据预算，比统一 top-k 更像方法。

### 第四优先级：实现 slot-triggered RAG

不要先做大 RAG。先把检索触发条件和 top-k 降低。

### 第五优先级：做 200-300 条声明级 audit

这会极大增强论文说服力，尤其当 accuracy 提升有限时。

---

## 12. 最终建议

中期后不要大改成一个完全新课题。应在现有 evidence no-RAG 成功基础上做结构化升级：

```text
现有方法：
更多候选帧 + evidence prompt

升级方法：
广告证据槽 -> 多路证据响应 -> 输入重构 -> 受控知识 -> 声明许可
```

这样既能继承已有实验，又能借鉴 2025-2026 年论文的真正趋势：

- 从 BIMBA/PruneVid 借鉴 evidence-preserving compression；
- 从 FOCUS/ZoomEye 借鉴 local evidence view；
- 从 ReVisionLLM/Grounded Multi-Hop 借鉴 coarse-to-fine temporal evidence；
- 从 EgoTextVQA 借鉴 scene text-aware VideoQA；
- 从 ViG-RAG 借鉴 structured retrieval，但改成证据触发；
- 从 Entailment Tree/EV2-Bench 借鉴 evidence verification，但改成广告声明许可。
