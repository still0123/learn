# 创新点一可靠性校准证据定位实验清单

**版本：** v1  
**日期：** 2026-07-15  
**目标：** 在固定 32 视图、11,664 视觉 Token、关闭二次采样的条件下，验证可靠性校准与不确定性探索能否改善广告视频证据定位，并在不牺牲总体问答性能的前提下提升细粒度证据利用。

## 1. 统一资源约束

- [x] 所有需要 CUDA 的任务只使用 GPU3，统一设置 `CUDA_VISIBLE_DEVICES=3`；
- [x] GPU3 上的 Whisper、选择器训练和 Qwen 推理串行运行，不同时加载多个大模型；
- [x] GPU0/1/2/4/5 不使用，不终止或影响其他用户进程；
- [ ] OCR、数据整理和统计使用 CPU，DeepSeek 裁判使用 API；
- [ ] 每次正式实验前检查 GPU3 compute PID、显存、代码哈希、数据哈希和断点状态；
- [ ] 所有逐题结果原子写入并支持断点续跑。

## 2. 阶段零：冻结预处理底座

- [x] 完成 Candidate64 CLIP 缓存 1707/1707；
- [x] 完成 Candidate64 OCR 缓存 1707/1707；
- [x] 验证 Raw32 在 Candidate64 中逐帧严格嵌套 1707/1707；
- [x] 完成 Pilot50、Train、Confirm-A/B/C 共 1050 个唯一视频的分段 ASR；
- [x] 分别记录 `success/no_audio/no_speech/transcription_failed`，禁止用空字符串混合状态；
- [x] 通过帧号、时间戳、特征维度、OCR 坐标、ASR 时间边界和重复文件审计；
- [x] 保存文件级 SHA256、聚合哈希、manifest 和空/非空失败清单；
- [x] 审计通过后冻结缓存，后续实验禁止重新解码或二次采样。

**门禁 G0：** CLIP/OCR 1707/1707、Raw32 嵌套 1707/1707、目标 ASR 无结构性错误；否则不进入方法实验。

## 3. 阶段一：冻结数据划分与证据标注

- [ ] 从 Train500 构建训练/校准划分，必须按视频分组，禁止同一视频跨集合；
- [x] 在任何新 QA 结果产生前冻结一份 Confirm-D300，要求与 Pilot50、Confirm-A/B/C 的问题和视频零重合；
- [x] 为 Confirm-D 所需视频补做同口径分段 ASR，仍只使用 GPU3；
- [ ] 建立 300 题证据集，标注关键时间段、证据类型和可见区域；AI 仅生成候选，正式指标必须使用复核后的标注；
- [ ] 证据类型至少包括全局叙事、人物/动作、Logo/品牌、OCR/价格、CTA 和语音；
- [ ] 标记 `tiny/ambiguous/ungroundable`，不强迫所有问题都有单一 ROI；
- [ ] 保存标注指南、双人复核或抽样复核结果以及数据哈希。

**门禁 G1：** 无数据泄漏，证据标注可复核；Pilot50 只作为回归集，Confirm-D 不用于调参。

## 4. 阶段二：候选特征与轻量选择器

- [ ] 为每个问题的 64 个候选帧生成问题—视觉 CLIP 相关性；
- [ ] 生成问题—分段 ASR 相关性、时间偏移一致性和 ASR 置信特征；
- [ ] 生成问题—OCR 相关性、OCR 检测置信度、跨帧文字稳定性和区域大小特征；
- [ ] 生成时间邻域一致性、时间覆盖、重复度和证据需求类型特征；
- [ ] 检查特征代码不读取测试答案、DeepSeek 分数或 Confirm 标签；
- [ ] 训练一个轻量 MLP 或 1D 时序选择器，冻结 CLIP、Whisper 和 Qwen；
- [ ] 在独立校准划分上执行温度缩放或等价概率校准；
- [ ] 输出逐帧证据概率 `p_i`、不确定性 `u_i` 和证据类型概率；
- [ ] 使用至少 3 个随机种子报告 AUROC、AUPRC、F1、Brier Score 和 ECE。

### 4.1 训练级对照

- [ ] `F0`：仅问题—视觉相关性；
- [ ] `F1`：`F0 + ASR`；
- [ ] `F2`：`F1 + OCR`；
- [ ] `F3`：`F2 + 时间覆盖/稳定性`；
- [ ] `F4`：完整特征但不校准；
- [ ] `F5`：完整特征并校准，作为候选最终选择器。

**门禁 G2：** 校准后 ECE/Brier 优于未校准版本，且证据分类不是只靠问题类型或视频 ID；否则只称“可靠性评分”，不称“任务不确定性”。

## 5. 阶段三：固定预算 64→32 证据选择

### 5.1 方法对照

- [ ] `T0 Raw32`：均匀 32 帧；
- [ ] `T1 MMR32`：冻结的旧自研时间选择器；
- [ ] `T2 VideoITG32`：冻结的公开强基线，复用已有缓存；
- [ ] `T3 Rel32`：校准证据概率 + 时间覆盖，不使用不确定性探索；
- [ ] `T4 Rel-U32`：可靠证据保底 + 高价值不确定证据探索；
- [ ] `T5 Penalty-U32`：把不确定性直接降权，仅作为反例对照。

### 5.2 核心消融

- [ ] `T4 - ASR`；
- [ ] `T4 - OCR`；
- [ ] `T4 - 时间覆盖`；
- [ ] `T4 - 不确定性探索`；
- [ ] `T4` 与旧 blur/downscale 退化敏感度对照。

### 5.3 证据指标

- [ ] Evidence Recall、Evidence Precision、Recall@32；
- [ ] 8-bin 覆盖、最大归一化时间空洞、重复帧率；
- [ ] ASR/OCR/Logo/价格/CTA 分类型召回；
- [ ] 不可定位问题的拒绝准确率；
- [ ] 选择器延迟、峰值显存和缓存读取开销。

**门禁 G3：** Evidence Recall 不低于 Raw32；Evidence Precision 至少比 Raw32 提高 4 个百分点；最大时间空洞明显低于旧 MMR32；关键证据类型无严重退化。未通过时不运行 Qwen。

## 6. 阶段四：动态局部细化

仅在 G3 通过后执行。

- [ ] 为 OCR、Logo、价格和 CTA 构建局部候选视图及精确 Token 成本；
- [ ] 预测局部细化的预期收益，只有“高相关且高不确定”区域才参与替换；
- [ ] 局部视图数量由收益和成本动态产生，不固定为 `24+8` 或 `16+16`；
- [ ] 保证总 submitted/represented views 与实际视觉 Token 和 Raw 对照一致；
- [ ] 比较 `Rel-U32`、`Rel-U + 动态细化`、历史固定 `24+8` 和无不确定性细化；
- [ ] 评估 Region Recall、文字可读率、时间 Evidence Recall 和实际 Token。

**门禁 G4：** Region Recall 提升，同时不降低时间 Evidence Recall；若只让响应图更尖锐但不提高区域命中，则停止局部细化。

## 7. 阶段五：Pilot50 Qwen 问答

仅对最少的四组运行 Qwen，避免重复烧卡：

- [ ] `Q0 Raw32`；
- [ ] `Q1 MMR32`；
- [ ] `Q2 Rel-U32`；
- [ ] `Q3 Rel-U + 动态细化`，仅 G4 通过时加入。

统一协议：Qwen3-VL-8B、32 个实际视图、11,664 Token、关闭二次采样、同一 ASR、Prompt 和生成参数。

- [ ] 完整视觉协议审计；
- [ ] 旧 Answer-only DeepSeek 同口径裁判；
- [ ] 人工复核所有胜负变化题；
- [ ] 10,000 次配对 Bootstrap；
- [ ] 分析 Strict、Relaxed、胜/平/负、`1→0` 和 `0→1`；
- [ ] 按视觉细节、叙事、品牌、价格/OCR、CTA、语音类型报告。

**门禁 G5：** 最终方法相对 Raw 的 Relaxed 均值不为负、Strict 不下降、严重 `1→0` 可解释；Pilot50 只作开发门禁，不作为最终证明。

## 9. 阶段七：鲁棒性与效率实验

- [ ] ASR 时间偏移扰动：固定正负偏移区间，测试声画错位鲁棒性；
- [ ] ASR 删除/无语音状态：验证模态缺失退化；
- [ ] OCR 模糊、遮挡和低对比扰动：验证拒绝与局部细化；
- [ ] 候选帧轻微缺失：验证时间覆盖稳定性；
- [ ] 比较 Raw、MMR 和最终方法的证据召回下降幅度；
- [ ] 报告离线预处理时间、在线选择器时间、Qwen 推理时间、峰值显存和实际视觉 Token；
- [ ] 区分一次性离线缓存成本与逐题在线推理成本。
