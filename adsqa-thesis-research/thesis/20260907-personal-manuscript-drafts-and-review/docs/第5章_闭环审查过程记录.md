可落地实验配置：
- 推荐实现路线：数据读取 → 视频采样 / ASR / OCR / 视觉标签 → 证据包构建 → 证据驱动 RAG → 多模态模型推理 → 声明级证据回溯校验 → 评测与消融。
- 推荐代码目录：/Users/bytedance/vqa_thesis_continue/code/
- 可迁移已有 RAG 原型：/Users/bytedance/vqa_thesis_continue/rag_mvp/rag_retriever.py
- 数据格式：JSONL，字段包括 sample_id、video_path、question、answer、task_type、metadata。
- 预处理输出：frames、timestamp、ASR segment、OCR bbox、confidence。
- 证据包字段：evidence_id、frame_id、timestamp、global_view、local_high_resolution_evidence_view、bbox_original、ASR、OCR、ad_evidence_types、scores。
- 视频采样参数：num_frames = 16 / 32 / 64，或 1fps / 2fps / 4fps。
- 关键帧选择：CLIP / SigLIP / Chinese-CLIP，query = question + ASR text + OCR text，topk 可先设为 8。
- 响应图近似实现：question patch similarity + ASR patch similarity + OCR bbox heatmap；若 patch-level CLIP 难实现，可先用 OCR bbox heatmap + global CLIP score。
- 锚框参数：scales = 0.4 / 0.6 / 0.8 / 1.0，rho = 1.0；第3章还建议加入多长宽比 1:1、2:1、3:1、4:1、1:2、1:3。
- RAG 参数：Top-K = 3 / 5；第4章原型默认 θ = 0.45、θ_E = 0.50、τ_E = 0.50、TopM = 5。
- 反思模块声明类型：visual_claim、ocr_claim、asr_claim、marketing_claim。
- 评价方式：优先使用 AdsQA 标准答案；生成式答案可用 semantic judge，但必须抽样人工复核 200-500 条，不应只依赖单个 LLM judge。

## 加强实验组合

1. 声画异步专项实验
   - 子集：audio-aligned、audio-leading、audio-lagging、audio-irrelevant、no-audio。
   - 方法：no ASR、ASR Prompt、Strict Align、Uniform Window、Gaussian Window、Proposed。
   - 指标：各子集 Accuracy、Overall、ASR 错配率、时间错位错误率。
   - 风险：需要人工标注或规则初筛后人工复核，否则只能写待补。

2. OCR/Logo/文字细节专项实验
   - 子任务：Text question、Logo question、Price/Number、Slogan、Brand recognition。
   - 方法：Base、Global only、Local only、Global + Local、OCR text prompt、Full。
   - 指标：子任务准确率、OCR 可读率、Logo 识别正确率、价格数字错误率。
   - 风险：Logo 检测难度较高，可先用 OCR + visual tags + MLLM 描述近似，但必须如实说明。

3. 参数敏感性实验
   - 关键帧 K：4 / 8 / 16。
   - 窗口半径 r：0s / 1s / 2s。
   - RAG Top-K：1 / 3 / 5。
   - 反思阈值：低 / 中 / 高。
   - 可扩展：局部视图 Top-m、锚框尺度、rho、R_g、R_l。
   - 指标：Accuracy、OCR/Logo 子集、幻觉率、Token、Latency。
   - 目的：证明方法不是只在单一参数下偶然有效。

4. 结构化推理消融
   - 设置：直接回答、常规自由式 CoT、观察—分析—答案、观察—知识匹配—分析—答案、证据状态 + evidence_id 约束。
   - 指标：Accuracy、证据引用正确率、营销概念误用率、过度推断率。
   - 目的：验证第4章“观察—知识匹配—分析—答案”不是普通 CoT Prompt。

5. 检索质量与证据匹配实验
   - 指标：Recall@K、MRR、证据匹配率、无关知识注入率。
   - 需要标签：问题对应相关知识条目、evidence_id 与 knowledge_id 人工匹配标签。
   - 风险：AdsQA 原始数据未必提供这些标签，必须人工构建子集。

6. LLM Judge 可靠性验证
   - 样本：建议 300-500 条。
   - 对比：人工评估、DeepSeek-V3 Judge、Qwen Judge。
   - 指标：与人工一致率、Cohen’s Kappa。
   - 附件要求：保留 Judge Prompt 和评分规则。
   - 风险：没有人工复核时，不能声称自动裁判可靠。

7. 错误归因统计
   - 类型：视觉误读、OCR 误读、Logo 误读、ASR 错配、时间错位、知识误用、过度推断、合规风险、反思误修正。
   - 指标：错误占比、Full 相对 Base 的错误减少项、反思导致的有害修正项。
   - 目的：支撑“可靠性提升”而不是只报告准确率。

8. 更多基线与跨数据集验证
   - 可加入：Qwen2-VL、Qwen2.5-VL、MiniCPM-V、LLaVA、Video-LLaVA、Video-ChatGPT。
   - 可尝试 VideoAds 相关任务作为补充背景或泛化验证。
   - 风险：必须确认模型可运行、输入格式一致、评估协议公平；不能只引用而不跑。

## 禁止直接写入正文的说法

- 禁止写“完全解决幻觉问题”“消除所有错误”“彻底突破现有方法”。
- 禁止写“显著降低 40% 推理时间”“大幅减少 Token”“显著降低显存”，除非已有真实 Token、Latency、Memory 数据。
- 禁止把未复现的 0.416、0.379、0.345 等阶段性主实验数值写成最终结果。
- 禁止把所有待补表格改写成已有结果。
- 禁止声称“AdsQA 五类任务划分已由原数据集提供”，除非复核数据集原始说明；否则应写“本文根据任务语义划分”。
- 禁止写“本文创新性地引入 RAG / CoT / Self-Reflection”。
- 应改为“本文基于证据包进行广告知识检索”“本文将推理过程约束为观察—知识匹配—分析—答案”“本文对答案声明进行证据回溯式链式反思”。
- 禁止将本文主线写成“视觉压缩 + RAG + CoT + Self-Reflection”。
- 应坚持“证据定位 → 证据压缩 → 证据解释 → 证据校验”。
- 禁止把视觉特征压缩写成简单 Token pruning、普通裁剪或普通均匀采样。
- 禁止把 ASR 写成“直接拼接 Prompt 即可提升”，第3章要求 ASR 邻域参与视觉定位。
- 禁止把 OCR/Logo 文本简单写成 Prompt 附加信息，必须强调其参与局部区域定位。

## A3 技术审查 Agent 输出

## 技术问题

1. **整体框架能覆盖第3章和第4章，但目前主要是实验设计，不是实验支撑**
   - 第5章已经围绕“证据定位 → 证据压缩 → 证据解释 → 证据校验”建立了较完整的实验框架。
   - 表5-17对第3章、第4章模块和实验章节的对应关系较全面。
   - 但除5.5阶段性主实验外，大多数表格均为“待补”，因此目前只能说明“计划如何验证”，还不能证明方法有效。

2. **模块一一对应关系基本成立，但若干关键模块没有被独立消融**
   - 高频过采样与语义关键帧优选在5.6中被同时打开，无法判断二者各自贡献。
   - 响应密度锚定没有单独与“随机锚定”“无锚定”“仅响应图不裁剪”对比。
   - 视听-文字时空响应图融合、动态融合权重、输入预算调度没有独立消融。
   - OCR/Logo响应、OCR文本Prompt、局部高分辨率视图三者的作用容易混淆。
   - 第4章中的 EvidenceScore、Allowed(K_i) 硬门控、证据感知重排序、观察—知识匹配—分析—答案协议尚未完全拆开验证。
   - 声明级反思中，“触发机制”“声明拆解”“证据回溯”“受控更新”也需要更细的消融，否则只能证明整体反思有效，不能证明声明级回溯机制有效。

3. **指标定义已有雏形，但还不够可执行**
   - Accuracy定义较宽泛，需要明确自动裁判Prompt、人工判定规则、二值化阈值和冲突处理规则。
   - 幻觉率需要定义“至少一处幻觉”的标注流程、标注员人数、一致性指标和复核机制。
   - Evidence Consistency需要说明声明拆解规则、声明粒度、证据支持判定标准、LOW_CONFIDENCE是否计入支持。
   - Knowledge Consistency需要明确知识库条目、相关性标注和营销概念使用正确性的判定规则。
   - Token压缩率需要明确视觉Token统计方式，因为不同多模态模型的图像Token与分辨率、patch策略、动态裁剪有关。
   - Latency和显存需要明确硬件、batch size、并发数、是否包含预处理、是否包含RAG和反思、是否使用缓存。
   - 缺少置信区间、显著性检验或bootstrap统计，最终结论容易不稳。

4. **视觉压缩验证路径是合理的，但目前还不能证明“压缩有效”**
   - 5.6、5.7、5.12可以支撑视觉压缩实验设计。
   - 但目前缺少实际视觉Token、总输入Token、帧数、局部视图数、Latency和Accuracy联动结果。
   - 局部高分辨率视图可能增加视觉Token，因此不能只用“裁剪面积变小”证明压缩。
   - 应增加“证据召回率”“关键帧命中率”“OCR区域命中率”“时间窗口命中率”等证据定位指标，否则仅靠QA Accuracy难以说明压缩过程保留了证据。

5. **证据驱动RAG验证设计合理，但实现条件缺失**
   - 5.10能够区分 no RAG、random RAG、generic RAG、marketing RAG、evidence-aware RAG，这是正确方向。
   - 但广告知识库来源、条目结构、embedding模型、检索器、重排序器、EvidenceScore公式、Allowed硬门控规则均未给出。
   - 检索质量表需要人工标注相关知识条目和 evidence_id—knowledge_id 对齐关系，目前没有标注方案细节。
   - 如果没有长度匹配控制，RAG提升可能来自Prompt变长，而不是证据驱动检索。

6. **声明级回溯校验实验设计正确，但还不能证明降低幻觉**

     - 修正成功率应以初始错误样本为分母；
     - 误修正率应以初始正确样本为分母；
     - 有害修正率应以触发反思样本或全部样本为分母，需要固定。
   - 声明拆解模型、声明类型判定、证据支持规则、CONFIRM/REVISE/REJECT/LOW_CONFIDENCE判定规则均需写清。
   - 当前不能写“链式反思降低幻觉率”，只能写“将通过该实验验证”。

7. **阶段性主实验存在数据编造或误读风险**

   - Qwen3-VL、LLaVA-OV、MiniCPM-V等引用状态未核查，正式论文中不能作为已确认文献基线直接使用。
   - 三位小数给人以高精度实验结果印象，但当前缺少复现实验信息，需谨慎。

## A4 创新性审查 Agent 输出

审查结论：第5章草稿已经具备防守“模块拼接”质疑的实验框架，但目前只能算“设计上可防守、证据上尚未闭环”。草稿已经覆盖普通RAG、随机/无关RAG、普通Self-Refine/开放式反思、Global/Local/Random Local、声画异步专项等关键对照；最大缺口是没有明确设置“AVAM/普通视觉锚定”或“通用视觉锚定”基线，导致第3章的“响应密度锚定”仍可能被质疑为普通视觉注意力/裁剪模块的再包装。此外，主实验的阶段性结果没有配套完整消融数值，仍不足以证明完整方法不是“视觉压缩 + RAG + Reflection”的串联叠加。

一、重点覆盖检查

| 审查点 | 草稿是否覆盖 | 风险判断 | 建议 |
|---|---|---|---|
| AVAM/普通视觉锚定对比 | 未充分覆盖 | 高风险 | 需要新增“普通视觉锚定 / question-only anchor / CLIP saliency anchor / AVAM-like anchor”对照 |
| 普通RAG对比 | 已覆盖 | 低风险 | 5.10 已有 generic RAG、marketing RAG、evidence permission RAG、evidence-aware RAG |
| 普通Self-Refine/普通反思对比 | 已覆盖 | 低风险 | 5.11 已有 Self-Refine baseline、open reflection、evidence-grounded reflection |
| 随机/无关RAG | 已覆盖 | 低风险 | 5.10 已有 random RAG、irrelevant RAG |
| Global/Local/Random Local | 已覆盖 | 低风险 | 5.7 已有 Global only、Local only、Global+Local、Random Local+Global、Oracle Local+Global |
| 声画异步专项 | 已覆盖 | 低风险 | 5.8 已单独设计 Aligned、Audio-leading、Audio-lagging、Audio-irrelevant、No-audio |
| 防守“模块拼接”整体逻辑 | 部分覆盖 | 中高风险 | 需要增加“简单拼接版本”与“证据闭环版本”的直接对比，以及模块交互收益分析 |

二、主要创新性风险

1. 缺少“普通视觉锚定 / AVAM-like”对比，响应密度锚定创新性不够稳

当前5.6和5.7主要比较了 KeyFrame、Q-Response、ASR、OCR、Global/Local、Random Local，但没有把本文的“响应密度锚定”同已有或通用的视觉锚定机制直接区分开。

容易被质疑为：

- 只是普通视觉注意力热图；
- 只是 CLIP 图文相似度裁剪；
- 只是把 OCR/ASR 分数加权后做区域裁剪；
- 只是 AVAM/视觉锚定模块的广告场景改写。

建议新增一组明确对照：

| 方法 | 说明 |
|---|---|
| Uniform crop | 固定中心裁剪或规则网格裁剪 |
| Random Local | 随机局部裁剪 |
| Question-only Anchor | 仅根据问题文本与视觉区域相似度选择局部区域 |
| CLIP Anchor | 使用 CLIP 图文相似度选择关键帧或区域 |
| OCR-box Anchor | 仅根据 OCR 检测框扩展生成局部视图 |
| ASR-guided Anchor | 仅用 ASR 文本召回相关时间窗口，不融合 OCR/视觉响应 |
| AVAM-like / Generic Visual Anchor | 普通视听注意力或通用视觉锚定方法，不使用广告证据类型、evidence_id 和声明级回溯 |
| Proposed Response Density Anchor | 本文方法：问题响应 + ASR邻域响应 + OCR/Logo文字显著性 + 证据类型 + 响应密度锚定 |

如果不方便引用 AVAM，建议写成“Generic visual anchoring baseline”或“AVAM-like baseline”，并说明“不依赖广告证据类型和声明级 evidence_id 接口”。如果正式使用 AVAM 名称，必须补充真实文献来源。

2. 主实验中的模块化对比可能反而强化“模块拼接”印象

5.5 当前主实验设置为：

- Base
- Base + evidence package
- Base + RAG
- Base + reflection
- Full / Ours

这个设计有价值，但也容易让审稿人理解为“就是逐个加模块”。如果没有补充“普通拼接版本”和“证据闭环版本”的差异，创新性论证会偏弱。

建议新增一张“拼接式增强 vs 证据闭环式增强”表：

| 设置 | 视觉输入 | 知识检索 | 反思方式 | evidence_id 是否贯穿 | 目的 |
|---|---|---|---|---|---|
| Naive concat | 均匀帧 + ASR/OCR文本拼接 | 无 | 无 | 否 | 验证不是简单堆输入 |
| Naive visual + RAG | 均匀帧 + 普通问题RAG | 问题驱动 | 无 | 否 | 验证不是普通RAG |
| Naive visual + Self-Refine | 均匀帧 + ASR/OCR文本 | 无 | 自由式反思 | 否 | 验证不是普通反思 |
| Modular pipeline | 视觉证据包 + 普通RAG + 普通反思 | 弱连接 | 自由式 | 部分 | 验证简单模块组合上限 |
| Evidence-closed loop / Ours | 证据包 | evidence-aware RAG | 声明级回溯 | 是 | 验证本文闭环机制 |

这样才能正面回答：“本文不是把视觉压缩、RAG、反思串起来，而是用 evidence_id 把证据定位、知识许可和声明校验绑定成闭环。”

3. RAG 消融设计较强，但需要强调“普通RAG”和“证据驱动RAG”的边界

## 四、表格层面的统一建议

建议全章统一以下格式：

1. 表题均加“阶段性 / 待补 / 待复核”状态；
2. 所有结果表增加“样本数N”或在表注说明；
3. “Overall”和“整体平均”统一为一个名称；
4. “Latency/ms”统一为“时延/ms”；
5. “Token”统一为“输入Token数”或“总输入Token数”；
6. “Full / Ours / Proposed / evidence-aware RAG”需要定义映射，避免读者认为是不同方法；
7. “-”需说明表示“不适用”，不是缺失值；
8. 所有“待补”最好细化为“待补：脚本统计”“待补：人工标注”“待补：运行实验”“待补：来源核查”。
