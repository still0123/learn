# 闭环多 Agent 论文写作编排方案

> 论文题目保持不变：**基于视觉特征压缩与链式反思的广告视频问答方法**  
> 工作目录：`/Users/bytedance/vqa_thesis_continue`  
> 目标：从“章节分工式 Agent”升级为“查资料—写作—审查—修改—定稿”的闭环多 Agent 工作流。

---

## 1. 为什么要改成闭环多 Agent

之前的 Agent 编排更像是：

```text
A1 写第2章
A2 写第3/4章
A3 写实验
A4 写答辩
```

这种方式能快速产出材料，但问题是：

1. 各 Agent 容易各写各的，主线不一定统一；
2. 写作 Agent 可能引用不准确或说法太泛；
3. 审查 Agent 没有明确介入修改闭环；
4. 论文容易变成“材料堆叠”，而不是反复打磨后的定稿；
5. 对“创新性够不够”“是否像模块拼接”这种核心风险，缺少持续质检。

因此，后续应改成闭环式多 Agent：

```text
资料 Agent → 写作 Agent → 审查 Agent → 修改 Agent → 主编 Agent
             ↑                                      ↓
             └──────────── 继续补资料 / 继续修改 ────┘
```

---

## 2. 闭环总流程

建议每一章或每一个任务都按以下流程执行：

```text
Step 1 资料检索 Agent
        ↓
Step 2 章节写作 Agent
        ↓
Step 3 技术审查 Agent
        ↓
Step 4 创新性审查 Agent
        ↓
Step 5 语言与结构审查 Agent
        ↓
Step 6 修改 Agent
        ↓
Step 7 主编 Agent 定稿
        ↓
若仍不合格 → 回到 Step 1 或 Step 2
```

这个流程的关键不是“多几个 Agent”，而是每个 Agent 有不同职责，并且后一个 Agent 会批判前一个 Agent 的输出。

---

## 3. Agent 角色设计

## A0 主编 Agent：总控与最终裁决

### 职责

- 维护论文总主线：证据定位 → 证据压缩 → 证据解释 → 证据校验；
- 决定每轮任务目标；
- 汇总各 Agent 输出；
- 判断是否进入下一轮修改；
- 最终输出可并入论文的版本。

### 输入

- 当前章节草稿；
- 资料 Agent 输出；
- 审查 Agent 意见；
- 修改 Agent 修订稿。

### 输出

- 定稿段落；
- 修改说明；
- 未解决问题清单；
- 下一轮任务指令。

### 判断标准

主编 Agent 必须检查：

1. 是否保持题目不变；
2. 是否围绕证据流主线；
3. 是否避免“RAG + CoT + Reflection 拼接”的表述；
4. 是否每个创新点都有实验支撑；
5. 是否存在无依据、夸大或不严谨表述。

---

## A1 资料检索 Agent：查文献、查开题、查专利、查实验依据

### 职责

- 查找当前章节需要的资料；
- 对比已有方法，例如 AdsQA、VideoAds、AVAM、RAG、Self-Refine、CoT、VideoQA；
- 提取可引用观点；
- 标记需要核查的引用；
- 提醒哪些说法可能没有依据。

### 输入

- 当前章节主题；
- 已有开题报告；
- 专利正文；
- 审查意见；
- 已生成论文骨架；
- 需要补的引用方向。

### 输出格式

```text
## 可用资料
- 资料1：主题、可用观点、适合放在哪一节
- 资料2：主题、可用观点、适合放在哪一节

## 与本文差异
- 与 AVAM 的差异
- 与普通 RAG 的差异
- 与 Self-Refine 的差异

## 风险提示
- 哪些引用需要核查
- 哪些说法可能过强
- 哪些地方缺少实验支撑
```

### 注意

资料 Agent 不负责写正文，只负责提供可靠材料和风险提示。

---

## A2 章节写作 Agent：根据资料写初稿

### 职责

- 根据主编要求和资料 Agent 输出，写章节初稿；
- 保持论文语气；
- 按硕士论文风格组织段落；
- 不凭空编实验数据；
- 对没有数据的地方写“待补”或使用模板式分析。

### 输入

- 当前任务目标；
- 主线要求；
- 资料 Agent 输出；
- 已有章节上下文。

### 输出格式

```text
## 本轮写作内容
正文段落……

## 写作说明
- 使用了哪些资料
- 哪些地方需要后续补数据
- 哪些地方需要主编确认
```

### 写作要求

1. 不改论文题目；
2. 不把创新点写成 RAG、CoT、Reflection 的简单组合；
3. 每个方法描述都要落到“证据定位/证据压缩/证据解释/证据校验”；
4. 实验结果不能编造；
5. 所有阶段性结果必须标注为阶段性或待复核。

---

## A3 技术审查 Agent：查方法是否站得住

### 职责

- 审查章节中的技术逻辑；
- 检查公式、流程、输入输出是否一致；
- 检查是否存在概念混乱；
- 检查“视觉压缩”是否真的被定义清楚；
- 检查“链式反思”是否只是 Prompt；
- 检查实验是否能支撑方法。

### 输入

- 写作 Agent 初稿；
- 当前方法章节；
- 实验设计。

### 输出格式

```text
## 技术问题
1. 问题：……
   影响：……
   修改建议：……

## 必须修改
- ...

## 可选优化
- ...

## 是否通过
通过 / 不通过
```

### 审查重点

- 证据包是否贯穿第 3、4、5 章；
- 第 3 章输出是否能被第 4 章使用；
- 第 4 章校验是否能回查第 3 章证据；
- 第 5 章实验是否能证明第 3、4 章模块；
- 压缩率、Token、Latency 是否定义明确。

---

## A4 创新性审查 Agent：专门防“模块拼接”

### 职责

- 从评委/审查员视角判断创新性；
- 检查是否像已有技术组合；
- 检查与 AVAM、普通 RAG、CoT、Self-Refine 的差异是否清楚；
- 检查创新点是否过度包装；
- 给出更稳的创新表述。

### 输入

- 写作 Agent 初稿；
- 技术审查 Agent 意见；
- 开题专利创新性诊断报告。

### 输出格式

```text
## 创新性风险
1. 风险：……
   为什么像已有方法：……
   如何改写：……

## 建议强化表述
- 原句：……
- 改成：……

## 答辩可能被问
- 问题1：……
- 建议回答：……
```

### 审查标准

该 Agent 必须持续追问：

1. 这是不是只是 AVAM + ASR？
2. 这是不是只是 RAG 换了一个知识库？
3. 这是不是只是 CoT Prompt？
4. 这是不是只是 Self-Reflection？
5. 这是不是只是通用视频问答套到广告场景？
6. 每个创新点有没有专项实验支撑？

---

## A5 语言结构审查 Agent：论文表达和章节结构

### 职责

- 检查论文语言是否正式；
- 检查段落是否重复；
- 检查章节衔接是否自然；
- 检查术语是否统一；
- 检查是否存在口语化、夸大或不严谨表达；
- 检查图表引用和章节编号。

### 输入

- 写作 Agent 初稿；
- 技术审查意见；
- 创新性审查意见。

### 输出格式

```text
## 语言问题
- ...

## 结构问题
- ...

## 术语统一建议
- 原术语：……
- 建议统一为：……

## 修改建议
- ...
```

### 统一术语

建议统一使用：

| 不建议混用 | 建议统一 |
|---|---|
| 链式反思 / 链式校验 / 自我反思 | 链式反思；具体机制称为证据回溯式校验 |
| Token 压缩 / 视觉压缩 / 特征压缩 | 视觉特征压缩；具体解释为证据保留型视觉输入重构 |
| RAG / 知识增强 / 专家上下文 | 证据驱动广告知识检索 |
| 响应图 / 热力图 / 注意力图 | 视听-文字时空响应图 |
| 裁剪区域 / 局部图 / ROI | 局部高分辨率证据视图 |

## A6 修改 Agent：根据审查意见重写

### 职责

- 汇总 A3、A4、A5 的意见；
- 修改写作 Agent 的初稿；
- 保留合理内容，删除风险表述；
- 对每条修改说明原因；
- 输出修订稿。

### 输入

- 写作 Agent 初稿；
- 技术审查意见；
- 创新性审查意见；
- 语言结构审查意见。

### 输出格式

```text
## 修订稿
正文……

## 修改说明
1. 修改了……，原因是……
2. 删除了……，原因是……
3. 增加了……，原因是……

## 仍需补充
- ...
```

### 职责

- 根据第 5 章实验执行清单跑实验；
- 填表；
- 记录配置；
- 不编造数据；
- 对失败实验如实记录。

### 输入

- 实验脚本；
- 数据集；
- 模型配置；
- 第 5 章实验表。

### 输出格式

```text
## 实验配置
- 数据集：……
- 模型：……
- 参数：……

## 实验结果
表格……

## 观察
- ...

## 异常或失败
- ...
```

### 注意

如果没有真实数据，实验执行 Agent 只能输出：

```text
待运行 / 缺少数据 / 缺少脚本 / 缺少模型输出
```

不能编造数值。

## A8 答辩防守 Agent：准备问答和风险防守

### 职责

- 审查意见。

## 4. 闭环运行方式

## 4.1 单章节闭环

适合改某一章，例如第 3 章。

```text
A0 主编提出任务：重写第3章 3.4 视听-文字响应图
        ↓
A1 资料 Agent 查 AVAM、ASR、OCR、声画异步相关资料
        ↓
A2 写作 Agent 写 3.4 初稿
        ↓
A3 技术审查 Agent 检查公式和流程
        ↓
A4 创新性审查 Agent 检查是否像 AVAM 简单改造
        ↓
A5 语言结构 Agent 检查表达
        ↓
A6 修改 Agent 输出修订稿
        ↓
A0 主编判断是否通过
```

如果不通过：

```text
回到 A1 补资料 或 A2 重写
```

---

## 4.2 整章闭环

适合整章定稿，例如第 5 章实验。

```text
A1 查同类论文实验设计
A2 写第5章实验初稿
A3 检查实验是否支撑方法
A4 检查实验是否能防模块拼接质疑
A5 检查语言和表格结构
A6 修改
A7 若有条件则跑实验填数据
A0 定稿
```

---

## 4.3 全文闭环

适合最终论文定稿。

```text
A0 主编拆分任务
        ↓
第1章闭环
第2章闭环
第3章闭环
第4章闭环
第5章闭环
第6章闭环
        ↓
A5 全文语言结构审查
        ↓
A4 全文创新性审查
        ↓
A3 全文技术一致性审查
        ↓
A6 全文修改
        ↓
A8 答辩防守
        ↓
A0 最终定稿
```

## 5. 每轮闭环的通过标准

每轮修改后，主编 Agent 按以下标准判断是否通过：

| 检查项 | 通过标准 |
|---|---|
| 题目一致 | 不修改题目 |
| 主线一致 | 始终围绕证据定位—证据压缩—证据解释—证据校验 |
| 创新性 | 不写成 RAG + CoT + Reflection 拼接 |
| 技术完整 | 输入、处理、输出明确 |
| 实验支撑 | 每个创新点至少有一个实验对应 |
| 表述严谨 | 不夸大、不编造、不说“完全解决” |
| 数据真实 | 没有真实实验则标记待补 |
| 章节衔接 | 第3章输出能被第4章使用，第5章能验证第3/4章 |

## 8. 总结

闭环多 Agent 不是简单“多个 Agent 分头写”，而是：

```text
一个查资料
一个写
一个审技术
一个审创新
一个审语言结构
一个根据意见修改
一个主编定稿
```

这样才能形成论文打磨闭环，尤其适合当前这个题目，因为它最大的风险不是写不出来，而是容易被认为是已有模块拼接。闭环多 Agent 的核心目标就是不断消除这个风险。
