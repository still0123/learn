## 与已有方法差异

- 与 AVAM 的差异
  - AVAM 的核心更接近文本/问题引导的视觉锚定，用于多图或图像问答中的自适应视觉区域选择。
  - 第3章不能只说“参考 AVAM 做视频裁剪”，而要强调本文面向广告视频，证据定位信号不是单一文本问题，而是“用户问题 + 邻域 ASR + OCR/Logo 文字显著性”的联合响应。
  - AVAM 侧重空间视觉锚定；第3章应突出“时空证据锚定”：ASR 带时间戳，关键帧有时间戳，语音邻域窗口允许画外音提前或滞后于画面。
  - AVAM 输出可以被理解为视觉局部区域；第3章输出应定义为可追溯证据包，包含 frame_id、timestamp、bbox、ASR 片段、OCR 文本、响应分数，供第4章回溯校验使用。
  - 因此差异表述应落在“声画异步广告视频中的视听-文字协同证据定位”，而不是“把 AVAM 加了 ASR”。

- 与普通视觉锚定/普通 ROI 裁剪的差异
  - 普通 ROI 裁剪通常依赖检测框、显著性图、Grad-CAM 或问题相关热力图，目标是找到图像中的关注区域。
  - 第3章应强调 ROI 不是最终目标，局部裁剪只是证据保留型输入重构的一部分。
  - 本文的局部区域由综合响应图驱动，响应来源包括问题语义、邻域 ASR 语义、OCR/Logo 显著性，而不是单纯视觉显著或检测框。
  - 本文同时保留全局视图，避免局部裁剪导致广告场景、人物关系、情绪氛围丢失。
  - 本文还记录坐标、时间戳和模态来源，使局部视图可以被后续推理和反思引用；普通 ROI 裁剪通常不强调这种跨章节证据追踪。

- 与普通 ASR Prompt 的差异
  - 普通 ASR Prompt 是把整段语音转写文本直接拼到多模态模型输入中，ASR 只作为全局文本上下文。
  - 第3章应强调 ASR 是主动定位信号：根据关键帧时间戳构建邻域窗口，对窗口内 ASR 片段进行高斯加权聚合，再参与视觉空间响应图计算。
  - 普通 ASR Prompt 无法说明某句旁白对应哪一帧、哪一区域；本文应将 ASR 片段与 frame_id、timestamp、bbox 绑定进证据包。
  - 普通 ASR Prompt 对声画异步无显式处理；本文通过 audio-leading、audio-lagging 的时间邻域建模缓解错配。

- 与普通均匀采样/CLIP Top-K 的差异
  - 均匀采样只解决“取哪些帧”，无法保证短时 Logo、价格、字幕和产品包装细节被保留。
  - CLIP Top-K 只做帧级语义相关性排序，仍可能选中语义相关但局部细节不可见的全局帧。
  - 第3章应把高频过采样 + 语义 Top-K 定位为“候选证据召回”，而不是完整创新点。
  - 真正差异应放在 Top-K 之后：在关键帧内部构建视听-文字时空响应图，并基于响应密度生成局部高分辨率证据视图。
  - 换言之，CLIP Top-K 是帧级筛选，本文方法是“帧级召回 + 区域级证据重构 + 证据包追踪”。

## 第3章风险提示

1. 容易被质疑为“AVAM + ASR”
   - 当前第3章中的问题响应图、ASR 响应图、OCR 响应图、语义重心、多尺度锚框、局部裁剪，与已有视觉锚定方法形式上很接近。
   - 如果只写“在 AVAM 上加 ASR 和 OCR”，创新性会显得偏弱。
   - 必须把差异落到“广告视频声画异步 + 短时文字/Logo + 证据包追踪”上，并用专项实验支撑。

2. 容易被质疑为普通 ROI 裁剪
   - 响应图求重心、生成多尺度框、选响应密度最高区域，这些步骤可能被认为是常规热力图 ROI 提取。
   - 专利审查意见已经明确指出，热力图定位、语义中心、锚框、ROI 裁剪都可能被视为常规技术选择。
   - 第3章需要避免把“裁剪”写成创新本身，应把创新落到“证据保留型输入重构”和“多模态证据包”。

3. “压缩”概念仍有被追问风险
   - 当前方法同时输入全局图和局部图，如果两者都调整到高分辨率，实际视觉 Token 可能不降反升。
   - `CR_area = 1 - Area(B*) / Area(f_t)` 只能说明局部区域面积小，并不能证明整体模型输入 Token 下降。
   - 若题目中使用“视觉特征压缩”，第3章必须明确压缩基准：相对全量帧、相对过采样帧、相对全帧高分辨率输入，还是相对视觉 Token 总量。

4. ASR 分支可能被质疑只是 Prompt 变体
   - 如果实验中没有比较“ASR Prompt”和“ASR 邻域响应图”，评委可能认为 ASR 只是换了输入位置。
   - 如果时序窗口半径、权重 σ、音频无关场景没有消融，声画异步贡献难以成立。

5. OCR/Logo 分支技术表达可能不够实
   - 当前第3章部分表述使用 `text/logo/brand/price` 等关键词构建响应，如果没有真实 OCR 框、Logo 检测框或置信度，容易被认为只是关键词 Prompt。
   - 需要说明 OCR/Logo 是检测结果、文字框、置信度、语义类别，还是纯文本先验；不同实现创新强度不同。

6. “可学习投影矩阵”与“免训练/冻结模型”可能冲突
   - 第3章公式中出现 `W_v, W_q, W_a, W_c` 等映射矩阵。
   - 如果方法是 training-free 或主要依赖 CLIP/Qwen 冻结推理，就不宜写成“可学习投影矩阵”，除非说明训练方式、训练数据和参数更新范围。
   - 建议统一为“线性投影/语义映射”或明确“在验证集上固定/由预训练模型提供”。

7. 第3章与第4章衔接必须真实
   - 第3章说输出证据包供第4章知识检索和链式反思使用。
   - 如果第4章实际只使用全局图、局部图和拼接文本，而没有引用 frame_id、bbox、ASR window、OCR text，则“证据包”会变成概念包装。
   - 必须确保第4章和第5章实验能回查第3章证据字段。

8. 外部文献和实验数字需要核查
   - 开题和专利中出现 AdsQA、VideoAds、AVAM、DeepSeek-V3 Judge、Qwen3-VL、0.416/0.379 等说法。
   - 写第3章方法时可引用其问题背景，但论文正文中的数据、模型名称、会议年份、指标解释应逐项核查，避免被认为引用不严谨或实验不可复现。

## 第3章强化建议

1. 强化核心定义
   - 建议第3章开头明确写：
     - “本文所称视觉特征压缩，不是单纯 Token pruning 或帧数减少，而是在固定视觉输入预算下，对广告视频视觉输入进行证据保留型重构。”
     - “压缩对象包括帧级冗余、空间区域冗余和无关模态上下文；保留对象是与问题回答相关的视觉、文字、语音证据。”
   - 建议把第3章目标定义为：
     - 最大化证据保留率；
     - 最小化无关视觉输入；
     - 保持证据可追溯。

2. 强化技术链条表达
   - 把第3章分成三个层次写清楚：
     1. 候选证据召回：高频过采样 + 语义关键帧优选；
     2. 证据区域定位：问题响应 + ASR 邻域响应 + OCR/Logo 响应；
     3. 证据输入重构：响应密度局部视图 + 全局语境视图 + 证据包。
   - 不建议把“过采样、Top-K、裁剪、拼接”并列写成模块列表，应写成“证据召回—证据定位—证据重构”的因果链。

3. 强化 ASR 声画异步机制
   - 明确 ASR 不只是文本输入，而是参与视觉定位：
     - ASR 片段带时间戳；
     - 每个关键帧建立时间邻域窗口；
     - 使用高斯权重降低远距离语音影响；
     - 输出与当前帧绑定的 ASR 响应图。
   - 增加异常处理表述：
     - ASR 置信度低时降低 β；
     - 背景音乐或无关旁白时降低 ASR 权重；
     - no-audio 场景退化为问题 + OCR/Logo 响应。

4. 强化 OCR/Logo 分支
   - 建议将 OCR/Logo 响应分成两类：
     - 检测型证据：OCR 框、Logo 框、品牌文字、价格数字、置信度；
     - 语义型先验：text、logo、brand、price、discount、number、slogan 等关键词。
   - 若有 OCR 框，应把框内响应显式加权，而不是只用关键词相似度。
   - 证据包中应保留 OCR 原文、位置、置信度和来源帧。

5. 强化局部锚定不是普通 ROI
   - 在响应密度公式后增加解释：
     - 不选择响应总能量最大框，避免大框天然占优；
     - 使用面积惩罚控制局部视图粒度；
     - 使用 Top-m + NMS 处理多峰证据，避免单一重心漏掉价格和 Logo 分处两端的情况。
   - 建议默认写 Top-1 为预算受限配置，Top-m 为扩展配置，并在实验中比较。

6. 强化压缩率定义
   - 至少报告四类指标：
     - 帧数压缩率：过采样帧 S 到关键帧 K；
     - 空间面积比例：局部 crop 面积占原图比例；
     - 视觉 Token 数：压缩前后视觉 Token；
     - 系统效率：总输入 Token、推理延迟、显存。
   - 注意不要只用局部面积证明整体压缩，因为全局图仍然被输入。
   - 推荐对比基准：
     - full frames；
     - uniform sampling；
     - CLIP Top-K；
     - global-only；
     - global + random local；
     - global + proposed local。

7. 必补实验支撑
   - 视觉定位消融：
     - KeyFrame only；
     - Q-response；
     - Q + ASR；
     - Q + ASR + temporal window；
     - Q + ASR + OCR/Logo；

   - 与 ASR Prompt 对比：
     - no ASR；

     - Gaussian temporal window；
     - proposed full response map。
   - 与 AVAM/普通锚定对比：
     - AVAM-like Q-only anchor；
     - Grad-CAM/heatmap ROI；

     - CLIP Top-K + global；

   - Global/Local 双流实验：
     - Global only；

   - OCR/Logo 细节实验：
     - Text question；

   - 效率实验：
     - 帧数；

8. 建议第3章答辩口径
   - “第3章不是 AVAM + ASR。AVAM 主要解决图像/多图场景中的文本引导视觉锚定；本文面向广告视频，关键问题是短时文字/Logo 证据和声画异步。ASR 在本文中不是 Prompt 文本，而是带时间邻域的视觉定位信号；OCR/Logo 也不是附加文本，而是局部证据响应来源。最终输出不是 ROI 图像，而是可被第4章推理和反思回查的证据包。”
   - “第3章的视觉压缩不是单纯把图裁小，而是在有限输入预算下重构视觉输入：保留全局语境，提升局部证据分辨率，并记录证据来源，使后续答案可以被帧、区域、ASR 和 OCR 回溯支撑。”



## A3 技术审查 Agent 输出

技术问题：

1. 视觉压缩定义总体清楚，但尚未完全形式化  
   当前已经把“视觉特征压缩”界定为“证据保留型视觉输入重构”，比单纯裁剪或降帧更准确。但仍缺少一个明确的压缩算子和预算约束，例如：
   `C(V, q, A, O; B_budget) -> E`
   以及视觉 Token、文本 Token、局部视图数量、全局视图分辨率之间的预算关系。否则后续实验很难证明“压缩有效”，只能证明“做了证据裁剪”。

2. 符号存在冲突和不一致  
   - `E = {E_1, ..., E_K}` 中的 `K` 与 Top-K 关键帧的 `K` 冲突，建议区分为 `K_f` 关键帧数和 `K_e` 证据单元数。  
   - 原视频用 `I_t`，候选帧用 `f_s`，关键帧又写 `f_t`，但 `t` 有时表示时间步、有时表示关键帧索引，需要统一。  
   - `τ_t` 未明确定义，应说明其是关键帧时间戳。  
   - `O_t = {(...) | τ_l = τ_t}` 使用严格时间相等不合理，OCR/Logo 检测应绑定 `frame_id`，或使用时间容差 `|τ_l - τ_t| <= δ`。

3. 响应图坐标系没有对齐  
   `X_t ∈ R^{H × W × d}` 是特征图坐标，而 `b_l`、`B_s`、`W_img`、`H_img` 是原图像素坐标。当前公式直接写 `(i,j) ∈ b_l`、`(i,j) ∈ B_s`，技术上不自洽。必须定义从原图到特征图的映射：
   `Π_img→feat(b_l)`、`Π_img→feat(B_s)`，或统一所有响应密度计算都在原图尺度完成。

4. 响应图归一化逻辑不完全自洽  
   `H_Q` 和 `H_A` 使用空间 softmax，整体和为 1；`H_D` 是检测框置信度最大值；`H_S` 是多个 softmax 后取 max，整体和可能大于 1；`H_O` 又混合 `Norm(H_D)` 和 `H_S`。三类响应图数值尺度不同，直接加权融合会导致某一分支支配结果。  
   必须统一定义 `Norm()`，并保证融合前 `H_Q`、`H_A`、`H_O` 处于可比尺度。

5. `H_S` 的广告文字语义先验可能产生弱定位或伪定位  
   使用 `{text, logo, brand, price, discount...}` 与视觉 patch 做相似度，并不一定能可靠定位 Logo 或价格区域，尤其在普通 CLIP/SigLIP patch 特征上，“price”“coupon”这类抽象词未必有稳定空间响应。该分支只能作为弱先验，不能被描述成可靠检测证据。证据包中必须明确区分：
   - 检测证据；
   - OCR 识别证据；
   - Logo 检测证据；
   - 语义先验证据。

6. ASR 邻域响应公式需要补充分母为零和低置信场景  
   `u_A(t)` 的分母可能为 0，例如窗口为空、ASR 置信度全低或被过滤。虽然文字中说会降权，但公式需要显式处理：
   - 若 `Σ g(t,m)c_m^a < ε`，则设置 `β_t = 0` 或 `H_A = 0`；
   - 否则再计算 ASR 聚合表示。

7. 帧级召回的 ASR 使用“全局 ASR 摘要”与后续声画异步建模不一致  
   `Score_frame(f_s)` 中使用 `u_a` 作为全局 ASR 摘要，可能让所有帧都受到同一语音摘要影响，弱化时间定位。建议帧级召回阶段也使用局部 ASR 窗口 `u_A(s)`，或同时保留全局 ASR 与局部 ASR 两项。

8. 响应密度锚定存在偏向小框或大框的问题，但缺少约束  
   `D(B_s) = Σ H / Area(B_s)^ρ` 合理，但需要补充：
   - 最小框面积；
   - 最大框面积；
   - 上下文扩展比例；
   - ρ 的取值依据；
   - 当框被边界裁剪后如何计算面积；
   - 响应图坐标面积还是原图面积。  
   否则在 `ρ ≥ 1` 时容易过度偏向小框，导致字幕单位、价格上下文、Logo 附近品牌名被裁掉。

9. 多尺度锚框只使用等比例缩放，不适合广告字幕和价格条  
   当前 `w_s = s · W_img, h_s = s · H_img` 只生成与原图同宽高比的框。广告视频常见证据包括底部字幕、横幅价格条、角标 Logo、竖向包装文字，需要加入不同长宽比锚框，例如：
   - 宽横条：`2:1`、`3:1`、`4:1`；
   - 小方框：`1:1`；
   - 竖框：`1:2`；
   - 检测框扩展锚框：以 OCR/Logo 框为中心扩展。

10. “视听-文字时空响应图”目前更像“带时间戳的空间响应图”

## 一、核心审查意见

### 1. “是否只是 AVAM + ASR/OCR？”

高风险。

当前写法中，“问题响应图 + ASR 邻域响应图 + OCR/Logo 响应图 + 加权融合”的形式非常容易被认为是已有文本引导视觉锚定或 AVAM 类方法的直接扩展。尤其是以下部分：

```text
H(t,i,j)
= α_t · H_Q(t,i,j)
+ β_t · H_A(t,i,j)
+ γ_t · H_O(t,i,j)
```

这种线性融合非常常见，创新性较弱。评委可能会问：

- AVAM 已经能用文本引导视觉区域定位，你只是把 ASR 文本也编码成一个文本向量了吗？
- OCR/Logo 响应图是不是只是多加了一个显著性 mask？
- ASR 邻域窗口是不是只是把视频附近语音当作额外 prompt？
- 加权融合的权重如何确定？如果是人工规则，是否只是工程规则组合？

#### 建议改写方向

不要把创新重点放在“三个响应图相加”，而要突出“声画异步下的时空证据绑定机制”和“广告证据类型驱动的输入重构”。

建议把 3.4.5 改为：

> 本文并非将 ASR、OCR/Logo 作为额外文本与用户问题简单拼接，而是将其转化为与关键帧时间戳、空间位置和广告证据类型绑定的响应约束。具体而言，ASR 分支只使用当前帧的时间邻域片段，并根据声画异步距离、ASR 置信度和问题类型动态调整贡献；OCR/Logo 分支不仅提供识别文本，还通过检测框、类型标签和置信度改变局部区域的响应密度。最终响应图不是通用注意力热图，而是用于后续局部视图生成和证据包构建的时空证据选择函数。

还应增加一个“与 AVAM 的操作级差异表”，例如：

| 维度 | AVAM/普通文本引导锚定 | 本章方法 |
|---|---|---|
| 输入文本 | 单一问题或描述 | 问题 + 时间邻域 ASR + OCR/Logo 类型证据 |
| 时间建模 | 通常无显式时间绑定 | 每个关键帧绑定 ASR 邻域、OCR 时间戳和帧时间戳 |
| 空间线索 | 文本-视觉相似度 | 文本相似度 + 检测框响应 + 广告类型权重 |
| 输出 | 注意力区域或裁剪图 | 带 frame_id、timestamp、bbox、ASR window、OCR/Logo、score 的证据包 |
| 目标 | 定位相关区域 | 在输入预算下重构可追溯问答证据 |

但注意：仅有表格还不够，必须在方法上把“证据包如何影响后续推理”讲清楚。

### 2. “是否只是普通视觉锚定/ROI 裁剪？”

中高风险。

目前 3.5 的“语义重心、多尺度锚框、响应密度、Top-m、NMS”与已有 ROI 选择、attention crop、saliency crop、dense caption grounding 等方法非常接近。尤其是：

```text
D(B_s)
= Σ H(t,i,j) / Area(B_s)^ρ
```

这本质上是基于热力图的区域打分，评委可能认为是普通 ROI 裁剪。

当前草稿虽然反复强调“不是普通 ROI”，但理由主要是：

- 同时保留全局视图；
- 输出证据包；
- 记录坐标、时间戳、ASR、OCR；
- 后续可以追溯。

这些属于系统组织层面的差异，不一定足以构成方法创新。

#### 建议改写方向

把“局部裁剪”改写成“预算约束下的证据保留型视觉重构”。即，不要只说选一个 ROI，而要明确优化目标是：在固定视觉 Token 预算下，同时最大化证据覆盖、模态多样性、时间多样性和局部可读性。

建议在 3.5 或 3.6 增加一个预算化目标函数：

```text
max  Σ EvidenceScore(E_k)
     + λ_1 · Coverage(E)
     + λ_2 · ModalityDiversity(E)
     + λ_3 · TemporalDiversity(E)
     - λ_4 · TokenCost(E)

s.t. TokenCost(E) ≤ B
```

其中：

- `EvidenceScore(E_k)`：问题、ASR、OCR/Logo 的综合响应；
- `Coverage(E)`：是否覆盖价格、Logo、字幕、人物动作等关键证据；
- `ModalityDiversity(E)`：避免只选视觉区域，忽略 ASR 或 OCR；
- `TemporalDiversity(E)`：避免 Top-K 帧集中在同一镜头；
- `TokenCost(E)`：全局视图和局部视图的视觉 Token 成本。

这样才能把方法从“裁剪 ROI”提升为“输入预算下的证据选择与重构”。

建议将 3.5.1 改为：

> 本节的目标不是从热力图中裁剪一个高响应区域，而是在固定视觉输入预算下，选择一组能够最大化问答证据保留率的局部视图。与普通 ROI 裁剪不同，本文的候选区域选择同时受到四类约束：问题相关性、广告证据类型、声画时间邻域和视觉 Token 成本。局部视图只有在其能够提升证据可读性或补充全局视图缺失信息时才被保留。

---

### 3. “是否只是 ASR Prompt？”

中高风险。

草稿已经多次强调 ASR 不是简单拼接到 Prompt，而是转化为空间响应信号。但实际公式中：

```text
u_A(t) = weighted sum of Enc(a_m)
H_A(t,i,j) = sim(z^v, φ_a(u_A(t)))
```

这仍然容易被理解为“把邻域 ASR 编码成文本向量，然后做文本-视觉相似度”，与 ASR Prompt 的区别不够硬。

评委可能问：

- 如果我把邻域 ASR 直接放进 Prompt，再让 VLM 自己看图，不也能做到吗？
- 你的 ASR 分支是否真的改变了视觉输入？还是只是影响了描述？
- ASR 与视觉区域之间的定位关系如何建立？语音里说“限时优惠”，为什么就能定位到底部价格标签？

#### 建议改写方向

必须强调 ASR 的作用是“前置视觉输入选择”，而不是“后置语言提示”。建议明确区分两种路径：

```text
普通 ASR Prompt:
完整视频帧 + ASR 文本 → VLM → 答案

本文:
ASR 时间邻域 → 帧级筛选/区域响应/局部视图生成 → 证据包 → VLM → 答案
```

建议在 3.3.1 或 3.4.3 增加：

> ASR 在本文中不作为回答阶段的完整文本上下文直接堆叠，而是作为视觉证据选择阶段的控制信号。也就是说，在进入问答模型之前，ASR 已经参与决定“哪些帧被保留、哪些区域被放大、哪些 OCR/Logo 检测结果被关联到当前问题”。因此，即使后续问答模型只接收证据包而非完整 ASR，ASR 仍已经通过视觉输入重构影响了模型可见的信息范围。

还建议增加一个消融实验设计：

| 设置 | 描述 | 用于证明 |
|---|---|---|
| Full ASR Prompt | 全部 ASR 拼接到 Prompt | 普通 ASR Prompt 基线 |
| Local ASR Prompt | 只拼接邻域 ASR，不参与视觉选择 | 排除“只是截短 Prompt” |
| ASR-Guided Visual Selection | ASR 参与帧/区域选择，但不作为长文本输入 | 证明 ASR 改变视觉输入 |
| Ours Full | ASR + OCR/Logo + 证据包 | 完整方法效果 |

如果没有这个消融，评委很容易认为 ASR 分支只是 prompt engineering。

---

### 4. “是否只是广告场景套用？”

中高风险。

当前广告特征主要体现在文字描述中，例如“价格、Logo、品牌、促销、口号、产品包装”等。但方法层面仍然是通用视频问答框架：

```text
高频采样 → 关键帧选择 → 响应图 → ROI → 全局/局部输入
```

这些步骤换成医疗视频、教学视频、电商直播、新闻视频也基本成立。因此，评委可能质疑：

- 你的方法是否真的依赖广告视频特有结构？
- 价格、Logo、字幕只是 OCR 类型标签，换个领域也能用。
- “广告视频问答”是不是只是应用场景，没有形成领域方法？

#### 建议改写方向

需要引入更强的“广告证据类型体系”和“问题类型驱动策略”。例如将广告问答拆为几类：

1. 品牌识别类：品牌名、Logo、包装；
2. 价格促销类：价格、折扣、优惠券、活动规则；
3. 功能卖点类：功效、使用效果、对比前后；
4. 可信背书类：认证标识、专家、奖项、用户评价；
5. 目标受众类：人物身份、使用场景、年龄/职业/肤质等；
6. 行动转化类：购买入口、扫码、限时、立即下单；
7. 合规声明类：小字免责声明、适用条件、限制条款。

然后说明不同问题类型触发不同证据策略。例如：

| 问题类型 | 主要证据 | 空间策略 | 时间策略 |
|---|---|---|---|
| 价格促销 | 数字、折扣、券、活动规则 | 优先底部/角落文字区域、小尺度局部视图 | 高频保留短时字幕 |
| 品牌识别 | Logo、包装、品牌字幕 | Logo/包装检测框加权 | 重复出现帧去重 |
| 功能卖点 | 产品动作、使用效果、旁白 | 全局动作 + 局部产品区域 | 允许 ASR 前后偏移 |
| 可信背书 | 认证标识、专家、机构名 | OCR/Logo/人物区域联合 | 关联旁白解释 |
| 合规声明 | 小字条款、限制条件 | 高分辨率文字区域优先 | 保留短时底部小字 |

建议在 3.4.5 的权重自适应部分不要只写“当问题涉及价格就提高 γ”，而应写成“广告问题类型识别—证据类型映射—响应权重调整”的机制。

可增加公式：

```text
p = AdQuestionType(q)

(α_t, β_t, γ_t, ρ, m)
= Policy(p, Conf_ASR(t), Conf_OCR(t), TokenBudget)
```

这样广告场景不再只是“换个数据集”，而是成为方法中的显式先验。

## 二、逐节具体改写建议

### 3.1 引言

优点：问题背景讲得较完整，已经强调广告视频中的短时证据、局部文字、声画错配和证据追溯。

问题：创新点表述仍偏泛，容易变成“多模态线索融合”。

建议把核心贡献改成三点，并且避免泛泛说“视听-文字协同”。

建议写成：

> 本章的核心贡献包括：  
> 1. 提出一种面向广告视频问答的证据保留型视觉压缩定义，将压缩目标从减少帧数扩展为在视觉 Token 预算下保留可追溯问答证据；  
> 2. 提出声画异步感知的视听-文字时空响应机制，将问题、时间邻域 ASR、OCR/Logo 检测和广告证据类型共同转化为帧内空间选择信号；  
> 3. 提出全局—局部双流证据包重构方式，使输出不仅包含裁剪区域，还包含时间戳、坐标、ASR 窗口、OCR/Logo 来源、证据类型和响应分数，为后续声明级校验提供结构化输入。

注意第三点中“证据包”只能作为支撑创新，不能单独作为主要创新，因为专利审查中“记录字段”往往被认为是数据结构或工程实现。

---

### 3.2 问题定义与总体框架

当前定义较清楚，但建议增强“预算约束”和“技术效果”。

建议把目标函数补充进去：

```text
E* = argmax_E Rel(E, q, A, O)
             + λ_1 Readability(E)
             + λ_2 Traceability(E)
             - λ_3 Cost(E)

s.t. Cost(E) ≤ B
```

解释：

- `Rel` 表示证据与问题相关性；
- `Readability` 表示局部文字、Logo、价格等细节在输入分辨率下的可读性；
- `Traceability` 表示证据能否回溯到帧、时间戳、坐标和模态来源；
- `Cost` 表示视觉 Token、总 Token、时延或显存开销；
- `B` 是输入预算。

这样本章的“压缩”才不只是经验性裁剪，而是有明确优化目标。

---

### 3.2.4 与已有视觉锚定方法的区别

这一节很重要，但目前还是偏解释性。建议更尖锐地写出“不可等价替换点”。

建议增加：

> 如果将本文方法退化为 AVAM 类视觉锚定，需要同时去掉三类约束：  
> 1. 去掉 ASR 时间邻域后，模型无法处理声画提前/滞后的证据关联；  
> 2. 去掉 OCR/Logo 检测框和广告证据类型后，模型无法稳定保留价格、小字条款和品牌标识等局部高价值证据；  
> 3. 去掉证据包结构后，模型只能得到局部图像，无法将答案追溯到具体帧、时间和模态来源。  
> 因此，本文方法不是在 AVAM 上附加一个 ASR 文本输入，而是将广告问答中的声画异步、短时文字证据和可追溯回答需求共同转化为视觉输入重构约束。

---

### 3.3 多模态预处理与候选证据召回

问题：现在的“高频过采样 + Top-K”比较普通。建议加入广告视频短时证据的召回指标或策略。

例如：

- 短时文字召回率；
- Logo/价格出现帧召回率；
- 时间去重；
- 检测触发保留机制。

建议增加：

> 对于包含 OCR/Logo/价格检测结果的候选帧，即使其全局语义相似度不高，也保留进入候选池。这是因为广告中的关键证据常以小区域形式出现，全局视觉编码可能无法反映其问答价值。

可将帧级得分改成：

```text
Score_frame(f_s)
= λ_q · sim(v_s, u_q)
+ λ_a · sim(v_s, u_A(s))
+ λ_o · OCRRel(f_s, q)
+ λ_b · BrandPriceBonus(f_s)
- λ_r · Redundancy(f_s)
```

其中 `u_A(s)` 最好用当前帧邻域 ASR，而不是全局 ASR 摘要 `u_a`。否则又容易被说成全局 ASR Prompt。

---

### 3.4 视听-文字时空响应图构建

这是最需要加强的部分。

当前问题：

1. 线性融合太普通；
2. ASR 响应仍像文本相似度；
3. OCR 语义先验可能导致虚假响应；
4. 权重自适应缺少可执行定义。

建议补充“问题类型驱动的权重策略”：

```text
p_q = ClassifyAdQuestion(q)

α_t, β_t, γ_t
= Normalize(
    w_Q(p_q),
    w_A(p_q) · Conf_A(t),
    w_O(p_q) · Conf_O(t)
  )
```

例如：

- 价格/优惠类：提高 OCR/Logo 权重；
- 旁白/卖点类：提高 ASR 权重；
- 场景/受众类：提高全局视觉权重；
- 合规条款类：提高小字 OCR 权重和小尺度局部框数量。

还要对 OCR 先验加限制，避免被认为“凭空猜测”：

> 语义先验只用于提高候选区域搜索敏感度，不作为最终事实证据。只有来自检测框或被局部视图重新识别出的文字/Logo，才在证据包中标记为可引用证据；先验触发的区域需要标记为 weak prior，不直接支持答案结论。

这点非常重要，否则审查员会质疑先验会引入幻觉。

---

### 3.5 基于响应密度的局部证据锚定

建议弱化“语义重心”，因为重心法在多峰响应下很脆弱，也显得传统。

可以改为：

- 默认使用峰值候选而不是重心；
- 重心只作为单峰响应的简化情况；
- 多峰 Top-m 是主机制，不是附加机制。

建议改写：

> 对综合响应图先进行局部峰值检测，得到候选证据中心集合。仅当响应图呈单峰分布时，使用响应重心作为候选中心；当响应图存在多个峰值时，分别围绕各峰值生成多尺度候选框，并通过响应密度、模态覆盖和 Token 成本联合排序。

候选框得分建议改成：

```text
D(B)
= [Σ_{(i,j)∈B} H(t,i,j)] / Area(B)^ρ
+ μ_1 · ModalityCover(B)
+ μ_2 · TypePriority(B, q)
- μ_3 · TokenCost(B)
```

这样就不是普通热力图面积归一化裁剪。

---

### 3.6 全局—局部双流视觉输入重构

当前“全局视图 + 局部视图”本身不新。建议强调“全局和局部不是并列输入，而是互相补偿”。

建议加入：

> 全局视图用于回答场景、人物关系、情绪氛围和营销意图；局部视图用于补偿全局缩放导致的文字、Logo、价格和包装细节损失。二者在证据包中通过同一 frame_id 和 bbox 绑定，使模型能够同时使用局部细节和全局上下文，而不是孤立地解释裁剪区域。

还应说明局部视图是否从原始高分辨率帧裁剪，而不是从缩放后的全局图裁剪。建议明确：

> 局部视图从原始帧裁剪后再缩放至模型输入分辨率，而不是从低分辨率全局视图中裁剪。

这是技术效果的关键。

---

## 三、建议补充的实验与消融

若没有这些实验，本章创新性很难站住。

### 1. 证明不是 AVAM + ASR

必须设置：

- AVAM/文本引导锚定；
- AVAM + 全局 ASR Prompt；
- AVAM + 邻域 ASR Prompt；
- 本章 ASR-guided visual reconstruction；
- 本章完整方法。

指标：

- 问答准确率；
- OCR/Logo/价格类问题准确率；
- 证据定位 IoU 或命中率；
- 短时证据召回率；
- Token/时延/显存。

### 2. 证明不是普通 ROI 裁剪

设置：

- 整帧低分辨率；
- 整帧高分辨率；
- 随机 crop；
- saliency crop；
- question-guided crop；
- 本章响应密度 + 证据包。

重点报告：

- 局部文字可读率；
- 价格/Logo识别准确率；
- 在相同 Token 预算下的 QA 性能。

### 3. 证明不是 ASR Prompt

设置：

- 无 ASR；
- 全 ASR Prompt；
- 邻域 ASR Prompt；
- ASR 仅用于视觉选择，不输入 Prompt；
- ASR 同时用于视觉选择和证据包。

如果“ASR 仅用于视觉选择”仍能提升，就能证明 ASR 不是简单 Prompt。

### 4. 证明不是广告场景套用

按广告问题类型拆分评测：

- 品牌识别；
- 价格促销；
- 功能卖点；
- 可信背书；
- 受众定位；
- 行动转化；
- 合规条款。

如果本章方法只在广告特有类别上显著提升，创新性更强。

## 四、建议强调的真正创新点

建议把本章创新凝练为以下四点，而不是泛泛写“多模态融合”。

### 创新点 1：证据保留型视觉压缩定义

不是压缩帧数，而是在预算约束下最大化可回答证据。

推荐表述：

> 本章将广告视频问答中的视觉压缩定义为证据保留型输入重构，而不是单纯减少帧数或裁剪图像。该定义同时约束证据相关性、局部可读性、模态来源可追溯性和视觉 Token 成本。

### 创新点 2：声画异步感知的 ASR 空间引导

不是 ASR Prompt，而是 ASR 参与视觉证据选择。

推荐表述：

> ASR 片段根据关键帧时间戳构成邻域语义窗口，并在帧级筛选和区域响应中改变视觉输入结构，从而缓解广告视频中旁白与画面提前或滞后的错配问题。

### 创新点 3：广告证据类型驱动的 OCR/Logo 响应

不是普通 OCR 文本拼接，而是类型化证据策略。

推荐表述：

> OCR/Logo 线索被划分为品牌、价格、折扣、口号、合规条款等广告证据类型，并根据问题类型调整空间响应和局部视图尺度，使小尺寸、高价值广告证据在压缩后仍可读。

### 创新点 4：可追溯证据包

不是单张 ROI，而是后续推理的结构化输入。

推荐表述：

> 每个证据单元同时记录视觉区域、全局上下文、时间戳、局部坐标、关联 ASR、OCR/Logo 来源、广告证据类型和响应分数，使答案生成可以回溯到具体帧和具体模态来源。

## 五、需要避免的表述

建议减少或替换以下表达：

1. “本文方法不是普通 ROI 裁剪”  
   仅否认不够，应说明技术机制差异。

2. “不是简单 ASR Prompt”  
   应改为“ASR 在回答前参与视觉输入重构”。

3. “广告特有 OCR/Logo 线索”  
   还不够，需变成“广告证据类型体系 + 问题类型策略”。

4. “响应图融合”  
   过于常见，应改为“声画异步和广告证据类型约束下的时空响应”。

5. “证据包使模型知道来源”  
   这更像工程包装，应说明它如何支持后续答案校验、证据引用和错误追溯。

## 六、可直接加入论文的改写段落

### 可加入 3.2.4 的段落

> 与 AVAM 类方法相比，本文的关键差异不在于额外增加了 ASR 或 OCR 文本，而在于这些模态线索被用于回答前的视觉输入重构。ASR 片段并非作为完整 Prompt 拼接给问答模型，而是根据关键帧时间戳形成邻域语义窗口，并影响帧级筛选和区域级响应；OCR/Logo 也并非仅作为识别文本输入，而是通过检测框、置信度和广告证据类型改变局部响应密度。由此生成的局部视图并不是孤立 ROI，而是与全局视图、时间戳、坐标和模态来源共同组成证据包。因此，本文方法解决的是广告视频问答中的证据保留型视觉重构问题，而不是通用视觉锚定问题的简单场景迁移。

### 可加入 3.4.5 的段落

> 综合响应图的权重不采用固定常数，而由问题类型和模态置信度共同决定。对于价格、折扣、活动规则和合规条款类问题，提高 OCR/Logo 分支权重并增加小尺度候选框；对于卖点解释、情感诉求和旁白说明类问题，提高 ASR 邻域分支权重；对于场景、人物关系和目标受众类问题，提高全局视觉分支权重。当 ASR 置信度低或 OCR 检测缺失时，相应分支权重自动降低。该机制使响应图具有广告问答任务相关性，而不是通用文本-视觉相似度热力图。

### 可加入 3.5 的段落

> 局部区域选择不以裁剪面积最小或响应峰值最大为唯一目标，而是在视觉 Token 预算下综合考虑响应密度、广告证据类型、模态覆盖和上下文完整性。对于价格、Logo、小字条款等局部证据，方法倾向选择较小但分辨率更高的局部视图；对于人物动作、产品使用过程和情绪氛围等上下文证据，方法保留更大范围的局部区域或依赖全局视图补充。由此，局部视图选择服务于问答证据保留，而不是普通显著区域裁剪。

3. 局部视图的数量控制。
4. 局部视图的分辨率控制。
5. 局部视图不是普通 ROI，而是证据保留型视觉输入重构的一部分。

建议补充句：

> 局部高分辨率证据视图并不替代全局语境视图，而是对全局缩放后容易丢失的文字、Logo、价格和包装细节进行证据增强。二者共同构成证据保留型视觉输入重构的视觉部分。

### 3.6.3 全局—局部双流组织方式

建议新增，说明输入格式：

> 对于每个关键帧 \(f_t\)，本文将全局语境视图 \(G_t\) 与一个或多个局部高分辨率证据视图 \(L_t\) 组合为双流视觉输入，并通过帧编号、时间戳和局部坐标建立二者之间的对应关系。

### 3.6.4 输入预算控制

建议新增。因为前文强调 Token、延迟和显存，后文必须接上：

> 输入预算由关键帧数量 \(K\)、每帧局部高分辨率证据视图数量 \(m\)、全局视图分辨率 \(R_g\) 和局部视图分辨率 \(R_l\) 共同决定。

并说明实验中需比较：

- 关键帧数量
- 局部视图数量
- 视觉 Token 数
- 总输入 Token 数
- 推理延迟
- 显存占用
- 问答准确率或证据命中率

### 3.7 证据包构建

建议单独成节，因为“证据包”是核心术语，不宜只在 3.2 和 3.6 中顺带出现。

- `global_view`
- `local_high_resolution_evidence_view`
- `bbox`
- `asr_window`
- `ocr_text`
- `logo_clue`
- `visual_tags`
- `response_score`
- `response_source`
- `confidence`

中文表述可写为：

> 证据包记录的不仅是图像内容，还包括该内容的时间来源、空间来源、语音来源、文字来源和响应分数，从而支持后续答案生成过程中的证据回溯。

### 3.8 本章小结

建议包括四点：

1. 定义证据保留型视觉输入重构。
2. 构建视听-文字时空响应图。
3. 生成局部高分辨率证据视图。
4. 输出可追溯证据包。
