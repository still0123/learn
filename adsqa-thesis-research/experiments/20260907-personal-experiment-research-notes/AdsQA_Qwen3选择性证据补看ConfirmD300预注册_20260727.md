# AdsQA Qwen3 选择性证据补看 Confirm-D300 预注册

日期：2026-07-27

## 1. 目的与独立性口径

本实验固定复验已经在 OOF-500 上通过扩展门禁的选择性证据补看策略：

```text
Clean Qwen3 Raw8 初答
→ 冻结 RealClaim985 验证器评估支持度
→ 仅触发最低支持的 10% 问题
→ 原帧反思 / 视听证据补看重写
→ 冻结验证器保守决定是否替换
```

确认集使用 `data/innovation1_confirmd300_v1/question.json`：

- 300 题、300 个唯一视频；
- Type 1–5 各 60 题；
- 与 AdsQA Train-500 视频零重叠；
- 与早期 Pilot50、Confirm-300、Confirm-300B、Confirm-300C 视频均不重叠。

限制必须如实说明：Confirm-D300 以前被另一个已冻结候选用于确认，因此它不是对整个研究过程都不可见的全局盲测集。但本方法的覆盖率、阈值、margin、Prompt、帧数、裁剪尺度和接受规则均在读取本次 GT 与裁判结果前由 OOF-500 冻结，因此它属于**方法级独立确认**。本实验不在 Confirm-D300 上调参。

## 2. 冻结输入与模型

- A0 回答模型：干净 `/data1/qky/Model/Qwen3Vl-8B`；
- A0 输入：8 个均匀帧，单帧 512，实际视觉 Token 必须为 1,024；
- A0 文本：问题 + 对应视频的分段 ASR 全文，最多 1,600 字符；
- 验证器：Qwen3 RealClaim985 LoRA；
- 验证器视图：与 A0 完全相同的 8 个冻结帧；
- 生成均为 `do_sample=false`；
- 二次视频帧采样关闭；
- 不使用网页、RAG、`meta_info`、参考答案或历史裁判结果。

## 3. 冻结触发规则

对 300 个 A0 全部进行支持度评分，然后：

1. 按 `support_probability` 升序排列；
2. 并列时按 `question_id` 排序；
3. 选择全局最低的 30 题，即固定 10% 覆盖率；
4. Confirm-D300 本身每题对应一个唯一视频，因此触发集也是 30 个唯一视频；
5. 仅在选择完成后，为运行并行性将 30 题确定性轮转分到五个运行分片，每片 6 题；
6. 问题类型不参与选择，只在结果中报告触发分布。

## 4. 冻结实验臂

| 方法 | 定义 |
|---|---|
| A0 | Clean Qwen3 Raw8 初答 |
| A1 | 使用同一 8 帧与 ASR 进行一次无门控反思 |
| A2 | 原 8 帧 + 两个问题相关时刻各一张完整帧与一张 mid-scale 裁剪，并显式提供 OCR/分段 ASR |
| A3 | 仅在冻结验证器通过时用 A2 替换 A0，其余保持 A0 |

A2 的问题相关时刻和裁剪框只由问题、视频、OCR 与分段 ASR 构建，算法与 OOF-500 保持一致：

- CLIP / ASR / OCR 权重为 `0.55 / 0.30 / 0.15`；
- 两个时间锚点的候选 rank 间隔至少 4；
- 使用每个锚点的 mid-scale 裁剪；
- OCR 最多 12 条，分段 ASR 最多 8 条。

## 5. 冻结 A3 接受规则

```text
P(A2) >= 0.8933094143867493
P(A0) < 0.8933094143867493
P(A2) - P(A0) >= 0.25
```

三项同时满足才切换。规则不得根据 Confirm-D300 的预测、GT 或裁判结果修改。

## 6. 协议审计

调用裁判前必须全部满足：

- answer-free 输入 300/300，300 个唯一视频，五类各 60；
- 与 Train-500 视频交集为 0；
- 视频、OCR、分段 ASR 缓存覆盖均为 300/300；
- A0 300/300、错误 0、每题 8 视图、视觉 Token 为 1,024；
- A0 验证器 300/300、错误 0；
- 触发集 30 题、30 视频，仅依据 A0 支持度；
- A1/A2 各 30/30、错误 0；
- A1 基础帧与 A0 一致；
- A2 基础 8 帧与 A0 一致，附加 4 个视图均可回指锚点与裁剪框；
- A1 为 8 视图，A2 为 12 视图且视觉 Token 不超过 4,096；
- A2 验证器 30/30、错误 0；
- A3 清单在读取 GT 或新裁判分数前冻结；
- 所有阶段关闭二次帧采样。

任一项失败则停止，不调用 DeepSeek。

## 7. 统一评分与门禁

冻结选择后，先进行 DeepSeek dry-run，精确计算需要评分的唯一答案数，再单独获得用户授权。统一报告：

- A0/A1/A2/A3 的 Strict、Relaxed 和 0/0.5/1 分布；
- 完整 300 题与触发 30 题两套结果；
- 胜/平/负、`wrong→right`、`right→wrong`；
- correction precision、触发率；
- 300 个视频簇的 10,000 次 Bootstrap；
- 各问题类型分层；
- 平均视觉 Token 与延迟。

确认通过门禁固定为：

1. 协议审计通过；
2. A3 实际答案切换不少于 3 题；
3. A3 胜数大于负数；
4. 完整 300 题 Relaxed 高于 A0；
5. 完整 300 题 Strict 不低于 A0；
6. `wrong→right > right→wrong`；
7. correction precision 不低于 60%；
8. 完整策略平均回答视觉 Token 不超过 1,600；
9. Relaxed 差值 Bootstrap 95% CI 下界不低于 -1 pp；
10. 任一问题类型的 Relaxed 降幅不超过 5 pp。

失败时冻结结果，不在 Confirm-D300 上修改任何方法参数。
