- 冻结原因：旧审计仅检查 `negative_plan.valid`，未读取视觉操作的嵌套 `valid`；来源视频与 Evidence-300 重叠；模型输入还携带了可推断监督状态的元数据。
- 处理：保留旧目录不覆盖；使用 `data/train.json` 的 500 条训练声明和视频索引重建 `dataset_v2/`。新集合与 Calibration、Development244、Evidence-300 均视频隔离，标签明确为 `not_human_gold=true`。
- 下一步：固定 Qwen3-VL-8B、32 视图、11,664 视觉 Token、关闭二次采样，完成 20 对 smoke 的帧/ASR/Token 审计后再进入候选 A。

## Smoke20 v2：固定视觉 Token 协议失败

- 40 个输入均提交并表示为 32 帧，二次采样关闭，反事实帧/马赛克操作已应用。
- 但原始视频分辨率直接进入 processor，导致后合并视觉 Token 在 2,464–11,520 之间变化，而非冻结的 11,664。
- 此 run 冻结为 `smoke20_v2_readr/`，不解释其 2/20 配对分数，也不进入训练。
- 唯一修复：所有已干预帧在 processor 前统一为 896×896；其他模型、提示词、帧数和生成设置不变。

## Candidate A 预条件 Smoke20 v3：声明锚定失败

- 固定协议已通过：40/40 均为 32 提交/表示帧、11,664 后合并视觉 Token、关闭二次采样。
- 但严格配对仅 2/20。多条正例已经被冻结 Qwen 判为 `CONTRADICT` 或 `INSUFFICIENT`，说明从训练 QA 答案直接抽取的宽泛声明不能作为当前证据的高置信正例。
- 多个负例仍被判为支持，说明均匀帧替换或通用马赛克没有删除该声明的决定性证据。
- 该候选在训练前失败，不运行 50 对验证或验证器训练。下一轮只改变源声明机制：从固定 Qwen 当前证据中提取带模态与锚点的原子声明，并仍标注 `not_human_gold=true`。

- Candidate C 的显式缺失状态 Smoke20 为 `14/20`，但 ASR 为 `7/7`、OCR 为 `4/7`、视觉为 `3/6`。总分由显式 ASR 可用性主导，不能作为跨模态证据验证器。

- RapidOCR 像素审计确认 500/500 OCR 负例至少一个目标文本框真实变化，`pixel_audit.json` SHA256 为 `86767d606489c6b684bdac7d35695be78f3bd0e18f4441a91523da725f1cc17b`。
- 但 Candidate D 的固定 Qwen Smoke20 仅 `15/20`，ASR `10/10`、OCR `5/10`。OCR 失败不是帧数、Token、遮挡未生效或监督泄漏，而是冻结 Qwen 的连续状态似然对真实文本删除没有稳定方向响应。冻结后不运行小试50、排序头训练、Calibration 或 QA 评测。
- Candidate E 前置审计结论为 `switch_allowed=false`：ASR/OCR 证书只能证明证据存在，不能独立证明答案正确；D 的 OCR 信号不可靠；而引用参考答案、裁判分数或改写冻结回答 Prompt 会引入泄漏或破坏协议。故不生成伪答案选举。

下一步不再进行同类弱监督反事实扫描。若重启创新点二，必须先获得独立人工对“答案原子命题—时间段/文本框/ASR span”的双审标注；再以答案 token 的 `E+`/经外部复验 `E-` 对数似然差为每模态分数，在 Calibration 一次性冻结并以风险—覆盖率评估保守接受或拒答。此前不能声称 QA 增益。
