# 2025-2026 视觉问答、视频问答、视觉定位相关论文创新点详细综述

记录日期：2026-07-07

用途：为 AdsQA / 广告视频问答毕业论文重新判断创新点是否足够新，并把 2025-2026 年相近论文的技术路线拆开，避免把已有热点写成本文创新。

说明：本文件是第一版详细综述，不声称覆盖所有 CVPR、ICCV、AAAI、NeurIPS、ACL/EMNLP、TPAMI 相关论文。它优先覆盖与本课题最接近的几条线：图像/视频问答、证据定位、时序 grounding、局部裁剪、高分辨率细节、视频 token 压缩、Video RAG、证据一致性与幻觉抑制。

---

## 1. 总体判断

2025-2026 年视觉问答和视频理解方向已经从“让大模型看更多帧/图像”转向：

```text
更长视频 / 更高分辨率输入
-> 问题条件化选择证据
-> 帧、区域、token 压缩
-> temporal / spatial grounding
-> 答案与证据联合评价
-> 对幻觉和证据错配做验证
```

因此，以下表述已经不适合作为毕业论文的核心创新：

- 仅做关键帧选择；
- 仅做局部裁剪或高分辨率 crop；
- 仅做视频 token 压缩；
- 仅做 RAG；
- 仅做 CoT / self-reflection；
- 仅要求模型输出证据时间段或证据描述。

更稳的方向必须落到广告视频的特殊性：

- 广告证据短时出现，例如 Logo、价格、包装、卖点字幕、CTA；
- 证据局部且细粒度，例如包装文字、小字、商品细节、画面角落优惠信息；
- 证据跨模态且可能错位，例如旁白先说、画面后出现，或者画面展示与口播不同步；
- 广告问题常涉及营销语义，例如目标受众、情绪诉求、说服策略、品牌调性；
- 外部营销知识只能解释已观察证据，不能越权替代视频证据。

## 2. 论文簇一：长视频 VideoQA 与视频 token 压缩

### 2.1 BIMBA: Selective-Scan Compression for Long-Range Video Question Answering

- 年份/会议：CVPR 2025。
- 核心问题：长视频包含大量冗余时空 token，self-attention 在长序列上的成本过高，简单均匀采样或 pooling 容易漏掉关键事件。
- 技术方案：引入 state-space / Mamba 风格的 selective scan，将高维视频信息选择性传播和压缩为较短 token 序列，再交给 LLM 处理。
- 创新点：不是简单减少帧数，而是学习一种长程视频信息选择机制，在长视频 QA benchmark 上提高效率和效果。
- 已经占掉的空间：普通“长视频 token 压缩”“从大量帧中选关键视觉 token”已经很难算新。
- 对本文的威胁：如果本文只说“减少无关帧/token，提高效率”，会被 BIMBA 这类工作覆盖。
- 对本文的启发：本文应强调不是通用长视频压缩，而是广告证据保留型输入重构，尤其保留短时字幕、Logo、价格、包装、CTA 等细粒度证据。

对本文可改写为：

```text
本文不以通用长视频压缩为目标，而面向广告视频中短时、局部、跨模态证据易被压缩丢失的问题，构建广告证据需求驱动的输入重构方法。
```

### 2.2 PruneVid: Visual Token Pruning for Efficient Video Large Language Models

- 年份/会议：Findings of ACL 2025。
- 核心问题：Video-LLM 中视觉 token 冗余严重，直接输入大量视频 token 成本高。
- 技术方案：训练自由方法；先合并静态/相似时空 token 降低冗余，再利用 LLM 与问题 token 的注意力关系剪掉不相关视觉 token。
- 创新点：不需要重新训练 Video-LLM，也能在保留性能的同时大幅减少 token。
- 已经占掉的空间：问题相关 token pruning、训练自由剪枝、时空相似 token 合并已经是明确已有方向。
- 对本文的威胁：如果第一创新点只叫“基于问题的 token 剪枝”，会显得弱。
- 对本文的启发：广告视频里的 OCR、Logo、小区域证据可能在普通 token pruning 中被误剪。因此本文可以强调“证据保留”而不是“压缩率最大”。

### 2.3 Dynamic-VLM: Simple Dynamic Visual Token Compression for VideoLLM

- 年份/会议：ICCV 2025。
- 核心问题：很多 VideoLLM 由图像 VLM 扩展而来，面对视频输入时需要在视觉 token 数量、时序覆盖和性能之间折中。
- 技术方案：构造大规模合成视频指令数据，并设计动态视觉 token 压缩架构，让不同视频任务使用不同压缩强度。
- 创新点：动态地调节视频视觉 token 表示，而不是固定压缩比例。
- 已经占掉的空间：动态 token compression 已经被顶会覆盖。
- 对本文的威胁：如果本文说“根据问题动态选择 token 数量”，容易和它正面撞。
- 对本文的启发：本文可以把动态性放到“证据槽触发”上，即根据广告问题需要什么证据来决定保留哪些证据视图，而不是泛泛调 token 数。

### 2.4 本簇结论

视频压缩方向已经非常拥挤。本文可以引用这些工作作为动机，但不能把“token 压缩”本身作为核心创新。更好的命名是：

```text
广告证据需求驱动的视听-文字证据定位与输入重构
```

关键词应从 compression/pruning 转向：

- evidence-preserving;
- ad evidence slot;
- short-lived local evidence;
- OCR/Logo/CTA preservation;
- global context + local evidence view.

## 3. 论文簇二：高分辨率图像 VQA、局部裁剪与主动视觉

### 3.1 ZoomEye

- 年份：2024/2025 arXiv，后续被多篇 2025 工作引用。
- 核心问题：高分辨率图像中小目标和细节很容易被 VLM 忽略。
- 技术方案：把图像组织成树状区域结构，先看全局，再沿 root-to-leaf 路径寻找与问题相关的局部区域。
- 创新点：训练自由的人类式 zoom-in 搜索。
- 已经占掉的空间：coarse-to-fine 图像区域搜索、局部放大、树状 zoom 已经不新。
- 对本文的威胁：如果本文写“先全局看视频，再局部 crop”，会显得像把 ZoomEye 从图像搬到视频。
- 对本文的启发：本文必须说明局部裁剪不是由“视觉相关性”单独触发，而是由广告证据需求触发。例如价格问题必须找价格/OCR 区域，品牌问题必须找 Logo/包装，行动号召问题必须找字幕/CTA。

### 3.2 FOCUS: Internal MLLM Representations for Efficient Fine-Grained VQA

- 年份/会议：NeurIPS 2025。
- 核心问题：细粒度 VQA 中，小物体、小文字、局部属性常常被低分辨率输入淹没。
- 技术方案：利用 MLLM 内部表示，尤其 KV cache / prompt 相关内部激活，生成对象相关性图，提出并排序 crop 区域。
- 创新点：训练自由，直接利用模型内部表征决定“看哪里”。
- 已经占掉的空间：用模型内部注意/表示找关键 crop 已经很强。
- 对本文的威胁：如果本文使用 attention/heatmap 选局部图，就会被认为与 FOCUS/ViCrop 一类工作相近。
- 对本文的启发：本文应避免把“热力图”写成创新，应改成“问题条件化证据响应图”，并明确响应图融合 ASR、OCR、Logo、广告证据类型，而不是只来自 VLM 内部 attention。

### 3.3 ViCrop / CROP / DeepEyes / AdaptVision / CropVLM

- 核心共性：它们都在解决“VLM 是否知道该看哪里、是否应该花更多视觉 token、是否应该调用 zoom 工具”的问题。
- 技术动作：
  - 用 attention / gradient / internal states 定位小细节；
  - 用低分辨率初看，高分辨率局部复看；
  - 用 RL 或工具调用训练模型主动 zoom；
  - 在资源约束下选择最小必要视觉输入。
- 已经占掉的空间：
  - 给 VLM 添加裁剪/放大工具；
  - 低分辨率到高分辨率的 coarse-to-fine；
  - 模型自己决定是否 zoom；
  - 根据问题找局部区域。
- 对本文的威胁：如果本文的第一创新点只落到“局部 crop + 再问模型”，基本不够新。
- 对本文的启发：要把局部 crop 绑定到“证据缺口”或“广告证据槽”，而不是绑定到普通相关性分数。

本文可防守写法：

```text
本文的局部证据视图不是通用 zoom-in 操作，而是由广告证据槽触发的输入重构结果。每个局部视图需要绑定 evidence_id、source_type、timestamp、bbox、trigger_slot 和 expected_observation，用于后续声明级证据许可。
```

## 4. 论文簇三：时序 grounding、视频证据定位与 grounded VideoQA

### 4.1 ReVisionLLM: Recursive Vision-Language Model for Temporal Grounding in Hour-Long Videos

- 年份/会议：CVPR 2025。
- 核心问题：小时级视频中，VLM 很难直接定位某个事件发生的准确时间。
- 技术方案：递归式时序定位。先扫描全视频找到粗粒度相关片段，再逐步缩小范围，最终定位事件边界。
- 创新点：用递归 search / revise 机制处理超长视频 temporal grounding。
- 已经占掉的空间：粗到细 temporal grounding、递归定位长视频事件已经有强代表。
- 对本文的威胁：如果本文写“粗定位时间片段再精定位”，会撞。
- 对本文的启发：广告视频较短，不应强调“小时级长视频定位”，而应强调“短视频内高密度、短时、局部证据定位”。

### 4.2 Grounded Multi-Hop VideoQA in Long-Form Egocentric Videos

- 年份/会议：AAAI 2025。
- 核心问题：多跳视频问答不仅要回答，还要定位多个相关时间区间作为视觉证据。
- 技术方案：构建带有 temporal evidence 的多跳 egocentric VideoQA 数据，并用于 instruction tuning。
- 创新点：把多跳 QA 与多段时间证据绑定。
- 已经占掉的空间：答案 + 多个 temporal evidence intervals 已经不是新概念。
- 对本文的威胁：如果本文第三创新点只是“答案附带证据时间段”，技术含量偏低。
- 对本文的启发：广告视频中多跳不一定长，但可能跨模态。例如“旁白说优惠 -> 画面出现价格 -> 结尾 CTA”形成短视频内多证据链。本文可以改成“广告语义证据链”，而不是普通多跳 temporal QA。

### 4.3 Object-centric Video Question Answering with Visual Grounding and Referring

- 年份/会议：ICCV 2025。
- 核心问题：现有 VideoLLM 多输出纯文本，缺少对象级输入 referring 和输出 grounding 能力。
- 技术方案：
  - 支持用户用文字和视觉 prompt 与视频对象交互；
  - 提出 STOM，将单帧视觉 prompt 传播到视频其他帧；
  - 构造 VideoInfer 对象中心视频指令数据。
- 创新点：对象级 VideoQA、visual grounding、referring segmentation 融合。
- 已经占掉的空间：VideoQA 与对象级 grounding/referring 的融合已经被 ICCV 覆盖。
- 对本文的威胁：如果本文主打“回答时定位画面对象”，不够新。
- 对本文的启发：广告视频对象不是普通物体，还包括 Logo、包装、字幕、产品卖点区域、CTA 按钮/文字。本文要做“广告证据类型定位”，不是通用 object-centric grounding。

### 4.4 TCRT: Task-aware Cross-modal Feature Refinement Transformer with LLMs for Visual Grounding

- 年份/会议：CVPR 2025。
- 核心问题：visual grounding 需要把文本描述与图像局部区域精确对齐。
- 技术方案：利用 LLM 生成 task-aware priors，再引导跨模态特征融合和目标区域定位。
- 创新点：LLM 先验参与视觉 grounding。
- 已经占掉的空间：文本/任务条件化 visual grounding 已经成熟。
- 对本文的威胁：如果本文只是“用问题文本指导区域定位”，不够新。
- 对本文的启发：本文应把“任务条件”进一步具体化为广告问题类型与证据槽，例如品牌识别、卖点识别、目标人群、情绪诉求、行动号召。

### 4.5 本簇结论

temporal grounding 和 visual grounding 不是空白。本文应避免说：

```text
本文首次将问题与视频片段定位结合。
```

可以说：

```text
已有工作多关注通用事件、对象或长视频片段定位。本文关注广告视频中短时、局部、跨模态且具有营销语义的证据定位，并将定位结果结构化为可约束答案生成的广告证据包。
```

## 5. 论文簇四：Scene Text / OCR / 视觉文字相关 VideoQA

### 5.1 EgoTextVQA: Towards Egocentric Scene-Text Aware Video Question Answering

- 年份/会议：CVPR 2025。
- 核心问题：现有 MLLM 在动态视频中的 scene text 识别和推理能力弱。
- 数据集：1.5K ego-view videos，7K scene-text aware questions。
- 主要发现：高分辨率、多帧推理、精确 temporal grounding、辅助 scene-text 输入对性能很关键。
- 创新点：将 scene text-aware VideoQA 系统化为 benchmark，并揭示现有模型短板。
- 已经占掉的空间：视频文字理解、scene text-aware VideoQA 已经有专门 benchmark。
- 对本文的威胁：如果本文只是说“广告里有文字，所以加入 OCR”，创新不足。
- 对本文的启发：广告视频确实强依赖文字，但本文应强调广告文字的功能差异：Logo、价格、功效词、免责声明、小字、CTA、促销时间，而不是一般路牌/家居文字。

本文可写成：

```text
与一般 scene text VideoQA 不同，广告视频中的文字不仅是可读内容，也是营销意图和答案许可的重要证据。本文根据问题类型将 OCR 文本映射为品牌、价格、功效、行动号召、限制条件等广告证据槽。
```

## 6. 论文簇五：Video RAG、结构化检索与知识注入

### 6.1 ViG-RAG: Video-aware Graph Retrieval-Augmented Generation via Temporal and Semantic Hybrid Reasoning

- 年份/会议：AAAI 2026。
- 核心问题：长视频理解中，单纯文本匹配不能动态对齐用户问题和相关视频片段。
- 技术方案：
  - 将视频 transcript/caption 等转成结构化图；
  - 联合建模多模态信息和时间关系；
  - 使用 semantic-temporal dual-level retrieval；
  - 用过滤机制选高置信证据片段。
- 创新点：把视频内容结构化为 temporal knowledge graph，再做语义+时间混合检索。
- 已经占掉的空间：Video RAG、图结构检索、语义-时间混合检索已经出现。
- 对本文的威胁：如果本文第二创新点叫“广告视频 RAG”或“视频知识库检索”，非常危险。
- 对本文的启发：本文 RAG 不能作为主创新，只能作为广告语义辅助模块，并必须受视频证据约束。

### 6.2 VideoRAG / VRAG / temporal-aware RAG

- 核心共性：把长视频转成可检索文本、caption、transcript、segment，然后基于 query 找相关片段辅助回答。
- 技术动作：
  - 视频帧选择；
  - transcript/caption 对齐；
  - segment-level retrieval；
  - temporal rerank；
  - graph 或 entropy 权重。
- 已经占掉的空间：视频检索增强生成已经成为通用路线。
- 对本文的威胁：如果本文的知识库只是“检索一些营销概念放进 prompt”，不仅不新，还可能引入噪声。你自己的实验也显示 RAG/verifier 版本比 no-RAG evidence 版本差。
- 对本文的启发：RAG 必须低噪声、证据触发、只补营销语义，不补视频事实。

本文可防守写法：

```text
本文不进行开放式 Video RAG，而是在广告证据包的约束下进行证据槽触发式知识检索。只有当视频证据已触发相应广告语义槽时，外部知识才被允许进入推理上下文；知识不能单独支持视频中未出现的事实声明。
```

## 7. 论文簇六：证据化推理、幻觉抑制与答案-证据一致性

### 7.1 Commonsense Video Question Answering through Video-Grounded Entailment Tree Reasoning

- 年份/会议：CVPR 2025。
- 核心问题：VLM 可能利用数据集偏置和答案先验，而不是真正基于视频推理。
- 技术方案：
  - 将 commonsense VideoQA 转成 entailment tree；
  - 每个子命题用 video-language entailment verification 验证；
  - 进行 tree reasoning；
  - 必要时 dynamic tree expansion；
  - 用 LLM 改写 answer set 做 de-biasing。
- 创新点：把 VideoQA 答案推理显式落到可验证的 video-grounded entailment tree。
- 已经占掉的空间：把答案拆成子命题并用视频证据验证，已经是强相关已有工作。
- 对本文的威胁：如果本文第三点只是“把答案拆成声明再验证”，技术含量不够。
- 对本文的启发：本文不能只做普通声明验证，要把声明类型限定到广告证据槽，并引入“知识越权控制”。

### 7.2 Seeing Is Believing / EV2-Bench: Grounding Long-Video Understanding in Spatio-Temporal Visual Evidence

- 年份/会议：AAAI 2026。
- 核心问题：长视频问答模型可能答案正确但证据不对，评测需要强制模型基于 spatio-temporal visual evidence。
- 技术方案：提出 EV²-Bench，并用 DynamicSelect 等方法强化证据选择。
- 创新点：把 long-video understanding 的评价中心从答案正确转向时空视觉证据。
- 已经占掉的空间：证据化评测已经不是空白。
- 对本文的威胁：如果本文只说“增加证据一致性评价”，不够新。
- 对本文的启发：你可以借鉴它，把 AdsQA 的评测从 strict/relaxed accuracy 扩展到 evidence support rate / unsupported claim rate，但创新必须场景化。

### 7.3 VideoZeroBench

- 年份：2026 arXiv。
- 核心问题：现有视频 MLLM 在复杂时空证据上能力不足，普通 QA 指标无法暴露问题。
- 技术方案：构建 capability-centric、evidence-grounded、hierarchical benchmark，要求模型处理长视频中的时空证据。
- 对本文启发：AdsQA 也可以设计小规模 evidence audit set，检查模型答案是否被广告证据支持。

### 7.4 MJ1 / Grounded verification chain 类工作

- 核心共性：将模型判断过程拆成 observations、claims、verification、evaluation，减少多模态裁判的无依据判断。
- 对本文威胁：声明级验证本身已经趋于常规。
- 对本文启发：广告任务中可做声明类型化：视觉事实声明、语音事实声明、文字事实声明、营销解释声明、外部知识声明。不同声明有不同许可条件。

本簇结论：

```text
“证据验证”本身不够新；“广告答案声明的证据许可规则”才可能成为有差异的辅助创新。
```

---

## 8. 对本文原创新点的重新评估

### 8.1 原创新点：token 定位切割

如果写成：

```text
基于问题相关性的关键帧选择和 token 切割
```

新颖性较弱，因为 BIMBA、PruneVid、Dynamic-VLM、Frame-Voyager、Q-Fold、FOCUS、ZoomEye 等都覆盖了相近思想。

更强写法：

```text
广告证据需求驱动的视听-文字证据定位与输入重构
```

必须包含这些差异点：

- 证据类型不是泛视觉 token，而是广告证据槽；
- 输入不是单一帧序列，而是全局语境视图 + 局部高分辨率证据视图 + ASR/OCR 证据；
- 目标不是最大压缩，而是保留可回答问题的最小证据包；
- 输出不是给模型看的图片集合，而是可追溯 evidence package。

### 8.2 原创新点：四维链

如果写成：

```text
视觉、语言、知识、反思四维推理链
```

新颖性较弱，容易被认为是 CoT/RAG/self-check 工程组合。

更强写法：

```text
广告语义证据槽驱动的知识检索与声明许可校验
```

注意：四维链可以作为内部实现或消融设置，不建议作为论文标题级创新点。

### 8.3 原创新点：证据校验

如果只是：

```text
让模型输出证据并检查答案是否一致
```

确实技术含量较低。

更强写法：

```text
广告答案声明的证据许可校验
```

关键在于规则要结构化：

- claim split；
- claim type classification；
- evidence requirement slot；
- supported / contradicted / insufficient / knowledge-only；
- unsupported claim downgrade；
- knowledge override blocking；
- final answer rewrite。

## 9. 建议的毕业论文最终技术主线

推荐不要写三个平均创新点，而写成“一主一辅”：

```text
主创新：
广告证据需求驱动的视听-文字证据定位与输入重构方法。

辅助创新：
基于证据槽的广告语义知识检索与答案声明许可校验方法。
```

两者关系：

```text
问题 Q
-> 广告问题类型识别
-> 证据需求槽生成
-> ASR/OCR/Logo/视觉候选证据定位
-> 全局语境视图 + 局部证据视图
-> evidence package
-> 证据槽触发的低噪声知识检索
-> 答案声明生成
-> 声明级证据许可/降级
-> 最终答案
```

这条主线的优势：

- 避开普通 token compression；
- 避开普通 crop/zoom；
- 避开普通 Video RAG；
- 避开普通 CoT；
- 能解释为什么你的 no-RAG evidence pipeline 当前实验效果最好；
- 能把 AdsQA 数据集的广告属性转化成论文独特性。

## 10. 论文写作中可以直接使用的创新点表述

### 10.1 创新点一：广告证据需求驱动的视听-文字证据定位与输入重构

> 针对广告视频问答中问题相关证据短时出现、局部分布且跨模态错位的问题，本文提出广告证据需求驱动的视听-文字证据定位与输入重构方法。该方法首先根据问题类型生成广告证据需求槽，随后融合视频帧视觉相关性、ASR 邻域语义、OCR/Logo 显著性和广告证据类型先验，构建问题条件化证据响应图。在此基础上，方法生成兼顾全局语境和局部高分辨率细节的证据视图，并输出结构化 evidence package，以降低无关视觉冗余对模型回答的干扰，同时保留广告问答所需的短时细粒度证据。

### 10.2 创新点二：证据槽驱动的广告语义知识检索与声明许可校验

> 针对广告问答中模型容易凭语言先验生成无证据营销解释的问题，本文提出证据槽驱动的广告语义知识检索与声明许可校验方法。该方法仅在视频证据触发相应广告语义槽时检索外部营销知识，并将候选答案拆分为视觉事实、语音事实、文字事实和营销语义声明。每类声明需回溯到对应视频证据或知识证据，未被视频证据支持的知识性声明将被降级、删除或标记为证据不足，从而降低无依据知识注入和广告语义幻觉。
